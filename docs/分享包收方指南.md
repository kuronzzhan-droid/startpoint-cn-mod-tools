# WF mod 分享包收方指南

> 面向:运行 startpoint-cn 私服、想使用他人 mod 内容的服主。
> **收方不需要安装任何 mod 工具**——本指南只涉及"把文件放对位置"。
>
> 相关文档:从零开一台服看 [README 的三步导航](https://github.com/kuronzzhan-droid/startpoint-cn/blob/release/modes-20260714/README.md)
> 与一键脚本 [`deploy.ps1`](https://github.com/kuronzzhan-droid/startpoint-cn/blob/release/modes-20260714/deploy.ps1);
> 模式类内容的完整装载/救援/客户端补丁细节看
> [`docs/self-host-modes.md`](https://github.com/kuronzzhan-droid/startpoint-cn/blob/release/modes-20260714/docs/self-host-modes.md)(下称**自建服指南**)。

## 分享包长什么样

```
wfshare-<起始>-to-<目标>/
├── archive-common-diff/      增量归档(主要内容)
├── archive-medium-diff/      中画质层(多为占位包)
├── archive-android-diff/     平台层(多为占位包)
├── dev-catalog/              dev 架构服务端专用材料(main 服务端忽略)
│   ├── catalog-cn-<目标>.json      整链候选 manifest
│   └── EntityLists/…csv            合并资源清单
├── requires.json             机器可读依赖声明
└── 说明.txt                  本包摘要
```

目录名末尾还会带**变体**后缀(`…-full` / `…-content-only`),见下节。

## 变体:full 还是 content-only(**先看这个**)

同一批内容(自制角色 + 自制武器 + 新玩法模式)会打成两个变体,**二选一**:

| 变体 | `requires.json` 里 | 你会拿到什么 |
|---|---|---|
| **full** | `"enhancement": true` | 作者自服的完整终态:内容 **+ 作者的个人增强**——全角色平衡重算(词条/队长技/成长曲线/魂珠)、单个官方角色的专项重做、官方 boss 血量上调等。想要"和作者服一模一样"的选它 |
| **content-only** | `"enhancement": false` | 只有内容。**所有官方行都按官方 CDN 原值重建**,官方数值一格没动;被作者改过的官方资产文件不下发 |

拿不准就要 **content-only**:它对你的官方数据最保守,新角色/新武器/新模式一样齐全。

`requires.enhancementDetail` 会写清 content-only 到底回滚了哪些表、丢了哪些文件,
以及基准取的哪个官方版本(`officialBaseline`,通常是 `1.4.54`)。

⚠ **两个变体不能同时铺**。它们的 zip 文件名不同(tag 一个是 `xxxx`、一个是 `xxxxco`),
同时放进 CDN 会让客户端**两份都下载并按文件名序应用**,终态是混的。换变体时先把旧变体的
zip 从 CDN 删掉,再铺新的。

> content-only 仍然是**整表替换**:它保证不动"官方原有的行",但保证不了"你自己加的行"。
> 外血统服主照样要走第 0 步的行级合并路线。

## 第 0 步:先判血统(**别跳过**)

"解压合并只增文件"对 **CDN 目录**为真——包只会往你的归档目录里加 zip,不删不改。
但**包内的表是整文件**:客户端应用这些 zip 之后,包里带的每一张
`master/…orderedmap` 会**整表覆盖**客户端上同名的表。所以真正的问题不是文件会不会被删,
而是**你的表和作者的表是不是同一个血统**。

先自问:你的基础 CDN / 客户端表是**跟着作者那条链**走的(内容等价于他的基线),
还是来自**别的私服血统**(你自己后来更新过、或从别家 CDN 拿的,表里有你自己的活动/商店/角色行)?

| 你的血统 | 怎么办 |
|---|---|
| **跟链血统**(与作者同源) | 照本指南直接解压合并,没问题 |
| **外血统**(有你自己的数据) | **不要直接用整表替换型的包**。已有野外先例:外血统服换上跟链的 `event_list` / 角色 16 表后,活动页与领主战直接「数据不足」瘫痪——你自己的活动行被整表抹掉了 |

外血统要用别人的 mod 内容,只能走**行级合并**:在你自己的数据包上重新生成,不动你的存量行。
完整分流(A 基线血统整表救援 / B 外血统行级合并)、以及自跑 mod-tools 时
**store 基线必须等于你目标客户端当前版本**这条前提(用落后的 store 发布会把表滚回几十个版本,
版本间隙里官方加的 key 全丢),都在**自建服指南**的「通用桥接」一节,别自己摸索。

纯资产包(只有 png/mp3/新路径文件、不含任何表)对任何血统都安全。拿不准就问作者
**包里有没有表**;`说明.txt` 与 `requires.serverDataNote` 通常会写。

## 前提:链尾衔接

增量包只对"链尾恰好达到包起始版本"的服务端生效。查看自己的链尾:

```bash
ls .cdn/cn/archive-common-diff/ | sort -V | tail -3
```

文件名 `pinball-<from>-<to>-…` 里最大的 `<to>` 就是你的链尾。链尾低于包起始版本时,先向 mod 作者索要覆盖你版本的累计包;`since=1.4.54` 的完整链包适用于所有拥有官方 1.4.54 dump 的服务端。

### 整合包:一条边可以跨很多个版本

包名里的 `<from>`/`<to>` 是**这条边的两端**,不是"每次只升一版"。作者可以用整合器
(`wf_pack_consolidate`)把一整段历史增量压成**一个整合包**,产物命名取
**所选内容的最早 from**,于是你会看到 `pinball-1.4.107-1.4.217-…` 这种跨 110 个版本号的单条边。

**这不是链断了**。判断衔接只看一件事:**有没有一条边的 `from` 等于你的链尾**。
中间那些版本号没有对应文件是正常的——它们已经被合并进这一条边了。

同理,同一个 `<from>-<to>` 下出现 `-1-`、`-2-`…多个序号也很正常:那是同一条边按体积
拆出的分包(CI 门禁单 zip ≤5MiB),客户端按 `get_path` 返回的列表**全部下载**,少拿一个都算残缺。
分包序号在 `archive-common-diff` / `archive-medium-diff` / `archive-android-diff` 三个目录里
**各自从 1 开始**,所以三个目录里可能有同名文件——**务必按目录对应解压,不要拍平成一个目录**。

## main 服务端(当前主流)

0. **先做第 0 步的血统判定**——外血统直接铺整表替换型的包会砸掉你自己的活动数据;
1. 把包内 `archive-common-diff/`、`archive-medium-diff/`、`archive-android-diff/`
   三个目录**解压合并**到你的 CDN 根(`.cdn/cn/`)**同名目录**——对 CDN 目录只增文件,
   不覆盖不删除(注意这只说文件;包里若带表,客户端应用后会整表覆盖客户端的表);
2. 服务端动态扫描,无需任何配置;玩家客户端重启游戏即自动下载更新;
3. 查看 `requires.json`:
   - `serverRestart: true` → 重启一次服务端(通常因为包含新角色,邮件白名单启动定格);
   - `minServerVersion` / `serverFeatures` 非空 → 该包依赖服务端逻辑(如新玩法模式),
     你的服务端版本必须满足,否则内容会异常(进本崩溃/结算错误)。**dev 架构还要另装
     玩法改造包**,见下节;
   - `clientPatches` 非空 → 玩家客户端需要对应补丁版 APK,见「`clientPatches`」一节。
4. **不要**把 `dev-catalog/EntityLists/` 拷到 CDN 根——main 服务端会优先读取该目录
   并改变 files_list 行为。

## dev 架构服务端(content:sync)

1. 同上解压合并三个归档目录;
2. 把 `dev-catalog/EntityLists/` 整目录拷到 CDN 根,成为 `.cdn/cn/EntityLists/`;
3. 用受支持入口重启(`npm run start:cn` 等),启动同步会校验并重建 Content Release;
4. `dev-catalog/catalog-cn-<目标>.json` 是整链候选 manifest,对应
   "官方 dump + 完整 mod 链"的状态,可用于离线校验、评审或 tracked 基线兜底路线。

### 模式类内容:还要装「玩法改造包」

上面 1-4 步只处理**内容**。如果包的 `requires.minServerVersion` / `serverFeatures` 非空
(自制连战、自定义活动规则这类**模式**内容),光靠内容包永远满足不了——**dev 基座刻意不含
任何玩法逻辑**,玩法要以独立模块的形式手动安装。照现有 1-4 步操作会看到活动入口但进本崩溃。

装载缝已随 **PR #19 合并进上游 `dev`**(`df3ad91`,`src/modes/`),**你不需要 fork 服务端**。
三件产物别混:

| 产物 | 是什么 | 谁来装 |
|---|---|---|
| **基座** | 上游 dev 构建的服务端,只含激活入口 | 正常部署 |
| **玩法改造包** | `xxx.mjs` + manifest,**代码** | 你手动放进 `modes.d/` 并登记哈希 |
| **内容包** | 本指南说的 CDN 增量,**数据** | 照常解压合并 |

> 红线:**内容包永不携带可自动加载的代码**。装模块 = 以服务器权限运行第三方代码,
> 是与"安装服务端本身"同级别的信任决定,所以没有自动发现、没有热加载。

装载是**双重显式**的:文件要在 `modes.d/`,**且**其 sha256 要登记在
`modes.d/modes-allowlist.json`(形如 `{"rogue.mjs": "<sha256>"}`)。缺一或哈希不符都会跳过并打
日志,不会静默加载。装卸模块都要重启。总开关 `MODES_ENABLED=0`,目录可用 `MODES_DIR` 覆盖。

```bash
cp <作者给的>/rogue.mjs modes.d/rogue.mjs
# sha256 不用自己算:改造包的 mode-manifest.json 里带了(连同 install 步骤、激活表名),
# 照抄成 {"rogue.mjs": "<sha256>"} 写进 modes.d/modes-allowlist.json
CDN_DIR=<cdn父目录> npm run content:sync && node --env-file=.env out/cn-server.js
```

启动日志出现 `[modes] loaded <name> (<capability>) sha256=…` 才算装上;没有这行 = 没装成
(哈希没登记/不符,或激活表缺失)。激活语义是**内容键控**的:模块第一步读自己的激活表,
表缺失或未启用就直接返回——所以"装了模块但没下发内容"与"完全没装模块"表现一致,
可以先装模块再按需下发内容。挂点、事务边界与失败模型见上游
[`docs/systems/mode-seam.md`](https://github.com/DontBeAlarmed/startpoint-cn/blob/dev/docs/systems/mode-seam.md)。

⚠ dev 架构上的模式已验证到服务端级(结算发奖/防跳关/惰性/CDN 下发),**客户端真机验收尚未完成**。
要稳,用作者的 `release/modes-20260714` 分支(逻辑直接编译进服务端,不用装模块)。

## requires.json 字段速查

| 字段 | 含义 |
|---|---|
| `schemaVersion` | 声明格式版本(带变体字段的是 2) |
| `pack.variant` | `full` / `content-only`(见「变体」一节) |
| `pack.anchor` | 这条边落在你链上的 `from → to`;`from` 必须等于你的链尾 |
| `enhancement` | 包里**有没有**作者的个人增强(true = 会改官方数值) |
| `enhancementDetail.officialBaseline` | content-only 的官方基准版本 |
| `enhancementDetail.revertedTables` | 被回滚成官方原值的表 |
| `enhancementDetail.droppedEntries` | 因被作者改写而**不下发**的官方资产文件 |
| `requires.serverRestart` | 放入后需重启服务端一次 |
| `requires.restartReasons` | 触发重启的原因(自动检测) |
| `requires.minServerVersion` | 最低服务端版本/分支(模式类内容) |
| `requires.serverFeatures` | 依赖的服务端功能名 |
| `requires.clientPatches` | 玩家客户端需要的补丁(见下节) |
| `requires.serverDataNote` | 服务端派生表的额外说明 |

## `clientPatches`:五合一补丁与缺哪个是什么症状

自制内容常常要客户端配合。作者那套客户端是**五合一**——玩家手里的包缺哪一个,症状不同:

| # | 补丁 | 作用 | **缺了会怎样** |
|---|---|---|---|
| ① | 免登录 | 跳过官方登录 | 进不去服 |
| ② | 服务器重定向 | 指向你的 `host:port` | 连的还是官方(已停服) |
| ③ | 深渊装备战斗门控 | 自制武器在战斗里生效 | 能拿到、能装上,**战斗里不生效**(不崩,最容易被误判成"数值没做对") |
| ④ | 赛瑞斯双形态 P-code | 特殊演出/双形态动画/湿润雷伤 | 领角色没事,**播放特殊演出即硬崩** |
| ⑤ | 逐角色像素占屏 | 渲染尊重 `frame.scale` | 大原生像素角色在角色页/战斗里恒定放大(实测杰拉德 1.79×、赛瑞斯 4.76×),显著偏大但**不崩** |

层次与顺序:①②③ 和 ⑤ 的站点 1 在 **AS3 层**(一起导回 SWF),④ 和 ⑤ 的站点 2 在 **P-code 层**
——**必须先把 AS3 那批导回 SWF,再打 P-code 那批**,顺序反了会被重序列化冲掉。

**收方通常不需要自建 FFDec 流水线。** 两个省事的路子:

- 找作者要**指向你服务器**的成品包;
- 或拿已发布的 **v2.0 五合一基座 APK**([mod-tools Releases](https://github.com/kuronzzhan-droid/startpoint-cn-mod-tools/releases)),
  用 `client-patch/repoint-apk/repoint_build.py` **只改服务器指向**(②号补丁落点)再重签,
  ①③④⑤ 的字节原样保留,构建自带回读校验。

换包时的签名取舍:**沿用玩家旧包同一个 keystore** → 可覆盖安装,本地身份保留;**换签名** →
玩家必须卸载重装,本地客户端身份被抹掉、下次登录开新号(存档还在服务端 DB,服主按 `device_id` 重绑)。

**全员换完包再发新角色**——数据与客户端补丁必须配套。细节见**自建服指南**的步骤 4。

## 常见问题

- **客户端说"已是最新"不下载**:链尾不衔接(见"前提";先确认没有把整合包的跨版本跨度误判成链断),
  或客户端 res_ver 已高于包目标版本。玩家卡在链外版本接不上时,救援办法见**自建服指南**的「通用桥接」;
- **邮件发不出新角色**:`serverRestart` 没执行,重启服务端;
- **进新玩法崩溃**:服务端不满足 `minServerVersion`/`serverFeatures`,内容包不携带服务端逻辑
  (dev 架构还需装玩法改造包并登记哈希,见 dev 一节);
- **活动页/领主战页突然「数据不足」或整片空白**:多半是**外血统吃了整表替换**——你自己的
  活动/商店/角色行被包里的表覆盖掉了。回滚(见下条)后按第 0 步走行级合并路线。
  另一个无报错的诱因是**服务器时间在活动排期窗外**(时间过滤是静默的),先在管理后台确认时间;
- **武器装上不生效 / 某角色演出一播就崩 / 像素明显偏大**:不是数据问题,是客户端缺 ③④⑤ 号补丁,
  见「`clientPatches`」一节的症状对照;
- **官方角色数值/怪物血量跟你记忆里不一样**:你铺的是 `enhancement: true` 的 **full** 变体,
  它带作者自服的平衡改动。向作者要 **content-only** 变体,删掉 full 的 zip 再铺;
- **同一条边下看到两组不同 tag 的 zip**:多半是 full 与 content-only 混铺了(见「变体」),
  留一组、删另一组;
- **回滚**:删除本包新增的 zip 文件即可(包只增不改;若客户端已下载,需清客户端资源缓存或等更高版本修复包)。
