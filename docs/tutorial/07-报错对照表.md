# 07｜报错对照表

在使用本套教程和工具时遇到报错，可以直接在本页按 **`Ctrl + F`** 搜索屏幕上的关键词或错误码。每一条都按「**现象 → 原因 → 怎么办**」给出直接解法。

---

## 一、安装基础软件与配置文件报错（第 01、04 篇）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 敲 `python` 报 `'python' 不是内部或外部命令`，或自动弹出了微软应用商店 | 安装 Python 时漏勾了 `Add python.exe to PATH`，或被 Windows 应用商店别名抢占 | 1. 重新运行 Python 安装程序，选 `Modify` 勾上 `Add Python to environment variables`（或卸载重装并在第一页底部勾选 `Add python.exe to PATH`）；<br>2. 打开 Windows「设置 -> 应用 -> 高级应用设置 -> 应用执行别名」，关掉 `python.exe` 与 `python3.exe` 两个开关，**关掉旧黑色窗口重开一个新的 `cmd`**。 |
| 运行工具或编辑台报 `AttributeError: module 'hashlib' has no attribute 'file_digest'` | 电脑当前生效的是 Python 3.10 或更旧版本（本仓库最低要求 **Python 3.11**） | 运行 `python -V` 查看版本；卸载旧版 Python，安装 **64 位 Python 3.11 及以上正式版** 后重开 `cmd`。 |
| 敲 `npm` 报 `因为在此系统上禁止运行脚本` | 在 PowerShell 窗口中运行了 `npm.ps1`，被 Windows 默认脚本执行策略拦截 | 改用 **`cmd` 命令提示符**（资源管理器地址栏输入 `cmd` 回车），或把命令里的 `npm` 写成 `npm.cmd`。 |
| 读取配置报 `JSONDecodeError: Invalid \escape` | `profiles/local.json` 里直接粘贴了带单个反斜杠 `\` 的 Windows 路径 | 用记事本打开 `profiles/local.json`，把所有路径里的单个反斜杠 `\` 全部改成**正斜杠 `/`**（或双反斜杠 `\\`），保存重试。 |
| 弹出 `UserWarning: profiles.json is deprecated` 或报新旧配置冲突 | 工具根目录下留有已废弃的 `profiles.json`（例如误加了 `--write-profile`），或系统里设过旧环境变量 `WF_TARGET_STORE` / `WF_SERVER_DIR` | 删除 `<工具目录>\profiles.json`，统一保留 `<工具目录>\profiles\local.json`；若用环境变量，统一改用新名 `WF_STORE`、`WF_SERVER`、`WF_CDN_DIR`、`WF_CDNDATA`。 |

## 二、服务端部署与客户端连服报错（第 02、03 篇）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 双击服务端 `start.bat` 弹窗要求装 `mitmproxy`，或双击 `validate_cdn.bat` 报缺 `en` / `ko` 目录 | 这两个 `.bat` 都是上游国际服遗留脚本，不适用于国服 | 不要双击任何 `.bat`！在 `<服务端目录>` 打开 `cmd`，校验 CDN 用 `npm run cdn:patch:check`，启动国服服务端用 **`npm run dev:cn`**（首次）或 **`npm run start:cn`**（日常重开）。详见 [02-部署服务端.md](02-部署服务端.md)。 |
| 服务端启动报 `CDN_DIR must point to the parent directory` | `<服务端目录>\.env` 里的 `CDN_DIR` 多写了一层 `/cn` | 打开 `.env`，确保写成 `CDN_DIR=".cdn"`（不能写成 `".cdn/cn"`），保存后重新启动服务端。 |
| 服务端窗口看着正常，但客户端一直转圈连接超时、电脑浏览器打开接口也卡住不动 | ① Windows 防火墙拦了端口；或<br>② 鼠标误点进服务端 `cmd` 黑窗口触发了文本选中，窗口左上角标题变成了 **`选择 ...`**，导致整个服务端进程被系统挂起暂停 | 1. 看一眼服务端黑色窗口标题栏：如果开头有「**选择**」二字，在窗口里按一下键盘 **`Esc`** 键即可立刻恢复运行；<br>2. 检查 Windows 防火墙是否已放行 Node.js（专用网络），且电脑与手机处在同一路由器网段。 |
| 装好补丁客户端，点开依然弹出雷霆官方账密登录框 | ① FFDec 里改完脚本只点了「编辑」没点底部保存并保存整个 SWF；或<br>② 重打包 APK 时没把新 SWF 覆盖进 `assets/worldflipper_android_release.swf`；或<br>③ 设备里的旧版客户端没卸载干净 | 先彻底卸载模拟器/手机上的游戏；用 FFDec 直接打开你最终签好名的 `.apk` 里的 SWF 回读检查两处脚本修改是否真在里面。详见 [03-安装客户端并连接.md](03-安装客户端并连接.md)。 |
| 跳过了登录框能进标题页，但下载更新永远卡在 `0%` 或报网络错误 | ① `<服务端目录>\.env` 里的 `CDN_BASE_URL` 还是默认的 `127.0.0.1`（安卓设备会把 `127.0.0.1` 当成安卓自己）；或<br>② 客户端补丁里忘了把 `"https"` 改成 `"http"` | 打开 `<服务端目录>\.env`，确认 `CDN_BASE_URL="http://<电脑局域网IP>:8001/patch/cn"` 与 `SESSION_PUBLIC_HOST="<电脑局域网IP>"`，保存并**重启服务端**；同时核对客户端补丁协议为小写 `"http"`。 |
| 安装补丁 APK 时提示「应用未安装 / 与现有软件包签名冲突」 | 设备上还装着官方原版或其他签名的旧包；或打包时把 `zipalign` 放在了 `apksigner` 签名之后把签名破坏了 | 1. 先卸载设备上已有的《世界弹射物语》；<br>2. 严格按 **先 `zipalign` 对齐 → 最后 `apksigner sign` 签名** 的顺序重签。 |

## 三、物化数据包、修改器与编辑台报错（第 04、05、06 篇）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `wf_store_materialize.py` 报 `full archive directory is missing` | `--cdn` 没指到含 `archive-common-full` 的那一层 | 把 `--cdn` 指到 `<服务端目录>\.cdn\cn`（不要漏掉末尾的 `\cn`）。 |
| `wf_store_materialize.py` 报 `destination must be nonexistent or empty` | `--dest` 指向的 `<物化目录>` 里已经有文件了 | 换一个全新的空路径（如 `<工作目录>\wf-store`），或把上次失败留下的残缺文件夹清空后再跑。 |
| 启动 `wf_gui.py`、`wf_selftest.py` 或其他工具报 `configured store is not an existing directory`、`请设置环境变量 WF_STORE`、`cannot read master/... from target/source stores`（或提示未找到 `store`） | `paths.store` 未配置、目录尚未物化，或少写了两层子目录 | 打开 `<工具目录>\profiles\local.json`，确认 `paths.store` 精确指向已物化的 **`<物化目录>/production/upload`**（点进该目录应直接看到 `00`～`ff` 子目录），或设置环境变量 `WF_STORE`（**不要**运行报错里提到的旧版废弃参数 `--write-profile`）。详见 [04-配置工具.md](04-配置工具.md)。 |
| `wf_gui.py` 能打开网页，但**左栏角色列表为空**，或列表里的角色**全部变灰无头像、点开报错** | ① 服务端 `assets/cdndata`（①层角色名册）未找到时左栏列表为空；<br>② `paths.store` 指错目录层级时角色全部变灰且无法读取表 | 在 `profiles/local.json` 中同时核对两项：① `paths.server` 指向 `<服务端目录>`（其下应有 `assets/cdndata/character.json` 和 `character_text.json`，或显式填 `paths.cdndata` / `WF_CDNDATA`）；② `paths.store` 精确指向含 `00`～`ff` 子目录的 `<物化目录>/production/upload`。 |
| 浏览器打开 `http://127.0.0.1:8765` 打不开页面 | 默认端口 `8765` 被其他程序占用或被 Windows 系统保留（`WinError 10013`） | `wf_gui.py` 遇到端口不可用会自动切到 `8766`、`8876` 等备用端口：**看一眼黑色 `cmd` 窗口第一行打印的真实地址 `http://127.0.0.1:<端口>/`** 按该端口访问即可，也可先执行 `set WF_GUI_PORT=8766` 再启动。 |
| 启动编辑台提示 `前端未构建（...studio\dist）`，浏览器打开空白或 404 | 尚未编译 `studio/` 前端静态资源 | 在 `<工具目录>\studio` 下依次运行 `npm install` 和 `npm run build`，生成 `studio\dist\index.html` 后再回 `<工具目录>` 启动 `python -m wf.studio --view local`。详见 [06-打开编辑台.md](06-打开编辑台.md)。 |
| 启动编辑台报 `unknown named view` 或报缺少 `kulo` / `store131` | 未指定 `--view` 且 `profiles/local.json` 里没有配置 `default_view` / `views.local`，触发了内部历史默认视图回退 | 按 [04-配置工具.md](04-配置工具.md) 第 3 步模板在 `profiles/local.json` 补齐 `default_view` 与 `views.local`，或用显式参数 `python -m wf.studio --store "<物化目录>\production\upload" --manifest "<服务端目录>\assets\asset-patch\manifest.json" --base-version 1.4.54` 启动。 |
| 启动编辑台报 `ValueError: view manifest does not exist` 或 `ValueError: view store is not a directory` | `profiles/local.json` 中 `wf_root`、`views.local.store` 或 `views.local.manifest` 路径拼写错误或对应文件尚未生成 | 检查 `<物化目录>\production\upload` 与 `<服务端目录>\assets\asset-patch\manifest.json` 在硬盘上是否真实存在，确认 `profiles/local.json` 中路径相对 `wf_root` 正确且全部使用正斜杠 `/`。 |
| 编辑台里点击保存草稿报 `403` 或提示缺少写入令牌 | 编辑台后端重启过，浏览器标签页里拿的还是上一轮的旧会话令牌 | 在浏览器按 **`F5` 刷新一次 `http://127.0.0.1:8790/` 首页**，重新获取当前会话令牌后再保存。 |
| 编辑台带 `--server-dir` 打开文案页报找不到 `character_text_rank_p5b.json` | 上游 `startpoint-cn` 默认只带 `character_text.json`，不含覆盖表 `character_text_rank_p5b.json` | 不改服务端双镜像文案时去掉 `--server-dir` 启动即可；若需保存服务端文案镜像，在 `<服务端目录>\assets\cdndata\character_text_rank_p5b.json` 新建一个内容仅为 `{}` 的 UTF-8 文件。 |
| 编辑台在「语音」页上传音频报找不到 `ffmpeg` | 本机未安装 `ffmpeg` 转码工具（仅替换语音时需要） | 安装 `ffmpeg` 并确保 `cmd` 里运行 `ffmpeg -version` 正常输出，或设置环境变量 `WF_FFMPEG` 指向 `ffmpeg.exe` 完整路径。 |

## 四、发布阻断、「改了没生效」与游戏崩溃速查（第 05 篇及进阶）

### 1. 发布命令或打包报错

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 运行 `wf_publish.py`、`wf_publish_guard.py` 或 `wf_selftest.py [10/20]` 报 `配置的 server 无法导出有效 CDN 根`（或 `未找到 CDN 目录`） | 工具在导入阶段检查服务端 `.cdn/cn/archive-common-diff` 未找到（`paths.server` 未填对，或 `.cdn/cn` 资源尚未放入） | 检查 `profiles/local.json` 中 `paths.server` 是否指向 `<服务端目录>`（或直接填 `paths.cdn_dir` / 环境变量 `WF_CDN_DIR` 指向 `<服务端目录>/.cdn/cn`），且其下已按第 02 篇放好 `archive-common-diff` 文件夹。 |
| 发布报 `发布被键闸门阻断(线上已有的键会消失)` | 你本地 `store` 里的这张表比服务端 CDN 现网最新版本**少了键**（通常是因为用了落后的旧 `store` 基线，一旦强发会把线上新加的角色或词条整批抹掉） | **严禁随手加 `--allow-key-deletion` 强行放行！** 先重新从当前最新 CDN 物化对齐 `store` 基线后再做修改。详见 [发布事故复盘](../experience/发布事故复盘.md)。 |
| 发布报 `发布被客户端能力闸门阻断(档案 ...)`（`wfx_gate` / `compat`） | 你在表里填写了扩展 `wfx:` 效果码或特殊构造（如 `422/423/424/724`），但所选的 `--client-profile` 客户端 APK 没有打对应补丁，发出去会崩溃或静默失效 | 若使用的是第 03 篇自制的基础连服客户端，请删掉扩展 `wfx:` 效果改用官方原生词条，发布时传 `--client-profile official`；若确需扩展能力，详见 [客户端补丁与APK](../guide/客户端补丁与APK.md)。 |

### 2. 「改了数据，但进游戏一点变化都没有」四步排查法

遇到改完游戏里还是旧数值，按下面 4 步从上往下核对，99% 都能当场定位：

1. **只点了「保存修改」，忘了点「发布」？**
   看一眼 `WF 修改器` 顶部是不是还挂着 **`待发布 1`**（或是在 Studio 编辑台里只保存了草稿——编辑台草稿不会自动改服务端！）。必须发布生成新的 `pinball-<旧版>-<新版>-...zip` 热更包。
2. **上游服务端发包后忘了同步并重启？**
   按 [02-部署服务端.md](02-部署服务端.md) 部署的上游 `startpoint-cn` 在启动时编译静态快照：发包后需把 `<服务端目录>\.cdn\cn\dev-catalog\EntityLists\` 下的最新 `.csv` 覆盖到 `<服务端目录>\.cdn\cn\EntityLists\`，并在服务端窗口按 `Ctrl + C` 后重跑 **`npm run start:cn`**，确认日志里 `"targetVersion"` 已变成刚刚发布的新版本号。
3. **游戏客户端没有「真重启」？**
   只切回手机桌面再点回游戏不会检查更新！必须**彻底划掉后台进程关闭游戏，再重新点图标启动**，看到标题页走过下载进度条才算拉到了新包。
4. **改错等级行或曾手工删过旧 `.zip` 复用了旧版本号？**
   - 刚建号的角色通常是 **Lv 1**，只改 `Lv 100` 的 HP 在 1 级角色面板上看不出变化；
   - 如果你曾手动删掉 `1.4.55` 的 `.zip` 又重发了一个同名 `1.4.55`，已经升到 `1.4.55` 的客户端绝不会重新下载它——再发一版 `1.4.56` 往前推进版本号即可。

### 3. 发布后客户端弹窗报错或闪退崩溃

> **第一步永远是先止血恢复**：
> 打开 `WF 修改器` → 顶部「**系统 -> 日志**」 → 对刚才改崩的那条记录点击 **`回溯到此前`**（自动还原备份并往前发一个更高版本号的修复包；**切勿直接去 `.cdn/cn` 删已发 `.zip`**）。恢复游戏正常进入后，再对照下表查刚才哪格填错了：

| 游戏报错码 / 崩溃现象 | 常见触发原因 | 修正办法 |
|---|---|---|
| **`C7050`**（进编队或进战斗崩） | 词条或队长技的**数值列（`c29`～`c51`）留空了**（客户端只对第 1 段做了空串兜底，第 2、3 段空串转 `NaN` 必崩） | 所有数值列（`power1` / `first_max` 等）不用时**一律填 `"0"`**，绝不留空字符串 `""`。 |
| **`C7101`**（进角色列表或编队崩） | 词条引用了不存在的固有状态 ID（`unique_condition`），或自定义面板文案漏挂接 | 检查 `unique_condition_id` 列填的 ID 是否已在 `unique_condition` 表中创建并一并发布。 |
| **`C2268`**（点开角色详情页崩） | 角色基础数值表 `character_status` 缺少必备等级断点行（`1 / 10 / 80 / 100`） | 还原该角色 `character_status`，只改现有断点行的数值，绝不删除断点行。 |
| **`C8601`**（点开玛纳板崩） | 自制或克隆角色的玛纳板节点表 `mana_node` 与开板表不匹配 | 检查克隆角色的 16 张关联表是否完整同步发布。 |
| **`C7051`**（放技能或战斗中崩） | 技能 DSL 指令参数非法，或客户端缺少该角色专属演出补丁 | 用技能预检工具排查 DSL，或改用官方兼容技能模板。 |
| **`F1009`**（空指针闪退） | 表行字段列数被手工改坏、跨表外键断链，或立绘/像素图集缺配套坐标 | 用 `wf_selftest.py` 校验表结构，切勿用 Excel 直接打开保存 CSV / `orderedmap` 数据。 |
| **`H400`**（通信请求错误） | 客户端发出的请求被服务端拒绝（如发放或编入了服务端 `assets/cdndata` 尚未注册的新角色 ID） | 新增角色或装备后，确认服务端侧 JSON 已同步更新并**重启服务端**。 |
