# 05｜第一次改数据

恭喜走到这里！现在服务端、客户端和修改工具都已经连通了。

本篇带你走完一次最完整的五步闭环：
**改一个角色 HP → 预览 → 发布 → 进游戏看到变化 → 还原**。

跑通这一圈后，你就彻底掌握了这款游戏离线热更的核心工作方式，而且最后一步会把数据干干净净还原回官方初值，不留任何脏数据。

---

## 动手前准备（1 分钟）

1. 确认你在 [02-部署服务端.md](02-部署服务端.md) 启动的服务端窗口正在运行。
2. 打开模拟器或手机里的游戏，点开「角色」界面，选一个**你当前账号已经拥有**的角色（推荐选建号自带的初始主角 **阿尔克**，角色 ID 为 `1`），**看一眼他现在的等级和 HP 数字并记下来**，随后可以先退回系统桌面。

---

## 第 1 步：启动图形修改器并打开角色的「数值」页（未实测）

我们先用仓库内置的网页图形修改器 `wf_gui.py` 来改基础血量（HP）。

### 做什么

1. 在 `<工具目录>` 的命令提示符中运行（或者直接双击 `<工具目录>` 下的 `wf-gui.bat`）：

```bat
python wf_gui.py
```

2. 保持这个黑色命令提示符窗口不要关，用电脑浏览器打开：
   <http://127.0.0.1:8765>
3. 在网页左侧的 **`搜索角色 / ID / 代号`** 输入框里输入 `阿尔克`（或输入 `1`，或输入你刚才记下的已拥有角色名字），在筛出的列表里点击该角色。
4. 在网页上方导航栏的「**角色**」分组里，点击 **`数值`** 页签。

### 预期看到什么

- 命令提示符打印 `WF 修改器已启动: http://127.0.0.1:8765`。
- 网页左上角标题为 **`WF 修改器`**，顶部显示当前 `store` 路径与 **`待发布 0`**。
- 点击 **`数值`** 页签后，右侧列出该角色在不同等级断点（如 `Lv 1`、`Lv 10`、`Lv 80`、`Lv 100`）对应的 `HP` 与 `ATK` 输入框。

### 不对怎么办

- 启动 `wf_gui.py` 立刻报错退出，提示 `未找到数据包 store`：回到 [04-配置工具.md](04-配置工具.md) 第 3 步，检查 `profiles/local.json` 的 `paths.store` 是否填对。
- 页面 `http://127.0.0.1:8765` 打不开（端口 `8765` 被占用或被 Windows 系统保留报 `WinError 10013`）：`wf_gui.py` 会自动依次改试 `8766`、`8876` 等备用端口，看一眼黑色命令提示符窗口打印的实际地址 `WF 修改器已启动: http://127.0.0.1:<端口>/` 按那个地址打开即可（也可先执行 `set WF_GUI_PORT=8766` 再启动）。
- 网页左侧角色列表为空：说明 `paths.store` 指错了层级（没有指到含 `00`～`ff` 子目录的 `production/upload`）。

---

## 第 2 步：修改角色 HP 并核对「预览」对比（未实测）

角色面板显示的血量来自客户端数据包里的 `character_status.orderedmap` 表，按固定等级断点存储，中间等级由客户端自动按直线插值计算。

> **⚠️ 两个新手防坑要点**：
> 1. **刚建号的角色通常是 Lv 1**：如果你只改了 `Lv 100` 的 HP，进游戏看 1 级角色是看不出变化的！所以测试时请**把 `Lv 1` 和 `Lv 100`（或所有等级行）的 HP 都改成 `9999`**。
> 2. **只改数字，绝不增删等级断点行**：角色缺少 `1 / 10 / 80 / 100` 任一必备断点时，打开角色页会触发 `C2268` 崩溃。

### 做什么

1. 在右侧 **`数值`** 页的表格中，把该角色 **`Lv 1`** 到 **`Lv 100`** 各行的 **HP** 输入框都改成 **`9999`**（ATK 保持原样不动）。
2. 点击表格右上方的 **`保存修改`** 按钮。
3. **不要急着闭眼狂点确定**——此时网页会先走一次只读预演（`dry_run`），弹出一个**改动预览确认框**。请仔细看一眼弹窗里列出的 `旧值 → 9999` 对比。
4. 确认角色 ID 和改动数字都符合预期后，在预览弹窗里点击**「确定」**正式写入本地 `store`。
   *(如果你发现填错了数字，在预览弹窗点「取消」，硬盘上任何文件都不会被改动。)*
5. （可选命令行双保险预览）你也可以新开一个 `<工具目录>` 命令提示符窗口，运行下面命令预览即将打包的内容：

```bat
python wf_publish.py --list
```

### 预期看到什么

- 点击 **`保存修改`** 时先弹出列出改前/改后数值的预览确认框。
- 点确定后，页面底部「运行日志」提示保存成功并自动生成了 `.bak-wfmod-<时间戳>` 备份，页面顶部徽章变为 **`待发布 1`**。
- 若运行了 `python wf_publish.py --list`，窗口会打印 `版本推进 : 1.4.54 -> 1.4.55`、待发布的 `production/upload/...` 文件名，且「键闸门」与「能力闸门」均无阻断报错。

### 不对怎么办

- 点击 **`保存修改`** 提示没有改动：确认你修改输入框里的数字后没有点旁边的「刷新」按钮把输入冲掉。
- `wf_publish.py --list` 报 `未找到 CDN 目录`：检查 `profiles/local.json` 里的 `paths.server` 是否正确指向了 `<服务端目录>`，且 `<服务端目录>\.cdn\cn\archive-common-diff` 文件夹存在。

---

## 第 3 步：发布增量更新包到服务端 CDN（未实测）

刚才的「保存修改」只改了 `<物化目录>` 里的本地表文件，游戏客户端还不知道。现在点击「发布」，工具会把改动打成 `1.4.54 -> 1.4.55` 的增量热更包放入服务端 `.cdn\cn`。

### 做什么

1. 在 `WF 修改器` 网页右上角，点击蓝色的 **`发布并重启游戏`** 按钮。
2. 网页会再次弹出待发布版本与文件清单预览框（显示版本将从 `1.4.54` 推进到 `1.4.55`），核对无误后点击**「确定」**。
   *(等价命令行做法：在 `<工具目录>` 命令提示符运行 `python wf_publish.py --client-profile official`。)*
3. **如果你使用的是 [02-部署服务端.md](02-部署服务端.md) 部署的上游 `startpoint-cn` 服务端**，请额外执行一次服务端内容同步（因为上游服务端在启动时会把 CDN 编译成静态快照）：
   - 首次同步前，先把 `<服务端目录>\.cdn\cn\EntityLists`（若是 `entities` 则对应 `entities`）复制一份到 `<工作目录>\EntityLists-1.4.54-backup` 留作原版备份；
   - 把工具刚刚自动生成的 `<服务端目录>\.cdn\cn\dev-catalog\EntityLists\` 里面的 `.csv` 文件，复制覆盖到 `<服务端目录>\.cdn\cn\EntityLists\` 中；
   - 切到运行服务端的黑色命令提示符窗口，按 `Ctrl + C` 停止服务，然后运行下面命令重新同步并启动服务：
     ```bat
     npm run start:cn
     ```

### 预期看到什么

- `WF 修改器` 底部运行日志打印 `[OK] 已发布: archive-common-diff/pinball-1.4.54-1.4.55-1-<月日时分>.zip`（同时自动在 `archive-medium-diff` 和 `archive-android-diff` 生成配套占位包），顶部徽章变回 **`待发布 0`**。
- 重启后的服务端窗口在内容同步阶段打印的 JSON 中，`"targetVersion"` 变为 **`"1.4.55"`**，并重新显示 `Server listening at http://0.0.0.0:8001`。

### 不对怎么办

- 服务端运行 `npm run start:cn` 时报 `CONTENT_SYNC_FAILED`：检查是否已将 `.cdn\cn\dev-catalog\EntityLists\` 下的最新 `.csv` 覆盖到 `.cdn\cn\EntityLists\`，且没有手工往 `archive-*-diff` 里丢入非工具生成的杂乱 `.zip` 文件。

## 第 4 步：进游戏看到 HP 变化（未实测）

游戏只在启动登录、请求 `/get_path` 时检查是否有新版本热更包。

### 做什么

1. 在安卓模拟器或安卓手机上，**彻底划掉后台关闭《世界弹射物语》**（不要只切到后台再切回来），然后重新点击桌面图标启动游戏。
2. 在标题画面点击进入游戏，等待短暂的增量数据下载完成。
3. 进入底部菜单「角色」，点开你刚才修改的那个角色（如 **阿尔克**），查看他的面板 HP。

### 预期看到什么

- 进游戏时出现简短的更新下载提示（拉取 `1.4.55`）。
- 角色详情页里的 **HP 数字已经变成了 `9999`**！

### 不对怎么办

- 进游戏完全没有触发下载提示，且 HP 还是旧数字：
  1. 确认游戏确实**彻底杀掉后台进程重启**过（仅返回游戏主页不会触发热更检测）。
  2. 检查第 3 步的服务端窗口是否已重跑 `npm run start:cn`，且启动日志里的 `"targetVersion"` 确实升到了 `"1.4.55"`。
- 触发了下载，但打开角色还是旧 HP：检查你看的角色是不是还停留在 **Lv 1**，而你在第 2 步是不是只改了 `Lv 100` 的那一行。

---

## 第 5 步：一键还原回修改前的原版数值（未实测）

实验成功！现在我们把刚才改过的角色还原回官方初始状态。

> **🚨 牢记热更回滚第一铁律：版本号永远只进不退！**
> **绝对不要**自己去 `<服务端目录>\.cdn\cn\archive-common-diff\` 里手动删除刚刚生成的 `1.4.55` 压缩包！因为你的手机/模拟器客户端本地已经记录自己升到了 `1.4.55`，删掉服务端压缩包会让客户端卡在「比服务器版本还高」的死胡同里。
> **唯一正确的还原方式**：把修改前的表备份还原回 `store`，再**往前发布一个更高的版本号（`1.4.55 -> 1.4.56`）**，让客户端正常下载覆盖回去。`WF 修改器` 的「一键回溯」已经帮你把这两步合并成了一个按钮。

### 做什么

1. 回到电脑浏览器的 `WF 修改器` 页面，在顶部导航栏最右侧的「**系统**」分组下，点击 **`日志`** 页签（页面标题为 **`改动日志 / 一键回溯`**）。
2. 在列表最上方找到你刚才那条 `character_status`（发布版本 `1.4.55`）的记录，点击该行右侧的 **`回溯到此前`** 按钮。
3. 在弹出的确认框（提示将把 `character_status` 表还原到这次改动之前的状态并自动重新发布）中，点击**「确定」**。
4. 同第 3 步一样，把新生成的 `<服务端目录>\.cdn\cn\dev-catalog\EntityLists\` 下的 `.csv` 覆盖到 `<服务端目录>\.cdn\cn\EntityLists\`，并在服务端窗口按 `Ctrl + C` 后重跑 `npm run start:cn`，确认服务端 `"targetVersion"` 推进到 **`"1.4.56"`**。
5. 再次彻底划掉后台并重开模拟器/手机里的游戏，下载 `1.4.56` 更新后打开该角色面板核对。

### 预期看到什么

- 点击 **`回溯到此前`** 后，底部运行日志显示备份已还原，并发布了新的 `pinball-1.4.55-1.4.56-1-<月日时分>.zip`。
- 客户端重开游戏下载 `1.4.56` 后，角色的 **HP 已经恢复为你动手前记下的原版数字**。

### 不对怎么办

- 如果你只想把本地 `store` 还原、暂时不想立刻发新包：可以改点「系统」分组下的 **`备份`** 页签，对目标 `.bak-wfmod-*` 点「还原」，等所有调整都改完后再统一点击右上角 **`发布并重启游戏`**。
