# 02 部署服务端

本篇带你在 Windows 电脑上部署上游国服私服服务端 [startpoint-cn](https://github.com/DontBeAlarmed/startpoint-cn)，并确认服务正常启动。

## 开始前先看（支持范围与自备清单）

上游仓库明确规定了运行基线与安全边界（详见上游 [README 支持边界](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/README.md) 与 [运行服务文档](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/docs/getting-started/README.md)）：

- **操作系统**：本文以 Windows 10 / 11 原生环境为准。
- **Node.js 版本**：必须 **`>= 20.12.0`**（推荐安装 20 LTS 或 22 LTS）。
- **自备 CDN 资源**：一份完整的**官方 CN `1.4.54` CDN 资源文件**（约 10 GB，放入目录后连同服务端生成物建议预留 15 GB 以上磁盘空间）。**上游仓库和本文均不提供任何 CDN 或游戏资源下载渠道**，请自行准备合法取得的资源。
- **网络范围**：仅限本机和受信任的局域网（如家里同一个路由器下）运行。服务端管理后台没有密码鉴权，**切勿直接把端口暴露到公网**（详见上游 [网络支持边界](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/docs/getting-started/network-boundary.md)）。

> **标注说明**：文中凡依赖联网安装或自备官方 CDN 资源、未在文档编写环境中实际跑过的步骤，均在标题标明 **「未实测」**；所有命令、参数、目录结构与输出格式均已核对上游源码。

## 第 1 步：安装 Node.js

### 做什么

1. 打开浏览器访问 [Node.js 官方网站](https://nodejs.org/)，下载 Windows 安装包（`.msi`）。请选择 **20 LTS** 或 **22 LTS** 版本（版本号必须大于等于 `20.12.0`）。
2. 双击下载好的 `.msi` 安装包，全程保持默认勾选项，一路点 `Next` 完成安装。
3. 按键盘 `Win + R`，输入 `cmd` 并按回车，打开黑色的「命令提示符」窗口。
4. 依次输入下面两条命令，每输完一条按一次回车：

```bat
node -v
npm -v
```

### 预期看到什么

- `node -v` 显示一行版本号，例如 `v20.x.x` 或 `v22.x.x`（若是 `v20`，中间数字必须 `>= 12`）。
- `npm -v` 显示一行数字版本号，例如 `10.x.x` 或 `11.x.x`。

### 不对怎么办

- 提示 `不是内部或外部命令，也不是可运行的程序`：先把当前黑色窗口关掉，重新按 `Win + R` 输入 `cmd` 打开再试。若仍找不到，重新运行 Node.js 安装包，确认勾选了 `Add to PATH`。
- 版本号低于 `v20.12.0`：去 Windows「设置 -> 应用」卸载旧版 Node.js，重新安装 20 LTS 或 22 LTS。低于 `20.12.0` 时，后续启动脚本会报 `当前 Node.js 版本无法加载 .env`。
- 如果你打开的是蓝底或新版 PowerShell 窗口，运行 `npm` 时报 `禁止运行脚本`（`running scripts is disabled on this system`）：请改用 `cmd`（命令提示符）窗口操作，或者把命令里的 `npm` 写成 `npm.cmd`。

## 第 2 步：下载上游服务端代码

### 做什么

1. 在电脑硬盘上选一个剩余空间充足（建议 15 GB 以上）的文件夹作为存放位置，下文统一记作 `<工作目录>`（文件夹路径尽量只用英文和数字，不要带空格或特殊符号）。
2. 用文件资源管理器打开 `<工作目录>`，鼠标点击顶部的**路径地址栏**，输入 `cmd` 并按回车，直接在这个文件夹里打开命令提示符。
3. 获取上游 [startpoint-cn](https://github.com/DontBeAlarmed/startpoint-cn) 代码（二选一）：
   - **已安装 Git**：在命令提示符输入下面命令并回车：
     ```bat
     git clone https://github.com/DontBeAlarmed/startpoint-cn.git
     ```
   - **未安装 Git**：用浏览器打开 <https://github.com/DontBeAlarmed/startpoint-cn>，点击页面右上角绿色的 **`<> Code`** 按钮，再点 **`Download ZIP`**。下载后把压缩包解压到 `<工作目录>`，并将解压出的文件夹重命名为 `startpoint-cn`。
4. 在命令提示符中进入服务端文件夹（下文将 `<工作目录>\startpoint-cn` 统一记作 `<服务端目录>`）：

```bat
cd startpoint-cn
```

### 预期看到什么

打开 `<服务端目录>` 后，能**直接**看到 `package.json`、`package-lock.json`、`.env.example`、`src`、`admin`、`tools`、`client-patch` 等文件和文件夹。

### 不对怎么办

- 打开 `startpoint-cn` 后里面只看到一个 `startpoint-cn-main` 子文件夹（解压 ZIP 常见情况）：点进子文件夹，把里面的全部内容剪切移动到外层 `<服务端目录>`，确保 `package.json` 直接位于 `<服务端目录>` 下。
- `git clone` 长时间不动或报连接失败：检查本机网络状态，或改用上面的浏览器 `Download ZIP` 方式。

## 第 3 步：安装项目依赖（未实测）

上游仓库包含服务端本体与内置的 `admin` 网页管理后台，根目录的一条 `npm ci` 命令会按同一份锁文件把两边依赖一起装好（详见上游 [运行服务文档](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/docs/getting-started/README.md)）。

### 做什么

确认命令提示符当前路径在 `<服务端目录>` 下，输入以下命令并回车：

```bat
npm ci
```

### 预期看到什么

- 等待几分钟下载安装完成后，窗口末尾显示 `added ... packages`，过程中没有 `npm ERR!` 红色报错。
- `<服务端目录>` 下新出现了 `node_modules` 文件夹。

### 不对怎么办

- 报网络超时（`ETIMEDOUT` / `ECONNRESET`）：检查网络连接后，重新运行一次 `npm ci`。
- 报 `better-sqlite3`、`node-gyp` 或缺少 `Visual Studio C++` 编译工具错误：通常是因为安装了过新的非 LTS 实验版 Node.js，没有对应的预编译数据库组件。请卸载当前 Node.js，改装 **Node.js 20 LTS 或 22 LTS**，再重新运行 `npm ci`。

## 第 4 步：放入自备的官方 CN 1.4.54 CDN 资源

默认 `ASSET_MODE="local"` 模式下，服务端会从 `<服务端目录>\.cdn\cn\` 读取游戏数据并向客户端提供资源下载（详见上游 [CDN 机制与架构总览](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/docs/cdn/overview.md) 与 [CDN 运行时支持边界](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/docs/cdn/runtime-support.md)）。

### 做什么

1. 在 `<服务端目录>` 的命令提示符中运行下面命令，创建 `.cdn\cn` 两级空目录：
   ```bat
   mkdir .cdn\cn
   ```
2. 把你**自备的官方 CN `1.4.54` CDN 资源**完整解压或复制到 `<服务端目录>\.cdn\cn\` 里面（本文不提供任何获取渠道）。
3. 用文件资源管理器打开 `<服务端目录>\.cdn\cn\`，肉眼核对里面的文件夹名称。

### 预期看到什么

打开 `<服务端目录>\.cdn\cn\` 后，**这一层目录下面直接包含**以下文件夹：

- **1 个资源清单文件夹**：名为 `EntityLists` **或** `entities`（两种官方目录名服务端都支持；点进去必须能看到 `10939-android_medium.csv`）。
- **3 个 Android 全量包文件夹**：`archive-common-full`、`archive-medium-full`、`archive-android-full`。
- **3 个 Android 增量包文件夹**：`archive-common-diff`、`archive-medium-diff`、`archive-android-diff`。
- （允许同时存在）`archive-ios-full`、`archive-ios-diff`：完整官方包共有 692 个 `.zip`（约 10 GB），其中 Android 运行时实际使用上述 6 个 Android 目录里的 **677 个 `.zip`**。

目录层级示意如下：

```text
<服务端目录>\
└── .cdn\
    └── cn\
        ├── EntityLists\（或 entities\，内含 10939-android_medium.csv）
        ├── archive-common-full\
        ├── archive-medium-full\
        ├── archive-android-full\
        ├── archive-common-diff\
        ├── archive-medium-diff\
        └── archive-android-diff\
```

### 不对怎么办

- `.cdn\cn\` 里面还是一个 `.rar` / `.zip` / `.7z` 总压缩包：必须把总压缩包解压出来（注意：解压出上面的 `archive-*` 文件夹即可，**不要**把 `archive-*` 里面的几百个 `pinball-*.zip` 再逐个解压）。
- 多套了一层文件夹（比如变成了 `.cdn\cn\cn\archive-common-full`）：把最里层的所有文件夹往上移一层，确保 `archive-common-full` 直接在 `.cdn\cn\` 下面。
- 缺少上面 6 个 `archive-*` 文件夹中的任何一个，或找不到 `10939-android_medium.csv`：说明这份 CDN 资源不完整。服务端不支持残缺、改写或拼凑的基线 CDN，请重新准备完整的官方 CN `1.4.54` CDN。

## 第 5 步：校验本地 CDN 是否放对（未实测）

> **⚠️ 重要避坑：不要双击根目录下的 `validate_cdn.bat`（也不要点 `unzip_cdn.bat`）！**
>
> 经核对上游源码（`src/validate_cdn.ts` 与 `assets/asset_lists/`），`validate_cdn.bat` 是上游国际服（Kakao `en` / `ko` / `th`）遗留脚本，里面完全没有国服 `cn` 的清单数据。双击它会让你选择 `en/ko/th` 并提示大量文件缺失，**不能用来校验国服 CDN**。

校验国服 CDN 应使用上游 [README 常用命令](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/README.md) 中列出的 `npm run cdn:patch:check`（只读检查，不改动文件）。

### 做什么

在 `<服务端目录>` 的命令提示符中运行：

```bat
npm run cdn:patch:check
```

*（可选完整哈希核对：如果你想把约 10 GB 的 677 个归档逐字节算一遍 SHA-256 校验和，可按上游 [Catalog 与 Planner 文档](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/docs/cdn/catalog-planner.md) 运行 `node tools/audit_cdn_catalog.cjs --initial`，机械硬盘上耗时较长，日常只需跑上面的快速校验即可。）*

### 预期看到什么

几秒钟后，窗口打印出一行 JSON，其中 `"status"` 为 `"valid"`，`"baselineVersion"` 与 `"targetVersion"` 均为 `"1.4.54"`：

```json
{"schemaVersion":1,"status":"valid","baselineVersion":"1.4.54","targetVersion":"1.4.54","patchCount":0,"patchArchiveCount":0,"patchBytes":0,"patches":[]}
```

### 不对怎么办

- 输出 `错误 [CDN_PATCH_CHECK_FAILED]` 并提到 `missing Android medium EntityLists CSV` 或路径不存在：回到第 4 步，检查 `.cdn\cn\` 是否多套了一层目录，以及 `EntityLists`（或 `entities`）文件夹里是否有 `10939-android_medium.csv`。
- 输出归档缺失、大小不一致或版本链错误：说明 `.cdn\cn\archive-*` 里有 `.zip` 漏拷或损坏，重新复制完整的官方 CN `1.4.54` CDN 后再跑一次校验（更多错误定位见上游 [CDN 排查手册](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/docs/cdn/debugging.md)）。

## 第 6 步：查询电脑局域网 IP 并配置 `.env`

上游 [`.env.example`](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/.env.example) 默认把资源下载地址写成了 `127.0.0.1`。但国服客户端是安卓应用：无论装在**安卓真机**还是同一台电脑的**安卓模拟器**里，安卓系统内部的 `127.0.0.1` 都指向安卓设备自己，而不是你的 Windows 电脑。因此需要把资源地址和联机对外地址都改成电脑的局域网 IP（各变量含义详见上游 [网络支持边界](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/docs/getting-started/network-boundary.md)）。

### 做什么

1. 在 `<服务端目录>` 的命令提示符中，将示例配置复制为正式配置文件 `.env`：
   ```bat
   copy .env.example .env
   ```
2. 在命令提示符中查询本机局域网 IP：
   ```bat
   ipconfig
   ```
   在输出里找到你当前正在上网的网卡（连 Wi-Fi 看「无线局域网适配器 WLAN」，插网线看「以太网适配器 以太网」；避开 WSL、Hyper-V、VMware、VPN 或模拟器生成的虚拟网卡），记下它的 **`IPv4 地址`**（四段数字，下文记作 `<电脑局域网IP>`；下一篇制作客户端补丁时也要填同一个地址）。
3. 用「记事本」打开 `<服务端目录>\.env`（可在命令提示符运行 `notepad .env` 直接打开），核对并修改下面两处，其余行保持原样：
   - 找到 `CDN_BASE_URL="http://127.0.0.1:8001/patch/cn"`，把里面的 `127.0.0.1` 改成 `<电脑局域网IP>`：
     ```ini
     CDN_BASE_URL="http://<电脑局域网IP>:8001/patch/cn"
     ```
   - 找到 `# SESSION_PUBLIC_HOST="<LAN_HOST>"`，**删掉行首的 `# `（井号和空格）**，并把 `<LAN_HOST>` 改成 `<电脑局域网IP>`：
     ```ini
     SESSION_PUBLIC_HOST="<电脑局域网IP>"
     ```
4. 顺手确认 `.env` 中以下默认项未被误改：
   - `ASSET_MODE="local"`
   - `CDN_DIR=".cdn"`（注意：只能填父目录 `.cdn`，**不能**填 `.cdn/cn`）
   - `CN_LISTEN_HOST="0.0.0.0"`、`CN_LISTEN_PORT="8001"`
   - `SESSION_HOST="0.0.0.0"`、`SESSION_PORT="8003"`
5. 按 `Ctrl + S` 保存文件并关闭记事本。

### 预期看到什么

- `<服务端目录>` 下存在名为 `.env` 的文件（不是 `.env.txt`）。
- 再次用记事本打开 `.env` 检查时，`CDN_BASE_URL` 和 `SESSION_PUBLIC_HOST` 都已填入你的 `<电脑局域网IP>`，且 `SESSION_PUBLIC_HOST` 行首没有 `#`。

### 不对怎么办

- 文件名变成了 `.env.txt`：在资源管理器顶部菜单点击「查看 -> 显示 -> 文件扩展名」，重命名去掉末尾的 `.txt`；或者删掉它，严格用上面的 `copy .env.example .env` + `notepad .env` 编辑。
- 以后电脑重连 Wi-Fi 后路由器分配的 `<电脑局域网IP>` 变了：记得同步更新 `.env` 中的这两项并**重启服务端**（`.env` 只在服务启动时读取一次，运行中修改不会热生效），客户端里的地址也需对应一致。

## 第 7 步：启动国服服务端（未实测）

> **⚠️ 重要避坑：不要双击根目录下的 `start.bat`（也不要点 `start-ios.bat`）！**
>
> 经核对源码，`start.bat` 是上游国际服遗留脚本：它会强制检查 `mitmproxy`（没装就自动弹窗打开下载网页并退出），且启动的是国际服旧入口 `out/server.js`（`8000` 端口），**不会启动国服服务端**（详见上游 [旧版部署兼容工具说明](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/deployment/README.md)）。
>
> 上游文档中的 `bash scripts/start-cn.sh` 需要 Bash 环境；在 Windows 原生命令提示符下，直接运行上游 [`package.json`](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/package.json) 提供的 **`npm run dev:cn`** 即可，它执行的动作与 `start-cn.sh` 完全相同（先构建管理后台与服务端，再自动同步本地 CDN 内容并启动服务，详见上游 [运行服务文档](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/docs/getting-started/README.md)）。

### 做什么

1. 在 `<服务端目录>` 的命令提示符中运行：
   ```bat
   npm run dev:cn
   ```
2. 首次启动监听端口时，Windows 可能会弹出「Windows 安全中心 / Windows Defender 防火墙」窗口询问是否允许 `Node.js JavaScript Runtime` 通信：**勾选「专用网络」（及当前局域网所属网络类型），点击「允许访问」**。
3. 启动完成后**不要关闭这个黑色窗口**（窗口关掉服务就停了；要停止服务时，在窗口里按 `Ctrl + C`）。
   *(提示：以后如果没有修改服务端代码、只是日常重开服务，可运行 `npm run start:cn` 复用已有构建，启动更快。)*

### 预期看到什么

窗口会按顺序自动跑完三个阶段：

1. **构建阶段**：编译 React 管理后台与服务端 TypeScript 代码。
2. **内容同步阶段（首次较慢，请耐心等待）**：服务端自动从 `.cdn\cn` 提取并生成运行所需的数据快照（Content Release），完成后打印一行含 `"status":"ok"` 与 `"targetVersion":"1.4.54"` 的 JSON（机制详见上游 [Content Sync 文档](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/docs/cdn/content-sync.md)）。
3. **正式监听阶段**：打印出类似 `Server listening at http://0.0.0.0:8001` 的日志，随后光标停在底部持续待命，不再退回命令行提示符。

### 不对怎么办

- 报 `INVALID_RUNTIME_CONFIG` 或 `[runtime] config startup failed`：`.env` 格式有误。打开 `.env` 检查引号是否成对、`SESSION_PUBLIC_HOST` 是否填了真实 IP（不能留着 `<LAN_HOST>` 占位符）、`CDN_BASE_URL` 开头是否是 `http://` 且不含 `?` 或 `#`。
- 报 `CDN_DIR must point to the parent directory`：把 `.env` 里的 `CDN_DIR` 改回 `".cdn"`，不要写成 `".cdn/cn"`。
- 报 `CONTENT_SYNC_FAILED` 或 `[runtime] content startup failed`：单独运行 `npm run content:sync`，保留第一条报错路径，对照第 4、5 步核对 `.cdn\cn` 文件是否完整。
- 报 `[runtime] http startup failed`、`[runtime] tcp startup failed` 或 `EADDRINUSE`：`8001`（HTTP）或 `8003`（联机 TCP）端口已被占用。检查是不是已经开着另一个服务端窗口没关。

## 第 8 步：在浏览器确认服务已经就绪（未实测）

### 做什么

保持第 7 步的服务端窗口运行，打开电脑上的浏览器，分别打开下面两个本机地址：

1. 健康检查接口：<http://127.0.0.1:8001/healthz>
2. 内置管理后台：<http://127.0.0.1:8001/admin/>（访问 <http://127.0.0.1:8001/> 也会自动跳到这里）

### 预期看到什么

1. 打开 `/healthz` 时，浏览器显示一段 JSON，其中关键状态均为就绪：
   - `"status":"ready"`
   - `"services":{"http":true,"tcp":true}`
   - `"admin":{"required":true,"available":true}`
   - `"assets":{"mode":"local","status":"ready","minClientVersion":"1.4.54",...}`
2. 打开 `/admin/` 时，浏览器正常加载出图形化的服务端管理后台页面。

### 不对怎么办

- 浏览器转圈卡住或提示「无法访问此网站 / 拒绝连接」：
  1. 看一眼第 7 步的命令提示符窗口，确认已经打印出 `Server listening` 而不是还在跑首次内容同步或已经报错退出；
  2. 检查黑色窗口左上角标题栏是否出现了 **「选择」** 二字（Windows 命令提示符下用鼠标点选窗口内部会把程序挂起暂停！在窗口里按一下键盘 `Esc` 键即可恢复运行）。
- 电脑浏览器访问 `127.0.0.1:8001` 正常，但你想用手机连接、而手机浏览器打不开 `http://<电脑局域网IP>:8001/healthz`：
  1. 确认手机和电脑连在同一个路由器的 Wi-Fi 下（不要连访客 Wi-Fi）；
  2. 打开 Windows「控制面板 -> Windows Defender 防火墙 -> 允许应用或功能通过 Windows Defender 防火墙」，找到 `Node.js JavaScript Runtime` 把「专用」和「公用」勾上（或在防火墙高级设置中放行 TCP `8001` 与 `8003` 入站端口）。
