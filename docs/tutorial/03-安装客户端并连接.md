# 03 安装客户端并连接

本篇带你将**自备的官方 CN `1.8.1` Android 客户端 APK**按上游 [客户端补丁说明（`client-patch/README.md`）](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/client-patch/README.md) 完成两处最小修改，重新对齐并签名后，安装到安卓模拟器或手机，连上你自己部署的服务端。

## 开始前先看（支持范围与自备清单）

- **已完成服务端部署**：请先按上一篇 [02 部署服务端](./02-部署服务端.md) 启动 `startpoint-cn` 服务端，保持黑色窗口运行，并准备好上一篇第 6 步查到的 `<电脑局域网IP>`（服务端 HTTP 默认端口为 `8001`，组合后即 `<电脑局域网IP>:8001`）。
- **自备官方客户端 APK**：上游唯一保证支持的客户端是**官方 CN `1.8.1` Android 客户端**，且只做下面两处最小改动（详见上游 [README 客户端补丁](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/README.md) 与 [CDN 运行时支持边界](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/docs/cdn/runtime-support.md)）。**上游仓库和本文均不提供任何 APK 或游戏资源下载渠道**，请自行准备合法取得的安装包。
- **设备空间要求**：首次连接服务端后，客户端会在游戏内下载并解压约 10 GB 的完整资源，请确保目标模拟器或安卓手机至少留有 15 GB 可用空间。

> **标注说明**：本篇操作均依赖自备的官方 CN 客户端 APK、签名工具及安卓设备，未在文档编写环境中实际执行，涉及步骤标题均标明 **「未实测」**；两处代码改动、文件路径与脚本用法均已核对上游 [`client-patch/README.md`](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/client-patch/README.md) 与 [`client-patch/apply.sh`](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/client-patch/apply.sh)。

## 第 1 步：准备打补丁与重签名工具

对照上游 [`client-patch/README.md`](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/client-patch/README.md) 列出的前置工具（均需自备，不随仓库分发），在电脑上确认备齐以下软件：

1. **Java 开发工具包（JDK，推荐 JDK 17 或 21）**：供 FFDec 运行，并提供自带的 `keytool` 生成签名证书。
2. **FFDec 24.0.1（JPEXS Free Flash Decompiler）**：上游文档指定版本为 `24.0.1`，用于修改 APK 内的主 SWF 脚本。
3. **Android SDK Build-Tools**：需要用到目录里的 `zipalign.exe`（对齐）和 `apksigner.bat`（签名），下文将该工具所在文件夹记作 `<Build-Tools目录>`。
4. **7-Zip 压缩软件**：用于在不拆散整包的前提下，从 APK 中单独取出和替换 SWF 文件，并删除旧签名目录。

### 做什么

1. 在电脑上新建一个专门放补丁中间文件的空文件夹，下文记作 `<补丁工作目录>`（路径尽量不要带中文、空格或特殊符号）。
2. 把你自备的官方 CN `1.8.1` 客户端 APK **复制一份**放进 `<补丁工作目录>`，并将这份副本重命名为 `wf-working.apk`（保留原件不动，改坏了随时可以重新复制）。
3. 在 `<补丁工作目录>` 的文件资源管理器地址栏输入 `cmd` 并按回车，打开命令提示符，输入下面命令检查 Java：

```bat
java -version
keytool -help
```

### 预期看到什么

- `java -version` 打印出 Java 版本号（如 `17.x` 或 `21.x`）。
- `keytool -help` 打印出密钥和证书管理工具的命令列表。
- `<补丁工作目录>` 里有一份 `wf-working.apk` 副本。

### 不对怎么办

- `java` 或 `keytool` 提示 `不是内部或外部命令`：请安装完整的 JDK（不要装不含 `keytool` 的精简运行时），安装后关掉命令提示符重开再试。
- 在命令行直接输 `zipalign` 提示找不到命令：属于正常现象（通常未加入系统 `PATH`），后面的步骤直接用带引号的完整路径 `""<Build-Tools目录>\zipalign.exe""` 和 `""<Build-Tools目录>\apksigner.bat""` 调用即可。

## 第 2 步：从 APK 副本中取出主 SWF 文件（未实测）

APK 本质上是一个 ZIP 压缩包。为了不破坏安装包里 `resources.arsc` 等文件的原始未压缩对齐属性，我们**不把整个 APK 解压拆散**，只用 7-Zip 打开并单独取出里面的主 SWF 文件 `assets/worldflipper_android_release.swf`。

### 做什么

1. 在 `<补丁工作目录>` 中，鼠标右键点击 `wf-working.apk`，选择 **7-Zip -> 打开压缩包**（注意是「打开压缩包」，不要选「解压到…」）。
2. 在弹出的 7-Zip 窗口里，双击进入 `assets` 文件夹，找到 **`worldflipper_android_release.swf`**。
3. 用鼠标把 `worldflipper_android_release.swf` 拖拽到 `<补丁工作目录>` 文件夹空白处，复制出来。
4. 先关闭 7-Zip 窗口（以免后面保存或占用来回冲突）。

### 预期看到什么

`<补丁工作目录>` 下出现 `worldflipper_android_release.swf` 文件，大小约 **29.0 MB**（与上游 [CDN 机制总览中的 CN 1.8.1 客户端对照表](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/docs/cdn/overview.md) 一致）。

### 不对怎么办

- `assets` 里找不到 `worldflipper_android_release.swf`，或文件大小明显不对（如约 28.2 MB 是旧版 `1.7.6` / `1.7.8`）：请检查你自备的 APK 是否确为官方 CN **`1.8.1`** Android 客户端；上游服务端不支持旧版客户端。

## 第 3 步：按上游 `client-patch` 修改两处配置（未实测）

上游 [`client-patch/README.md`](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/client-patch/README.md) 与 [`client-patch/apply.sh`](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/client-patch/apply.sh) 明确给出了连接自建服所需的**全部两处最小改动**（不要修改其他任何游戏逻辑）：

| 序号 | 目标脚本路径 | 修改前 | 修改后 | 作用 |
|---|---|---|---|---|
| 1 | `pinball/config/core/DevConfig.as` | `public static var sdkDummy:Boolean = false;` | `public static var sdkDummy:Boolean = true;` | 跳过雷霆官方 SDK 登录，改用虚拟 `userId`（支付/实名/推送等 SDK 接口变为本地空实现） |
| 2 | `pinball/config/gbits/DevConfig_gf_android.as` | 域名 `shijtswygamegf.leiting.com`；协议 `"https"` | 域名改为 `<电脑局域网IP>:8001`；协议改为 `"http"` | 把客户端 API 请求全部指向你自己的服务端 |

> **地址格式提醒**：域名位置只填 `<电脑局域网IP>:8001`（带英文冒号和端口号），**不要**在里面再写 `http://`，也**不要**加末尾斜杠 `/`；协议是在同一文件的另一处单独把 `"https"` 改成 `"http"`。

下面给出两种操作方式，**任选一种**完成即可（Windows 新手推荐**方式 A**）：

### 做什么（方式 A：用 FFDec 图形界面直接修改，推荐 Windows 新手）

1. 启动 **FFDec 24.0.1**，点击左上角菜单 **文件（File） -> 打开（Open）**，选择 `<补丁工作目录>\worldflipper_android_release.swf`（文件较大，等待几秒加载完毕）。
2. **改第 1 处（免登录）**：
   - 在左侧树状目录依次展开 **`scripts`（脚本） -> `pinball` -> `config` -> `core`**，点击 **`DevConfig`**。
   - 点击中间代码区底部的 **编辑 ActionScript（Edit ActionScript）** 按钮。
   - 找到 `public static var sdkDummy:Boolean = false;`，把 `false` 改成 `true`。
   - 点击代码区底部的 **保存（Save）** 按钮。
3. **改第 2 处（服务器地址重定向）**：
   - 在左侧树状目录依次展开 **`scripts` -> `pinball` -> `config` -> `gbits`**，点击 **`DevConfig_gf_android`**。
   - 点击中间代码区底部的 **编辑 ActionScript（Edit ActionScript）** 按钮。
   - 把代码中出现的 `shijtswygamegf.leiting.com` 全部替换为 `<电脑局域网IP>:8001`。
   - 把代码中的 `"https"` 替换为 `"http"`。
   - 点击代码区底部的 **保存（Save）** 按钮。
4. **写回磁盘文件（必做）**：点击 FFDec 左上角主菜单 **文件（File） -> 保存（Save）**（或按 `Ctrl + S`），等左下角状态栏保存完成后关闭 FFDec。

### 做什么（方式 B：按上游文档导出 AS3 脚本 -> 运行 `apply.sh` 或记事本修改 -> 导回）

如果你想按上游 [`client-patch/README.md`](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/client-patch/README.md) 的「导出 -> 脚本替换 -> 导回」流程操作：

1. 在 FFDec 中打开 `worldflipper_android_release.swf`，在左侧 `scripts` 下**只选中 `pinball.config` 包**（切勿全选整个 `scripts` 导出，上万个混淆类全量导出会耗时数小时并极易内存溢出），右键点 **导出选中项（Export selection）**，格式选 `ActionScript`，导出到 `<补丁工作目录>\as3_export`。
2. 修改导出的两个 `.as` 文件（二选一）：
   - **已安装 Git for Windows（Git Bash 自带 `bash` 与 `perl`）**：打开 Git Bash 运行上游 [`client-patch/apply.sh`](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/client-patch/apply.sh)：
     ```bash
     bash "<服务端目录>/client-patch/apply.sh" "<补丁工作目录>/as3_export" <电脑局域网IP>:8001
     ```
   - **没有 Git Bash / Perl**：直接用记事本打开 `<补丁工作目录>\as3_export\scripts\pinball\config\core\DevConfig.as` 与 `<补丁工作目录>\as3_export\scripts\pinball\config\gbits\DevConfig_gf_android.as`，按上方表格手工改好两处并保存。
3. 回到 FFDec，使用 **导入脚本（Import scripts）**，选择导出的 `scripts` 目录（即点进去能直接看到 `pinball` 文件夹的那一层），导入完成后点击左上角 **文件 -> 保存（Ctrl + S）**，关闭 FFDec。

### 预期看到什么

- 重新用 FFDec 打开 `<补丁工作目录>\worldflipper_android_release.swf` 抽查：
  - `DevConfig` 中已是 `public static var sdkDummy:Boolean = true;`；
  - `DevConfig_gf_android` 中已是 `<电脑局域网IP>:8001` 与 `"http"`，不再有 `shijtswygamegf.leiting.com` 或 `"https"`。
- 若使用方式 B 运行了 `apply.sh`，终端会打印两行：
  - `[OK] 免登录: ...`
  - `[OK] 重定向→<电脑局域网IP>:8001: ...`

### 不对怎么办

- 重开 SWF 发现改动没了：刚才只点了代码框下方的「保存」，漏掉了左上角主菜单的 **「文件 -> 保存（Ctrl + S）」**。重新改一次并点左上角保存。
- FFDec 卡死或报 `OutOfMemoryError` 内存不足：在命令行用 `java -Xmx4g -jar "<FFDec目录>\ffdec.jar"` 指定 4 GB 内存启动 FFDec，且不要做整包导出。
- FFDec 直接保存 ActionScript 时报关联类编译错误：可在选中目标字段/方法后切换到 FFDec 右侧的 **P-code** 面板点「编辑 P-code」，把 `sdkDummy` 处的 `pushfalse` 改为 `pushtrue`，以及把 `DevConfig_gf_android` 对应字符串常量改为 `<电脑局域网IP>:8001` 和 `"http"`，保存后同样点左上角「文件 -> 保存」。

## 第 4 步：把改好的 SWF 替换回 APK 并删除旧签名（未实测）

修改过 APK 内部文件后，根目录 `META-INF` 里的官方旧签名校验信息就失效了，重签名前应当先删掉它。

### 做什么

1. 先确认 FFDec 已经完全关闭。
2. 在 `<补丁工作目录>` 右键点击 `wf-working.apk`，选择 **7-Zip -> 打开压缩包**。
3. 在 7-Zip 窗口双击进入 `assets` 文件夹，把 `<补丁工作目录>` 里改好的 `worldflipper_android_release.swf` 拖进 7-Zip 窗口，弹窗确认覆盖时点击 **「是」**。
4. 点击 7-Zip 窗口左上角的「返回上一级」回到 APK 根目录，找到 **`META-INF`** 文件夹，单击选中后按键盘 `Delete` 键删除并确认。
5. 关闭 7-Zip 窗口。

### 预期看到什么

重新用 7-Zip 打开 `wf-working.apk` 查看时：

- 根目录下已经没有 `META-INF` 文件夹；
- `assets\worldflipper_android_release.swf` 的修改时间是你刚刚保存的时间。

### 不对怎么办

- 拖入时提示「文件正由另一进程使用」：检查 FFDec 是否还在后台没关，关掉后再试。

## 第 5 步：生成自签名证书 keystore（仅首次需要，未实测）

安卓系统要求所有 APK 必须带有效签名才能安装。如果你手里已有自己的 `.keystore` 或 `.jks` 文件可跳到第 6 步；没有的话用 JDK 自带的 `keytool` 当场生成一个。

### 做什么

在 `<补丁工作目录>` 的命令提示符中运行：

```bat
keytool -genkeypair -v -keystore my-wf.keystore -alias wfkey -keyalg RSA -keysize 2048 -validity 10000
```

按窗口提示一步步输入：

1. **输入密钥库口令**：自己设一个至少 6 位数的密码（**注意：输入密码时屏幕上不会显示星号或任何字符，盲输完直接按回车**；随后再盲输一遍相同密码按回车）。
2. **询问姓名、组织单位、城市、省/市、国家代码等 6 个问题**：全部直接按回车跳过即可。
3. **询问 `CN=Unknown, ... 是否正确?`**：
   - 如果括号提示是中文 `[否]:`，输入汉字 **`是`** 并按回车；
   - 如果括号提示是英文 `[no]:`，输入字母 **`y`** 并按回车。
4. 若接着提示输入 `<wfkey>` 的密钥口令，直接按回车（使用与密钥库相同的密码）。

### 预期看到什么

`<补丁工作目录>` 下生成了 `my-wf.keystore` 文件（请把这个文件和密码留好；以后换 IP 重新打补丁时用同一个 `my-wf.keystore` 签名，就可以在设备上直接覆盖安装，不会因卸载而丢失本地设备绑定）。

### 不对怎么办

- 第 3 小步按回车后又重新从“您的名字与姓氏是什么”开始问：因为在中文 Windows 下输了 `y`（只认汉字 `是`）。重新输到确认那一步时，切换中文输入法输入 `是` 再回车。

## 第 6 步：用 `zipalign` 对齐并用 `apksigner` 签名（未实测）

> **⚠️ 顺序千万不能反**：必须 **先 `zipalign` 对齐，后 `apksigner` 签名**！如果签完名再跑 `zipalign`，会把 Android v2/v3 签名块破坏掉，导致手机和模拟器都装不上。

### 做什么

1. 在 `<补丁工作目录>` 的命令提示符中，先运行 4 字节对齐，生成 `wf-aligned.apk`（把 `<Build-Tools目录>` 换成你电脑上实际的 Android SDK `build-tools\<版本号>` 路径）：
   ```bat
   "<Build-Tools目录>\zipalign.exe" -p -f -v 4 wf-working.apk wf-aligned.apk
   ```
2. 用 `apksigner` 对 `wf-aligned.apk` 签名，输出最终成品 `wf-cn-patched.apk`：
   ```bat
   "<Build-Tools目录>\apksigner.bat" sign --ks my-wf.keystore --ks-key-alias wfkey --out wf-cn-patched.apk wf-aligned.apk
   ```
   出现 `Keystore password for signer #1:` 时，盲输第 5 步设的密码并按回车。
3. 运行签名自检，确认最终包签名合法：
   ```bat
   "<Build-Tools目录>\apksigner.bat" verify -v wf-cn-patched.apk
   ```

### 预期看到什么

- `zipalign` 末尾输出 `Verification succesful`，目录下生成 `wf-aligned.apk`。
- `apksigner verify -v` 输出首行为 `Verifies`，下面包含 `Verified using v1 scheme (JAR signing): true` 和 `Verified using v2 scheme (APK Signature Scheme v2): true`。
- `<补丁工作目录>` 下得到最终可安装的 **`wf-cn-patched.apk`**。

### 不对怎么办

- `apksigner` 报 `Keystore was tampered with, or password was incorrect`：密码输错了，重新运行第 2 小步输入正确密码。
- `apksigner verify` 报 `DOES NOT VERIFY`：确认没有对签好名的 `wf-cn-patched.apk` 再做任何 7-Zip 修改或 `zipalign`，从本步第 1 小步重新生成。

## 第 7 步：安装到安卓模拟器或手机（未实测）

### 做什么

1. **先卸载旧客户端**：如果模拟器或手机里原先装过官方原版或其他签名的《世界弹射物语》，因为签名不一致无法直接覆盖，**请先在设备桌面长按图标把它卸载干净**。
2. 安装刚签好名的 `<补丁工作目录>\wf-cn-patched.apk`：
   - **安卓模拟器（如 MuMu 12、雷电模拟器等）**：直接用鼠标把 `wf-cn-patched.apk` 拖进模拟器画面里松手（或点模拟器侧边工具栏的「安装 APK」选中该文件）。
   - **安卓手机 / 平板**：用数据线或文件传输工具把 `wf-cn-patched.apk` 拷进手机存储，在手机自带的「文件管理」里点开安装（系统弹窗拦截时按提示允许安装未知来源应用）。

### 预期看到什么

安装进度条走完提示「应用安装完成」，设备桌面上出现《世界弹射物语》图标。

### 不对怎么办

- 提示「应用未安装 / 与现有软件包冲突 / 签名不一致（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）」：设备里还没删干净旧版。安卓手机请检查「应用分身 / 隐私空间 / 多用户子账户」里是否还留着一份旧版，全部卸载后再装。
- 提示「安装包解析错误 / 未签名」：确认你拷贝安装的是签好名的 **`wf-cn-patched.apk`**，而不是中间产物 `wf-working.apk` 或 `wf-aligned.apk`。

## 第 8 步：启动游戏并连接自己的服务器（未实测）

### 做什么

1. **点开游戏前做最后三项检查**：
   - 电脑上的服务端黑框窗口仍开着，且电脑浏览器访问 <http://127.0.0.1:8001/healthz> 显示 `"status":"ready"`；
   - 如果用**安卓手机**，确认手机连的是**和电脑同一个路由器的 Wi-Fi**（不要用流量，也不要连路由器访客网络）；
   - **关闭**手机或模拟器里的加速器、VPN、抓包或代理软件，防止局域网流量被劫持走。
2. 在模拟器或手机桌面点击《世界弹射物语》图标启动游戏。
3. 看到标题画面后点击屏幕进入，当弹出约 10 GB 的**资源更新下载提示框**时点击确认下载，保持游戏在前台等待下载与解压完成（中途不要强杀游戏进程，也不要关电脑上的服务端窗口）。

### 预期看到什么

1. **直接跳过雷霆登录弹窗**：启动后不会弹出官方账号密码框，服务端会按你的设备标识自动创建本地账号与初始存档（`Player1`）。
2. **电脑服务端窗口实时滚动日志**：你点击标题屏幕时，黑色窗口会立刻刷出 `/api/index.php/tool/signup`、`/api/index.php/load`、`[BEACON ...]` 等日志；开始下载资源时，会持续访问 `/patch/cn/archive-...` 下载 ZIP（客户端下载机制详见上游 [CDN 客户端流程](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/docs/cdn/client-flow.md)）。
3. **成功进入游戏主城**：资源下载解压跑完后顺利进入游戏界面；此时用电脑浏览器刷新 <http://127.0.0.1:8001/admin/>，能在管理后台看到新生成的玩家角色。

### 不对怎么办

- **一打开还是弹出雷霆官方账号登录框**：第 3 步 `DevConfig.as` 的 `sdkDummy = true` 没有保存进 SWF，或者第 4 步没把新 SWF 拖进 APK 替换，按第 3～6 步重新核对打包。
- **游戏一直转圈后报通信错误，且电脑服务端黑框里一行新日志都没有**：
  1. 打开手机或模拟器**自带的浏览器**，输入 `http://<电脑局域网IP>:8001/healthz` 访问试试；
  2. 如果浏览器都打不开：说明设备连不到电脑——回查 [02 部署服务端](./02-部署服务端.md) 第 8 步放行 Windows 防火墙（允许 `Node.js` 或 TCP `8001`、`8003` 入站），检查电脑 `ipconfig` 的 `<电脑局域网IP>` 是否变了，以及服务端 CMD 标题栏是否误点了鼠标变成「选择」暂停状态（按 `Esc` 恢复）；
  3. 如果设备浏览器能打开 `/healthz`，只有游戏连不上：说明第 3 步 `DevConfig_gf_android.as` 里的地址填错了（例如多写了 `http://`、漏了 `:8001`、或忘了把 `"https"` 改成 `"http"`），修正后重签重装。
- **能过标题画面（服务端窗口有 `/load` 日志），但一点开始下载资源就报错或卡 `0%`**：
  打开服务端目录的 `.env` 文件，检查 `CDN_BASE_URL` 是不是还留着默认的 `127.0.0.1`！必须改成 `http://<电脑局域网IP>:8001/patch/cn`，保存后在服务端窗口按 `Ctrl + C` 停止并**重新运行 `npm run start:cn`（或 `npm run dev:cn`）重启服务端**才会生效（详见上游 [网络支持边界](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/docs/getting-started/network-boundary.md)）。
- **弹窗报 `C8601` 或 `H404`**：
  - `H404` 代表点到了上游当前尚未实现的接口（可对照上游 [支持矩阵](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/docs/status/support-matrix.md) 与 [已知问题](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/docs/status/known-issues.md) 查看当前功能覆盖范围）；
  - `C8601` 代表客户端资源校验或读取失败，请对照上游 [CDN 排查手册（C8601 章节）](https://github.com/DontBeAlarmed/startpoint-cn/blob/main/docs/cdn/debugging.md) 确认客户端确为 CN `1.8.1`、服务端 `.cdn\cn` 通过了校验且客户端下载未在中途损坏。
