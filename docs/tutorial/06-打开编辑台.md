# 06｜打开编辑台

在上一篇里，你体验了传统网页修改器 `wf_gui.py`（适合快速改基础 HP/ATK 单表）。本仓库还内置了新一代可视化工作台——**Studio 编辑台（`wf.studio`）**。

---

## 编辑台和上一篇的 `wf_gui.py` 有什么区别？

| 对比项 | `wf_gui.py`（传统修改器，端口 `8765`） | `python -m wf.studio`（编辑台，端口 `8790`） |
|---|---|---|
| **对本地 `store` 与服务端** | 保存即直接改写 `paths.store` 里的表文件 | **完全只读**，绝不改动你的 `store`、服务端或线上 CDN |
| **改动存在哪里** | 直接写进 `store`（旁存 `.bak-wfmod-*` 备份） | 只写进工具目录下的独立草稿箱 `work/studio-drafts/` 与本地交付目录 `work/studio-deliveries/` |
| **擅长做什么** | 改基础 HP/ATK（`character_status`）、快速打单表热更边 | 可视化浏览/编辑角色词条（一板/二板/三板）、技能、文案规范校验、立绘裁切、像素小人动画播放与导入、语音替换、克隆新角色、BOSS 工坊、武器工坊 |

简单来说：**在编辑台里不管你怎么点、怎么试改，都只是在草稿箱里演练，绝对不会把你正在玩的服务端或基准数据包改坏**。

---

## 第 1 步：构建编辑台前端网页（首次或更新代码后做一次）

编辑台的前端界面源码位于 `<工具目录>\studio\`，第一次打开前需要用 Node.js 把它编译成浏览器能直接加载的静态网页文件（`studio\dist\index.html`）。

### 做什么

1. 用文件资源管理器打开 `<工具目录>`，在顶部路径地址栏输入 `cmd` 并回车，打开命令提示符。
2. 依次运行下面三条命令（进入 `studio` 子目录 → 安装前端依赖 → 编译打包 → 退回 `<工具目录>`）：

```bat
cd studio
npm install
npm run build
cd ..
```

### 预期看到什么

- `npm install` 完成后没有红色的 `npm ERR!`。
- `npm run build` 在几秒内完成（使用 `Vite` 打包），生成 `<工具目录>\studio\dist\index.html` 与 `assets` 资源文件。
- 执行 `cd ..` 后，命令提示符路径回到 `<工具目录>`。

### 不对怎么办

- 报 `'npm' 不是内部或外部命令`：回到 [01-安装基础软件.md](01-安装基础软件.md) 第 2 步检查 Node.js（`>= 20.12.0`）是否已安装，并重开新的 `cmd` 窗口。
- 在 PowerShell 里报 `禁止运行脚本`：请改用 `cmd` 命令提示符窗口执行，或写成 `npm.cmd install` 与 `npm.cmd run build`。

## 第 2 步：启动编辑台后端服务（未实测）

如果你在 [04-配置工具.md](04-配置工具.md) 第 3 步已经按模板填好了 `profiles/local.json`（含 `"default_view": "local"` 与 `"views": { "local": ... }`），现在只需一条命令即可启动。

### 做什么

确认命令提示符当前路径位于 `<工具目录>`（**不是** `studio` 子目录），运行：

```bat
python -m wf.studio --view local
```

*(如果你没有在 `profiles/local.json` 里配置 `views.local`，也可以用命令行直接显式传入基线目录与清单文件，效果完全一样：)*

```bat
python -m wf.studio --store "<物化目录>\production\upload" --manifest "<服务端目录>\assets\asset-patch\manifest.json" --base-version 1.4.54
```

### 预期看到什么

- 命令提示符在几秒内打印类似下面的启动信息，并停在底部持续监听（**不要关闭该窗口**）：
  ```text
  编辑台（草稿可写）: http://127.0.0.1:8790/  视图 1.4.54  ZIP 0 个，额外叠加 0 个
  补丁链清单 ...：找到 0 个 ZIP，缺 0 个
  写入令牌已写到 ...work\studio-drafts\.session.json...
  ```
- 如果你之前在 `第 05 篇` 发过测试包且清单未启用，这里依旧干净地按 `1.4.54` 基线只读打开。

### 不对怎么办

- 打印 `提示：前端未构建（...studio\dist），请在 studio/ 下运行 npm run build`：说明漏做了第 1 步，按 `Ctrl + C` 停掉后端，回第 1 步执行构建后再启动。
- 报 `ValueError: unknown named view: local` 或回退去寻找 `kulo` / `store131` 报错：说明 `profiles/local.json` 里还没有加上 `views.local` 配置段。回到 [04-配置工具.md](04-配置工具.md) 第 3 步补齐 `default_view` 与 `views` 字段，或改用上面第二条带 `--store` 和 `--manifest` 的显式启动命令。
- 报 `ValueError: view manifest does not exist: ...` 或 `ValueError: view store is not a directory: ...`：说明 `profiles/local.json` 里的 `wf_root`、`views.local.store` 或 `views.local.manifest` 路径填错或目录尚未物化。确认 `<物化目录>\production\upload` 与 `<服务端目录>\assets\asset-patch\manifest.json` 在硬盘上真实存在，并检查 JSON 中全部使用了正斜杠 `/`。
- 报端口 `8790` 已被占用：加上 `--port 8791` 换一个本机空闲端口启动（注意：为安全起见，编辑台强制只允许监听 `127.0.0.1` / `localhost` / `::1` 本机回环地址，传局域网 IP 会被直接拒绝）。

## 第 3 步：在浏览器浏览角色、播放像素动画并试存一份草稿（未实测）

编辑台后端每次启动都会在本地生成一次性会话令牌，并在你从本机浏览器访问首页时自动注入页面，防止外部网页越权调用本机接口。

### 做什么

1. 打开电脑上的浏览器，访问：
   <http://127.0.0.1:8790/>
2. **先认清界面布局**：
   - **顶部深色导航栏**：左侧可切换 **`编辑内容`** 与 **`补丁管理`**；右侧有客户端档案选择器、**`工具`**（查版本链与 ID 占用）和 **`词条速查`**（也可随时按快捷键 **`Ctrl + K`** 呼出）。
   - **第二排状态条**：显示 `当前内容：local · 资源版本 1.4.54`，并带有醒目的 **`只写草稿`** 标签。
   - **四大工坊页签**：在 `编辑内容` 下可切换 **`角色工坊`**、**`草稿角色`**、**`BOSS工坊`**、**`武器工坊`**。
3. **只读逛一圈（零风险）**：
   - 在 **`角色工坊`** 里随便点开一个你喜欢的角色；
   - 依次点看角色详情页的 7 个内容页签：**`能力`**（含 `一板` / `二板` / `三板（觉醒）`）、**`技能`**、**`文案`**、**`立绘`**、**`像素`**（可直接在网页里实时播放角色的待机、攻击、技能等全部像素小人动作！）、**`语音`**、**`交接单`**；
   - 点击角色标题右上角的 **`资源`** 按钮，可在右侧抽屉查看该角色关联的全部底层文件路径。
4. **体验草稿箱保存与撤销**：
   - 切回角色的 **`能力`** 页签，尝试点开任意一条词条改一个数值并写入草稿；
   - 点击角色标题右上角的 **`本次修改`** 按钮打开草稿抽屉：你会看到刚才的改动被记录在草稿列表里（对应硬盘上的 `<工具目录>\work\studio-drafts\<角色ID>\`），在这里可以点击保存草稿、生成本地候选交付包，或者点击**撤销**把这条草稿改动删掉，随时回到零改动状态。

### 预期看到什么

- 页面正常加载出完整的中文角色列表、属性星级徽章、立绘头像与像素动画播放器，没有顶部红色的 `后端不可用` 报错。
- 在草稿里做的修改和撤销只改变 `<工具目录>\work\studio-drafts\` 下的文件，你的 `<物化目录>` 和 `<服务端目录>` 分毫未动。

### 不对怎么办

- 点击保存草稿时报 `403` 或提示缺少写入令牌：通常是因为后端重启过，而浏览器还开着重启前的旧标签页。**按 `F5` 刷新一次 `http://127.0.0.1:8790/` 首页**重新获取新令牌即可。
- 在 **`语音`** 页签尝试上传/替换自定义音频时报找不到 `ffmpeg`：只有替换语音转码时才需要安装 `ffmpeg`（安装后确保在 `cmd` 里敲 `ffmpeg -version` 可运行，或设置环境变量 `WF_FFMPEG` 指向 `ffmpeg.exe` 完整路径）。
- 需要同时核对或写出服务端双镜像文案时：启动编辑台时需额外加上 `--server-dir "<服务端目录>"` 参数；注意上游 `startpoint-cn` 默认不含 `<服务端目录>\assets\cdndata\character_text_rank_p5b.json`，若带 `--server-dir` 打开文案页提示缺少该文件，可在该路径新建一个内容仅为 `{}` 的 UTF-8 文件即可。

## 附：当前版本 `python -m wf.studio` 常用启动参数速查

在 `<工具目录>` 运行 `python -m wf.studio --help` 可查看完整参数说明，最常用的实际可用参数如下：

| 参数 | 作用说明 |
|---|---|
| `--view <视图名>` | 使用 `profiles/local.json` 中 `views.<视图名>` 定义的基线与补丁清单（如 `--view local`） |
| `--store <目录>` | 显式指定只读基线 `production/upload` 目录 |
| `--manifest <文件>` | 显式指定补丁链 `manifest.json` 路径（可配合 `--base-version 1.4.54` 与 `--zip-dir`） |
| `--base-version <版本>` | 指定基线 `store` 对应的版本号（国服官方基线填 `1.4.54`） |
| `--tip <版本>` | 只叠加到清单中的指定版本为止（默认叠到清单最新启用版本） |
| `--zip-dir <目录>` | 查找补丁 ZIP 的目录（可重复传入多个） |
| `--extra-zip <ZIP路径>` | 在清单链之后额外按顺序叠加单个测试补丁 ZIP（可重复传入） |
| `--extra-zips-file <TXT>` | 按文本文件（每行一个 ZIP 路径）批量叠加测试补丁 ZIP |
| `--server-dir <目录>` | 传入只读 `<服务端目录>` 供文案编辑对照服务端镜像表 |
| `--provides <JSON>` | 生成本地交付包时默认使用的客户端能力清单（`python -m wf apk provides` 的输出） |
| `--port <端口号>` | 修改本机监听端口（默认 `8790`） |
| `--warm` / `--no-prewarm` | `--warm` 在启动时同步预加载角色列表；`--no-prewarm` 关闭后台词条/文案缓存预热 |
