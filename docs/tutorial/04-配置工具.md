# 04｜配置工具

走完前两篇后，你的电脑上应该已经有了能正常启动的 `<服务端目录>`（含校验通过的 `.cdn\cn` 官方 `1.4.54` 数据包），安卓模拟器或手机也已经能登录进游戏主页。

本篇做三件事：
1. 把服务端 `.cdn\cn` 里的压缩包解包成一份本机可读写的 **`store` 数据包目录**（`<物化目录>`）；
2. 创建本机路径配置文件 **`profiles/local.json`**，告诉所有工具你的服务端和数据包放在哪；
3. 运行只读自检脚本 **`wf_selftest.py`**，确认 20 项环境检查通过。

---

## 为什么需要先准备一份 `store` 数据包？

服务端 `.cdn\cn` 下面放的是几百个分段压缩包（`.zip`），工具不能直接在零散的压缩包里改某一张表。因此我们需要先生成一份平铺展开的 **`store` 目录**（目录末尾是 `production\upload`，里面有 `00` 到 `ff` 共 256 个十六进制子目录和上万个数据文件）。

准备 `store` 有两种方式：
- **方式 A（强烈推荐）**：直接用本仓库自带的 `wf_store_materialize.py` 从 `<服务端目录>\.cdn\cn` 一键物化生成，无需从模拟器往外导文件。
- **方式 B（备选）**：直接指向本机安卓模拟器共享目录里已经下载完的 `WorldFlipper\dummy\download\production\upload` 文件夹。

下面以最稳妥的**方式 A** 为主线讲解（方式 B 附在第 2 步末尾供备查）。

---

## 第 1 步：预演从本地 CDN 物化 `store`（只读不写盘）

先做一次不加 `--apply` 的空跑预演，确认工具能完整读通 `<服务端目录>\.cdn\cn` 的版本链。

### 做什么

1. 用文件资源管理器打开 `<工具目录>`，点击顶部路径地址栏输入 `cmd` 并回车，打开命令提示符。
2. 选定一个**尚未创建**（或完全为空）的路径作为 `<物化目录>`（推荐填 `<工作目录>\wf-store`，**不要**提前往里面放任何文件，也不要放进 `<服务端目录>` 或 `<工具目录>` 内部）。
3. 在 `<工具目录>` 的命令提示符中运行下面的预演命令（把 `<服务端目录>` 和 `<物化目录>` 替换成你的真实路径）：

```bat
python wf_store_materialize.py --cdn "<服务端目录>\.cdn\cn" --server-dir "<服务端目录>" --dest "<物化目录>"
```

### 预期看到什么

- 几秒到十几秒后，窗口打印一行 `[plan]` 摘要和一行 JSON，其中 `tail` 为 `1.4.54`，`"ok":true`，且 `rejected=0`：
  ```text
  [plan] tail=1.4.54 edges=... files=... bytes=... rejected=0
  {"ok":true,"tail":"1.4.54",...}
  ```
- 因为没有加 `--apply`，此时硬盘上还不会写入文件。

### 不对怎么办

- 报 `[ERR] full archive directory is missing`：说明 `--cdn` 指错了层级。必须指向里面直接装有 `archive-common-full` 的那一层（即 `<服务端目录>\.cdn\cn`，而不是上一层的 `.cdn`）。
- 报 `[ERR] destination must be nonexistent or empty`：说明 `<物化目录>` 已经存在且里面有文件。换一个新的空路径（例如 `<工作目录>\wf-store`），不要指向已有项目的文件夹。

---

## 第 2 步：正式执行物化并逐文件校验（未实测）

预演通过后，加上 `--apply --verify` 正式写出 `store` 并逐个校验 CRC 与字节大小（预计占用约 6 GB 磁盘空间，耗时一到数分钟，视硬盘速度而定）。

> **注意**：请**不要**附加旧文档提过的 `--write-profile` 参数——该旧参数会在仓库根目录生成已废弃的 `profiles.json`，触发配置冲突告警。我们在第 3 步统一填写现行标准配置 `profiles/local.json`。

### 做什么

在 `<工具目录>` 的命令提示符中运行：

```bat
python wf_store_materialize.py --cdn "<服务端目录>\.cdn\cn" --server-dir "<服务端目录>" --dest "<物化目录>" --apply --verify
```

### 预期看到什么

- 窗口依次打印 `[plan] ...`、`[verify] files=...`，最后一行 JSON 包含 `"ok":true`。
- 打开 `<物化目录>\production\upload`，能看到 `00`、`01` …… `ff` 等两位数十六进制子文件夹。

### 不对怎么办

- 中途报磁盘空间不足（`No space left on device` / `WinError 112`）：清理分区空间后，**先把写了一半的 `<物化目录>` 整个删干净**，再重跑本步命令。
- 报 CRC 或压缩包损坏（`BadZipFile`）：说明 `<服务端目录>\.cdn\cn` 里某个 `.zip` 拷贝损坏，回到 [02-部署服务端.md](02-部署服务端.md) 第 5 步重跑校验定位损坏文件。

> **备选方式 B（不跑物化，直接用模拟器现成数据包）**：
> 如果你的电脑磁盘空间紧张，且本机模拟器已在第 03 篇进游戏把资源全部下载完毕，也可以在模拟器的共享数据目录里找到 `WorldFlipper\dummy\download\production\upload`（点进去同样应看到 `00`～`ff` 子目录），在下一步把 `store` 直接填成这个 `upload` 目录的完整路径即可。但手机真机无法直接让电脑读写内部目录，真机用户请一律用上面的方式 A。

## 第 3 步：创建并填写 `profiles/local.json`

本仓库**不会**在你的硬盘上盲猜或全盘搜索目录，所有工具统一按以下优先级读取本机路径：

**环境变量（如 `WF_STORE`、`WF_SERVER`） > `profiles/local.json` > 未配置直接报错**

日常使用只需把示例文件 `profiles/example.json` 复制成 `profiles/local.json` 填好一次即可。`profiles/local.json` 已被 `.gitignore` 忽略，不会误传到公开仓库（完整字段说明见 [`profiles/README.md`](../../profiles/README.md)）。

### 做什么

1. 在 `<工具目录>` 的命令提示符中，把示例配置复制为 `profiles\local.json`：

```bat
copy profiles\example.json profiles\local.json
```

2. 用记事本打开它：

```bat
notepad profiles\local.json
```

3. 把文件内容**整段替换**为下面这份模板，然后把第一行的 `<工作目录>` 改成你电脑上的真实路径。
   **⚠️ JSON 斜杠防错必读**：JSON 语法里单个反斜杠 `\` 是转义符，直接粘贴 Windows 路径里的 `\` 会报语法错误！**请把路径里所有的反斜杠 `\` 全部改成正斜杠 `/`**（Windows 下 Python 完全支持正斜杠 `/`）。
   *(如果你在第 02 篇和本篇第 2 步起的名字就是 `<工作目录>/startpoint-cn` 和 `<工作目录>/wf-store`，下面除了第一行 `wf_root` 以外都不用改；如果你起了别的文件夹名，请把对应的 `startpoint-cn` 和 `wf-store` 改成你的实际文件夹名。)*

```json
{
  "wf_root": "<工作目录（把路径里的\\全部改成/）>",
  "servers": {
    "local": {
      "root": "startpoint-cn"
    }
  },
  "rehearsal_server": "local",
  "default_view": "local",
  "views": {
    "local": {
      "store": "wf-store/production/upload",
      "manifest": "startpoint-cn/assets/asset-patch/manifest.json",
      "zip_dirs": [
        "startpoint-cn/.cdn/cn/archive-common-diff"
      ],
      "base_version": "1.4.54"
    }
  },
  "paths": {
    "store": "wf-store/production/upload",
    "server": "startpoint-cn",
    "cdn_dir": null,
    "cdndata": null,
    "kulo": null,
    "store131": null,
    "runtimes": null,
    "studio_screenshots": null
  }
}
```

4. 按 `Ctrl + S` 保存并关闭记事本。
5. 在 `<工具目录>` 的命令提示符中运行下面这条只读核验命令，检查 JSON 格式无误且路径已解析到真实目录：

```bat
python -c "import wf.paths as p; print('store =', p.path('store')); print('server =', p.path('server'))"
```

### 预期看到什么

- 命令正常打印出两行完整路径，没有任何 `Warning` 或 `Error`：
  - `store = <物化目录>\production\upload`
  - `server = <服务端目录>`

### 不对怎么办

- 报 `json.decoder.JSONDecodeError: Invalid \escape`：说明 `profiles/local.json` 里混入了单个反斜杠 `\`，或者漏掉了双引号、多删了逗号。重新打开 `profiles/local.json`，把所有 `\` 改成 `/`。
- 看到 `UserWarning: profiles.json is deprecated; migrate to profiles/local.json` 或报新旧配置冲突：说明 `<工具目录>` 根目录下存在旧版遗留的 `profiles.json`，或者系统里设过旧环境变量 `WF_TARGET_STORE` / `WF_SERVER_DIR`。删掉根目录下的 `profiles.json`（保留 `profiles\local.json`）并清除旧环境变量即可。

## 第 4 步：运行 20 项只读环境自检（未实测）

`wf_selftest.py` 会在**不修改任何一字节游戏文件**的前提下，帮你把 Python 版本、路径表文件、表读写往返一致性和服务端 CDN 目录全部体检一遍。

### 做什么

在 `<工具目录>` 的命令提示符中运行：

```bat
python wf_selftest.py
```

*(提示：默认不加参数是纯只读 + 空跑模拟，随时随便跑；若想额外测试一次「金丝雀真实写入后立即字节级复原」闭环，可加 `--deep` 运行 `python wf_selftest.py --deep`。)*

### 预期看到什么

- 窗口逐项打印 `[1/20]` 到 `[20/20]` 的检查结果，各项为 `PASS`（部分非必填扩展项显示 `WARN` 属正常提示，不影响使用），最底部汇总显示 **`0 项失败`**，命令退出码为 `0`。

### 不对怎么办

- `[3/20]` 报 `未找到数据包 store` 或找不到哈希文件：检查 `profiles/local.json` 里的 `paths.store` 是否指到了 `production/upload` 这一层（常见错误是少写了两层，只填到了 `<物化目录>`；正确结尾必须是 `.../production/upload`）。
- `[13/20]` 或 `[14/20]` 报找不到服务端 `cdndata` 或 `.cdn/cn/archive-common-diff`：检查 `paths.server` 是否指到了 `<服务端目录>` 根目录（底下应直接有 `assets\cdndata\character.json` 和 `.cdn\cn\archive-common-diff`）。
- 遇到其他报错项：直接对照 [07-报错对照表.md](07-报错对照表.md) 逐条解决。
