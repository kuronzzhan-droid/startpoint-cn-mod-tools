# 增强开关(GUI「增强开关」页签 / wf_enhancement_switch.py)

一句话:**在「官方原版」与「已冻结的增强态」之间逐格取值**。开 = 用增强值,关 = 回官方原值。

面向自服运维:想只关掉某一类增强(比如把解除主位限制收回去,或把 boss 血量放回官方),
或者整体切回官方原版再切回来,而**不碰**三个自制角色、15 把深渊武器和 700099 模式。

---

## 1. 为什么不是「重跑平衡套件」

`wf_balance_suite --apply` 第一件事是把 6 张表从 `.bak-wfmod-balance-20260709-*` 等
锁定基准整文件覆盖回去。那份基准早于三自制角色与深渊武器:

| 表 | live | 套件锁定基准 | 差额里是什么 |
|---|---|---|---|
| ability | 375 595 B | 311 219 B | 赛瑞斯/史黛拉/杰拉德的词条行、C7050/U0000 修复 |
| ability_soul | 42 638 B | 38 313 B | `wf_rogue_rewards` 写的 8000101-8000115 |
| leader_ability | 83 613 B | 52 187 B | 自制角色队长技 |

**任何按钮只要落到 `--apply`,就等于把 20 天的角色/武器工作静默回滚。** 而且那份基准
本身已带一轮增强(ability 2652 行 vs 官方 2972 行),"全关"也回不到官方。

所以本引擎**不重算、不 import、不 subprocess 平衡套件**,只在三份字节之间取值:

| 名 | 来源 |
|---|---|
| `official` | `wf_enhancement_policy.OfficialBaseline` —— 官方 CDN 归档,唯一 ground truth |
| `enhanced` | 增强基线快照,一次性冻结当前 store(`snapshot` 子命令) |
| `live` | store 现字节,只读 + 受控写 |

> 工具箱里的 `balance_suite` 卡片**保持原样**:它仍然是"重建增强内容"的入口,
> 但它和本面板是两件事,别在切过官方之后去按它。

## 2. 地址模型

一张表 = key → 叶子。**一个叶子里可能拼着多行**(换行分隔),每行才是定宽 CSV
(ability 126 列 / leader 124 / soul 123)。所以地址是 `(key, 嵌套路径, 行号, 列号)` 四级:

- 双方都有的行、列数相同 → 逐格比较,**格级**归属
- 只在增强侧 → 追加行,**行级**归属
- 只在官方侧 → 被增强删掉的行 → 关掉该开关时补回
- 行数变少 / 列数对不上 → **整键**二选一(实测只剩 2 个键落到这条,已在 UI 单列)

## 4. 两条护栏 + 两条自检等式

**R1 枚举·哨兵锁行**:兜底桶的差异如果触碰 `kind`/`target`/`trigger_limit`/`string_id`/
`action_path`/`powerflip_override` 等列,该行不允许子勾选拆分(避免拼出「增强的 kind +
官方的强度」这类死行)。**被点名认领的格不受影响**——解除主位限制改的正是 202 这个 kind,
它带取值守卫(只认官方值 202/false),是故意改的。

**R2 子桶跨越锁行**:`power`/`feel`/`gate` 三个子勾选只在"该行的差异全落在同一子桶"时独立生效。
平衡套件的补偿对(层强度写 `strength`、压缩后的层数写 `trigger_limit`)必然跨桶,会自动升格为整行。
实测 R1 1804 行、R2 256 行,面板常驻显示这两个数——**把限制说出来,而不是假装可以随便勾**。

**E1 / E2**:每次 plan 都跑
- E1:全部关 → 官方 key 逐行等于 official
- E2:全部开 → 官方 key 逐行等于 enhanced

任一不成立说明归属表有洞(有地址没人认领或被重复认领),**拒绝写盘**。实测真实 store 两条都成立。

## 5. 安全性

- **自制内容永不进 diff**:只遍历官方 key,自制角色/武器/模式行原样保留。
  实测切回官方后:三自制角色在场、15 把深渊武器魂珠 15/15 在场。
- **官方 key 不做内容识别**:官方基准里有的 key 天然是官方的。
  (否则商店官方商品 `700099` 会被"模式 id"的模式匹配吃掉。)
- **第三方改动 fail-safe**:某格既不等于官方也不等于增强 = 快照之后有人手改过,
  默认**保留现值**并在预览里列出;要覆盖得显式 `--allow-foreign`。
- **没点到的开关保持现状**:CLI 的基准向量取自 store 实测态,不是 spec 默认值
  ——`--off char.main_position` 只动这一项。
- **pre-image 回滚**:每次 apply 先把要动的表全量备份到
  `work/enhancement-switch/preimages/<id>/`,失败自动回滚,事后可 `rollback --preimage <id>`。
  实测 apply → rollback 后与原 store 逐字节一致。
- **两项需要联动的开关在 GUI 里只读**,必须走 CLI 显式加开关:
  - `char.white_tiger`:客户端 4★ 配服务端 5★ 会撞 `characterExpCaps` 越界,
    要同时改 `assets/character.json` 与 `assets/cdndata/character.json` 并钳存档 → `--allow-white-tiger`
  - `other.shop_700099`:补回客户端行还要同步 `assets/event_item_shop.json` 与 id_map,
    否则商品可见但购买必失败 → `--allow-shop`
- **`other.treasure_2001` 不进任何一键预设**:深渊武器商品文案宣传了这个玩法。
- **`weapon.wab` 默认关**:store 是增强态,但 CDN 链上已经是官方值(1.4.106 还原过)——
  开着并发布会把超模值重新推上线。

## 6. 用法

GUI:工具箱旁边的**增强开关**页签。第一次进要建官方基准索引(要打开官方全量包),
几十秒到几分钟,之后有缓存。勾完点**预览**看逐表影响,再点**写入 store**。
一键按钮**只改复选框**,不写盘。

```bash
python mod-tools/wf_enhancement_switch.py snapshot --tag base   # 冻结增强基线(只做一次)
python mod-tools/wf_enhancement_switch.py status                # 逐开关看现状
python mod-tools/wf_enhancement_switch.py plan --off char.main_position
python mod-tools/wf_enhancement_switch.py apply --preset official --scope character
python mod-tools/wf_enhancement_switch.py rollback --preimage pre-20260729-133401-...
```

**冻结时机很重要**:`snapshot` 把当前 store 当成"增强侧"。必须在**增强还开着**的时候冻,
在部分切回官方之后冻,ON 侧会被永久钉成官方值,此后"启用增强"写的却是官方值。
守卫会挡掉"自制内容行缺失"的 store(那多半是被平衡套件洗过的),但挡不住"已经切过官方"——
这条只能靠你自己看 `status`。

## 7. 写盘之后

面板写的是 **store**,不是 CDN。玩家要吃到还得发布:走既有的发布链
(`wf_publish` / GUI 的待发布徽章)。切回官方发的是一条**前向边**,不是重切旧边,
链语义上是安全的;但发布前请照常跑 `wf_release_guard` / `verify_cdn_chain`。

自动化测试:`mod-tools/tests/test_enhancement_switch.py`(44 例,合成表,不依赖真实 store/.cdn)。
