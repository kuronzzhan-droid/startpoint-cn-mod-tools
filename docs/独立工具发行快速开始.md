# WF Mod Tools 独立发行快速开始

本包是独立工具，不要求放在 `startpoint-cn` 仓库旁边，也不会靠相邻目录猜服务端、CDN、store
或数据库位置。工具使用者仍需合法准备自己的客户端数据、原版 CDN/store 和目标服务端。

## 1. 安装

1. 安装 Python 3.12 或更高版本；
2. 解压 ZIP，保持 `wf-mod-tools/` 内目录结构；
3. 在该目录执行：

```powershell
python -m pip install -r requirements.txt
python -X utf8 -m wf_release_v1 --help
python -X utf8 wf_release_ui.py --help
python -X utf8 wf_preview_2d.py --help
```

不要把真实 `.env`、`profiles.json`、`target.json`、receipt、store、CDN 或数据库复制进工具目录。

## 2. 路径配置

复制 `profiles.example.json` 为工具目录外的私有配置，或使用显式环境变量/CLI 参数。关键路径均应为
绝对路径；显式配置无效时工具会失败关闭，不会回退到某个相邻 checkout。

常用 seam：

- `WF_SERVER_DIR`：服务端根；
- `WF_CDN_DIR`：CN CDN 根；
- `WF_DATABASE_DIR`：数据库根；
- `WF_TARGET_STORE`：客户端 store；
- `WF_APK`：客户端 APK；
- `WF_VOICE_DUMP`：语音资源根；
- `WF_FFMPEG`：ffmpeg 可执行文件。

具体 target v1 结构见 `docs/wf-release-v1-local-install.md` 和
`docs/examples/wf-release-target.windows.json`。

## 3. 发行物闭环

```powershell
# 构建/验证标准发行物
python -X utf8 -m wf_release_v1 build --help
python -X utf8 -m wf_release_v1 verify --help
python -X utf8 -m wf_release_v1 inspect --help

# 旧分享包只读检查与隔离导入
python -X utf8 -m wf_release_v1 inspect-share --help
python -X utf8 -m wf_release_v1 import-share --help
python -X utf8 -m wf_release_v1 adopt-character --help
python -X utf8 -m wf_release_v1 build-overlay --help

# 受管目标只读规划、安装与恢复
python -X utf8 -m wf_release_v1 probe --help
python -X utf8 -m wf_release_v1 plan-install --help
python -X utf8 -m wf_release_v1 install --help
python -X utf8 -m wf_release_v1 rollback --help
```

现代服务端以 capabilities v1 为主路径；旧服务端只在 capabilities 端点精确 404 后进入显式
legacy 候选流程。连接失败、认证失败、5xx、畸形响应和不受支持的现代响应都不会静默降级。

## 4. 编辑与预览

- `wf_gui.py`：传统完整编辑器；
- `wf_release_ui.py`：preparation-only Release 工作台；
- `wf_preview_2d.py`：角色 pixelart / atlas / timeline 只读预览，支持 rotated frame；
- `wf_character_flow.py`：新角色 package 的唯一生产入口；
- `wf_release_v1 import-share`：把已验证旧分享包隔离导入，再进入采纳/编辑/重封流程。

任何真正写 store/CDN/server/device 的动作前，先运行 dry-run/plan/preflight，并确认目标绝对路径。

## 5. 当前边界

- 包内不含本机 profile、target、receipt、WIP、测试、任务书、缓存或真实数据；
- 不自动解决 CDN 同版本冲突：冲突会失败关闭，由作者显式改号或重建链；
- 不提供“分享包=项目”的持久项目管理层；现有隔离导入→编辑→seal 已覆盖主要二次开发闭环；
- 工具级验收不等于真实服务端、CDN、设备或游戏内演出验收；
- schema-aware 高级表单、2D 补间与音频同步属于后续按需增强。

## 6. 包完整性

包根的 `MANIFEST.json` 记录 source commit、工具版本及每个成员的 size/SHA-256。分发时同时提供
外部 `SHA256SUMS.txt`；验收先核对外部 ZIP 摘要，再核对包内 manifest。
