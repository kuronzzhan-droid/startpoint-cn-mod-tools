# 崩溃码速查

本文适合在改包测试中遇到红色报错弹窗、启动卡死或战斗闪退，需要按错误码快速定位坏表与坏资产的新手阅读。弹窗出现错误码后请先不要重启客户端（重启会覆盖上一次日志），直接打开客户端数据目录下的 `Local Store/custom_Release_Android/latest.log` 查看报错堆栈，再按下方编号检索修法。

## 1. `F1009`（空对象引用：DSL 缺根外壳、空分支填错或队长技零先例描述）

- **现象**：打开技能预览、进战斗加载脚本或点开角色详情面板时立刻崩 `F1009`。
- **原因**：常见于四处空引用：技能 DSL 根节点写成了裸 `["Block", ...]` 缺 11 参数 `ActionDsl` 外壳；`If / Conditionals*` 的空分支写成了命令 `["DoNothing"]` 而非表达式 `["Block", []]`；`Rectangle` 少写了第 3 参圆角；或在 `leader_ability` 放入了无队长技自动描述模板的触发器。
- **怎么做**：补齐 `ActionDsl` 11 参根外壳（可用 `python wf_dsl_root_fix.py --store <数据包upload目录> --apply`），把分支顶层 `DoNothing` 改为 `["Block", []]`，补齐 `Rectangle` 3 参数，无先例队长技词条移回 `ability` 表或配覆写文案。
- **怎么验证**：对脚本运行 `python -m wf check dsl <树文件.json>`、对词条运行 `python -m wf check text <快照.json>`。预期两项检查均通过，重进预览与详情页不弹 `F1009`。

## 2. `F1034`（类型转换失败：编码误传包装字典或等级数组槽填了单值）

- **现象**：进入战斗读取技能或命中敌人瞬间闪退报 `F1034`。
- **原因**：把 `wf_dsl.parse_dsl` 返回的 `{"tree": ..., "numbers": ...}` 整个字典直接传给了 `encode_amf3`（应只传 `parsed["tree"]`）；或者在要求技能等级数组的槽位（如 `Sector` 第 2 参开角、3 参数 `AC*` 状态第 3 参成长数组）里填了单个数字或布尔值 `false`。
- **怎么做**：重新用 `parsed["tree"]` 编码脚本；对照 `python wf_dsl_sig.py` 把单值参数补齐为对应长度的等级数组。
- **怎么验证**：运行 `python -m wf check dsl <树文件.json>`。预期签名与类型校验零错误，进练习场释放技能不闪退。

## 3. `F1125`（数组越界：`.parts` 特效片段超总长或贴图池容量不足）

- **现象**：自定义战斗特效播放到中后段或同屏粒子最多时闪退报 `F1125`。
- **原因**：`.parts` 图层片段的 `起始帧 + 持续帧` 超过了动画总帧数，或者头部 `a` 字段（`imageMaxNumbers` 贴图对象池上限）小于同帧并发切片数。
- **怎么做**：对齐图层总长与 `.timeline` 结束帧，并调大 `imageMaxNumbers` 使其不小于同屏最大并发切片峰值。
- **怎么验证**：运行 `python wf_flatomo_capacity.py` 检查特效文件。预期无越界与容量不足告警，进图完整播完特效不崩。

## 4. `C2301` / `C2308`（魂珠副本限制冲突 / 常驻词条叠层状态冲突）

- **现象**：装备武器魂珠进编队报 `C2301`，或者角色带新被动进图瞬间报 `C2308`。
- **原因**：武器本体强化逻辑固定无副本种类限制，给配套魂珠单独填了副本限制就会抛 `C2301`（若缺客户端深渊门控补丁还会导致限制武器全模式常驻生效）；常驻 `during` 模式行误填了 `Initial` 初始叠层标记，或同一能力键内把最优叠层直击计数与连击触发器混在一起则会抛 `C2308`。
- **怎么做**：保持魂珠与武器本体的副本限制一致且核对客户端门控补丁；去掉 `during` 行上的初始叠层标记，冲突触发器拆到不同能力槽。
- **怎么验证**：运行 `python -m wf check text <快照.json>`，预期无 `during` 契约告警，带装备与角色进图正常开战。

## 5. `C4208` / `C8004`（道具图标填 `(None)` / 同步纹理未进图集）

- **现象**：打开商店、背包或抽卡界面报错 `C4208` 或 `C8004`（`<路径>` 的纹理尚未加载）。
- **原因**：`item` 表第 4 列填 `(None)` 必崩 `C4208`；填单张散装 PNG 路径（或先发了 `item` 表行却还没下发对应图集、又或试图仅靠 CDN 替换封在 APK 内置包里的 `battle/common/layer1`）会让同步取纹理接口查不到已驻留子纹理而崩 `C8004`。
- **怎么做**：道具小图标打进 `item_icon/sprite_sheet`（抽卡券大图进 `item/sprite_sheet`），确保图集先于或随表行一同下发；内置战斗图集走底包更新。
- **怎么验证**：进游戏打开领主币商店与道具详情弹窗。预期图标正常渲染且不弹 `C4208 / C8004`。

## 6. `C7050` / `C7101`（表枚举构造不存在 `parseAtN` / 布尔列解析失败）

- **现象**：启动读表或点开角色时崩 `C7050`（日志含 `parseAtN`，`N` 即 0 起算列号）或 `C7101`。
- **原因**：`C7050` 常见于枚举列留空串 `""` 而非 `(None)`、前置条件（`8 / 9 / 87 / 144 / 187 / 188 / 200 / 205`）后一列主体留空、`during` 行冷却列 `c85` 未填 `(None)`、可玩角色属性填了 `6`（无属性）、跨表错放仅 `ability` 支持的 `kind 724`，或客户端未打对应扩展词条补丁。`C7101` 则是布尔列（`ability c72`、`leader_ability c70`、`general_boss c36`）留空或填了非 `true / false` 字符串。
- **怎么做**：按 `parseAtN` 指出的列号补上 `(None)`、主体枚举或合法 `true / false`；用扩展词条时核对客户端 `provides.json`。
- **怎么验证**：运行 `python -m wf check text <快照.json>` 与 `python -m wf check compat --requires <requires.json> --provides <provides.json>`。预期 0 错误，重启客户端顺利进主城。

## 7. `C7051`（CDN 表与客户端内置 `*_iosbundled` 表键重复）

- **现象**：热更完成后停在启动加载页直接崩 `C7051`。
- **原因**：下发的 CDN `orderedmap` 中包含了客户端内置 `bundle.zip` 同名 `*_iosbundled` 表里已有的键，合并器检测到重复键直接拒绝加载。
- **怎么做**：从 CDN 变更集中删掉与内置表重名的键；确需改内置键时重打客户端底包。
- **怎么验证**：发包前运行 `python -m wf.studio.draft bundle-check`。预期输出 0 处撞键，启动客户端正常过标题页。

## 8. `C8013` / `C8037` / `C8016`（前导预载漏登记 / 时间轴数据尚未加载）

- **现象**：进图读条快结束或战斗中某招式出手瞬间崩 `C8013`、`C8037` 或 `C8016`。
- **原因**：`C8013 / C8037` 是召唤物 `general_funnel` 或即时道具脚本未在进图前导预载表注册；`C8016` 则是战斗中用到了未预载的 `.timeline`——典型如 Boss 或召唤怪打出了非关卡 `c69` 推荐属性的固定属性攻击、补丁 `102` 转能力伤害但全队无原生能力伤词条预载 `total_ability_damage_effect`，或角色像素 `.timeline` 缺齐 9 个标准动作标签。
- **怎么做**：补齐 `general_funnel` 注册；跨属性攻击关卡塞入对应属性占位哑元怪触发预载；用 `102` 转换码时给角色配一条原生能力伤词条；保齐角色 9 个动作标签。
- **怎么验证**：运行 `python -m wf check boss <副本ID>` 与 `python -m wf.studio.draft pixel-analyze --character <角色ID>`，进图实测跨属性招式与伤害触发不崩。

## 9. `C8100`（「数据不足」下载死循环）与 `C8105`（PNG 大写魔数错误）

- **现象**：进图反复弹窗「数据不足」无法开战（`C8100`），或刚加载图片就报 `C8105`。
- **原因**：`C8100` 是表里引用的脚本、语音、图标未打进补丁，或 `general_boss` 空动作列（如 `c109`）误填了 `(None)` 而非空串 `""`，又或战斗特效精灵表未按 `<目录>/<目录名>.png` 命名。`C8105` 则是塞入了标准大写 `PNG` 头图片，未转成存储态小写 `\x89png` 头。
- **怎么做**：补齐缺失资产，把 `general_boss` 空动作槽改回 `""`，对齐特效目录与精灵表同名；所有 PNG 用工作台或 `wf_assets.py` 写入小写魔数头。
- **怎么验证**：运行 `python -m wf.studio.draft save` 与 `python -m wf check <delivery-manifest.json>`。预期引用完整且魔数合规，进图一遍读条通过。

## 10. `C8251` / `C10000` / `C14102`（多波次缺门动画 / 地形边界或跳点锚点缺失）

- **现象**：多波次副本进图崩 `C8251`，加载地形崩 `C10000`，或移植 Boss 瞬移时崩 `C14102`。
- **原因**：两波及以上关卡所用的 `field` 行第 7、8 列缺过场门与过渡舱动画报 `C8251`；单层地形缺或重复定义了 `BOUNDS / WALL` 报 `C10000`；Boss 位移脚本查找的 `CUSTOM_POSITION` 锚点在当前地形不存在报 `C14102`。
- **怎么做**：多波次换用带门动画的 `field`；每波次层保证唯一合法边界；移植带位移的 Boss 时把原地形对应的 `CUSTOM_POSITION` 一并拷入目标地形。
- **怎么验证**：运行 `python -m wf check boss <副本ID>`。预期地形与锚点校验全绿，进图打通全波次与位移招式不崩。

## 11. `C8601`（指定的 Key 不存在，界面常提示「部分资源文件已损坏」）

- **现象**：进主城、点玛纳板、开商店、进领主大地图或进战斗时弹窗提示「部分资源文件已损坏」，日志记录 `C8601`。
- **原因**：外键查表落空：`kind 629` 漏配 `custom_ability_string` 同名键；领主节点 `c6` 漏配 `boss_coin_shop_category`；商店漏配 `boss_coin_shop`；音乐漏配 `bgm_asset`；语音漏配 `character_speech`；`ability c2` 雕像组或 `character c26` 定位填了官方枚举外的自造词；或者整表发布误删了线上已有键。
- **怎么做**：对照 `latest.log` 里紧挨着 `C8601` 上方的表名补齐缺失外键，修正枚举列，并用 `key-diff` 追回误删键后发新版本正向修复包。
- **怎么验证**：运行 `python -m wf check text <快照.json>`、`python -m wf check boss <副本ID>` 及 `python wf_publish_guard.py`。预期外键与键集合零缺失，重进对应界面不再报错。

## 12. `C10109` / `C14510` / `C14555` / `C16102` / `C16103`（词条与脚本运行契约错误）

- **现象**：进战斗初始化或放技能时分别弹出 `C10109`、`C14510`、`C14555`、`C16102` 或 `C16103`。
- **原因**：`C10109` 是把战斗切换属性 `kind 720` 错放进了 `During` 常驻模式（只能放 `Instant`）；`C14510` 是 `kind 629` 所在槽的 `character c36`（`max_ability_powers`）填了 `1` 导致插值除零；`C14555` 是 `StartModifierField` 场地效果数组塞了超过 1 项；`C16102` 是 `CreateCondition` 第 10 槽实体类型（角色/敌人 `3`、弹珠 `2`）与主体不符；`C16103` 是引用了未绑定的正整数主体或把 `MoveHitArea` 写在了 `CreateHitArea` 第 20 槽外部。
- **怎么做**：`720` 改 `Instant`；`629` 槽的 `max_ability_powers` 改 `6`；`StartModifierField` 数组只留 1 项；对齐 `CreateCondition` 类型码 `2 / 3`；补齐主体绑定并把 `MoveHitArea` 移入 `CreateHitArea` 第 20 槽。
- **怎么验证**：运行 `python -m wf check text <快照.json>` 与 `python -m wf check dsl <树文件.json>`。预期全部契约检查通过，进图触发技能正常生效。

## 13. `U_1d93f4`（战斗 `layer0` `4096×4096` 图集装箱溢出）

- **现象**：单机正常，一进三人协力或换阶段加载就闪退，日志报 `U_1d93f4`（`MaxRectsPacker size exceeded`）。
- **原因**：同房全部参战角色的像素图集与战斗特效合并打包进 `4096×4096` 的 `layer0` 时超出面积上限。
- **怎么做**：裁掉精灵表右下纯透明废边，运行 `python wf_battle_atlas_repack.py` 去重紧缩图集。
- **怎么验证**：运行 `python wf_atlas_budget_check.py --pack <角色包目录>`。预期高压协力场景占用率达标且返回码为 0。

## 14. `U_4f5401` / `U_f6da5a` / `U_ac0726` / `U_50fc52` / `U_3be147`（内部未捕获断言崩溃）

- **现象**：战斗中途或进图黑屏直接强退，日志记录 `U_` 开头的内部崩溃哈希。
- **原因**：`U_4f5401` 是在弹珠（`-18`）、敌人或队友主体上用了未实现的 `CD` 坐标系；`U_f6da5a` 是含 `ACUnique` 的单条 `CreateCondition` 状态总数超过 2 个；`U_ac0726` 是 `SpawnFunnel` 分组号超出 `1..10` 或敌方脚本误调 `HideCharacter`；`U_50fc52` 与 `U_3be147` 则是主怪、分身变量表、小怪或召唤物在关卡指定的 `c95` 等级 `N` 上缺了等级表行。
- **怎么做**：弹珠朝向改用 `EF`、受击目标改用 `AB / GH`；拆分含 `ACUnique` 的 `CreateCondition`；限制浮游炮组号在 `1..10` 并删掉敌方 `HideCharacter`；补齐参战全怪物在目标等级 `N` 的等级定义行。
- **怎么验证**：脚本跑 `python -m wf check dsl <树文件.json>`，关卡跑 `python -m wf check boss <副本ID>`（肉鸽加跑 `python wf_rogue_validate.py`）。预期零告警，进图实测全程稳定通关。
