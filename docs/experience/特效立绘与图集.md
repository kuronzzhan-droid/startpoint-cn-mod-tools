# 特效立绘与图集

本文适合需要替换角色立绘、派生十件套 UI 图标、制作像素小人动画或拼装战斗技能特效的改包新手阅读。如果遇到三人协力爆图集闪退、图片报文件头错误、立绘上下移位或特效进图隐形，可以按本文核对资源混淆规范与图集预算。

## 1. 三人协力战斗图集 `layer0` 撑爆 `4096×4096` 上限（`U_1d93f4`）

- **现象**：新角色单人进练习场一切正常，一进三人协力房间或 Boss 换阶段重载就闪退报 `U_1d93f4`（`size exceeded`）。
- **原因**：战斗开始时客户端会把全房最多 18 名主副位角色的像素精灵表、强化弹射特效与技能特效动态拼进同一张 `4096×4096` 的 `layer0` 大图集（`full_shot` 立绘和 `skill_cutin` 不进 `layer0`；原版不预载 `special_sprite_sheet`，但在带双形态能力的补丁客户端中 ★4 及以上主位角色会把 `special` 一并装入 `layer0`）。如果精灵表右下角留了大块纯透明废边或重复帧未去重，多人叠加就会塞不下。
- **怎么做**：裁掉精灵表右侧和底部的纯透明空白（只改小 PNG 画布宽高，左上角原点不变，无需重算 `.atlas` 坐标），并对重复帧做图集去重重排。
- **怎么验证**：发包前运行 `python wf_atlas_budget_check.py --pack <角色包目录>`（或 `--ids <角色ID>`）。预期看到各协力高压场景占用率低于阈值且退出码为 0；若超标，运行 `python wf_battle_atlas_repack.py` 紧缩图集后重测。

## 2. CDN 资产未做魔数混淆或音频编码违规（`C8105` / 语音无声）

- **现象**：替换图片后进图立刻报错 `C8105`，解包二进制失败，或者角色新语音放不出声音、播到一半截断。
- **原因**：游戏数据目录中的资产带有固定混淆与压缩要求：PNG 文件头第 2..4 字节必须是小写 `png`（十六进制 `89 70 6e 67`），直接放标准大写 `PNG` 必崩 `C8105`；`.amf3.deflate` 与 `.atf.deflate` 必须用无头部裸压缩（`wbits = -15`）；角色语音 MP3 必须是 44.1kHz 单声道恒定码率 CBR（官方标准为 96kbps，切勿用 112kbps——客户端帧长表在该档位写的是 `122000`，会算错步进解不动），且每个音频帧头首字节需做 `0xFF ↔ 0x7F` 翻转。
- **怎么做**：不要手动改后缀直塞原文件，统一通过工作台 `python -m wf.studio` 或 `wf_assets.py` 转换写入。
- **怎么验证**：执行 `python -m wf.studio.draft save` 做草稿落盘自检。预期所有资产头校验通过；进图点开图鉴立绘与语音列表逐条试听，确认画面正常、音频完整播完。

## 3. 立绘双槽规则、透明底硬要求、`skill_cutin` 漏转 ATF 与 `faceY` 反向位移

- **现象**：换了 `skill_cutin` 的 PNG 在手机上放技能还是旧图，立绘整块白底把战斗场地挡得严严实实，或者把 `faceY` 调大想让立绘往下移结果反而往上跑了。
- **原因**：每个角色只有 `_0`（初始）和 `_1`（觉醒）两套立绘槽。`full_shot_1440_1920` 和 `skill_cutin` 必须是透明底抠图（保留人物与脚边小景物，绝不能留满幅矩形背景）；而真机渲染 `skill_cutin` 只读 `android` 层的 `.atf.deflate` 纹理，根本不读同名 PNG。位置由 `character_image`、`trimmed_image`、`full_shot_image_attribute`（格式 `1000,1000,1,faceX,faceY`）三表控制，其中 `faceY` 是脸部锚点坐标——数值改小立绘往下走，数值改大立绘往上提；且画布刚好 `1440×1920` 时纵向偏移会被客户端边缘钳制。
- **怎么做**：立绘与特写一律抠成透明底；改完 `skill_cutin` 的 PNG 后运行 `python wf_atf.py --regen <逻辑路径>` 同步重编 ATF；想把立绘往下挪时减小 `faceY`。
- **怎么验证**：运行 `python -m wf.studio.draft portrait-info --character <角色ID>` 核对双槽尺寸与锚点，进游戏真机或模拟器放一次主动技能，确认新特写正常弹出且不遮挡背景场地。

## 4. 白底立绘抠图误用宽带去白边，导致深色底泛灰圈或吃掉浅色花瓣

- **现象**：白底原画抠完放进深色角色详情页，轮廓外围浮着一圈脏灰雾，或者白色的花瓣、星星、高光被掏空成半透明破洞。
- **原因**：对整圈轮廓做宽带反混白或自动清理小孤岛，会把原本就是浅色的前景道具误判成半透明背景吃掉；而原画白纸边缘常带微弱纸面灰点，单纯卡死纯白又会留白刺。
- **怎么做**：使用 `python wf_portrait_white_matte.py --source <白底原画.png> --out <透明母图.png>` 处理：只删与画面四边连通的纯白背景、仅对紧贴背景的 2 像素窄带做抗锯齿反解；被身体围住的封闭白洞通过配置 `remove_seeds` 点名扣除，白花瓣等极浅色道具圈进 `protect_regions` 保护。
- **怎么验证**：运行 `python wf_portrait_white_matte.py --audit --source <白底原画.png> --master <透明母图.png>`。预期前景误删像素为 0；把母图分别叠在纯黑底和纯白底上肉眼检查，确认既无白麻点也无前景破洞。

## 5. UI 十件套图标漏套异形蒙版、透明无底或宽扁像素怪被等级条挡脸

- **现象**：编队底栏的六边形或水滴形头像变成了一块突兀的方砖，角色缩在空框里发虚，或者宽扁体型的像素 Boss 转可玩角色后主卡只看得见肚子、脸被挡住。
- **原因**：除 `skill_cutin` 外，其余 10 张角色 UI 图标都必须是有底色的不透明图，且圆形、六边形（`battle_control_board`）、水滴条（`cutin_skill_chain`）、圆角方各自套有固定的官方 alpha 形状蒙版；四张 `square*` 同比例图还必须保持同一构图缩放。对于横向宽扁的像素 Boss，编队主卡（`thumb_party_main`）底部约 1/3 会被等级数字和副位小头像盖住，整只居中塞入必被挡脸。
- **怎么做**：在工作台用 `python -m wf.studio.draft portrait` 按头顶/脸宽模板与官方众数蒙版一键派生全套图标；宽扁像素角色改用脸部优先的特写裁切框，把主体提上半区。
- **怎么验证**：调用 `wf_ui_derive_gate.py` 检查尺寸、蒙版越界与不透明度覆盖率包络，预期全部合格；进游戏打开编队主卡与战斗操作板，确认异形切角干净、脸部完整露在等级条上方。

## 6. 像素小人（`FrameAnimation`）跳号错帧、Boss 体型霸屏或瞬移闪现

- **现象**：像素动画缺号区间播出了下一张动作图，大体型 Boss 转可玩角色进图比半个屏幕还大，原地瞬移走路时残影乱跳，或者进图崩 `C8016`。
- **原因**：`.atlas` 里的帧编号 `N` 代表该切片覆盖的**结束帧号**（区间为 `上一编号+1 .. N`），所以中间跳号时显示的是后一条 `N` 的画面，而不是延续前一张。玩家渲染器 `MemberView` 会把每帧 `scale` 强行覆写为 `6`，只改表放大系数拦不住巨型 Boss 霸屏；靠场地锚点跳点的 Boss 改成原地走路时中间缺全透明过渡帧就会闪现；且角色 `.timeline` 缺齐 9 个标准动作标签会崩 `C8016`。（骨架 `.parts` Boss 转可玩同理，需离线烘焙成 `1/k` 像素帧序列四件套。）
- **怎么做**：核对结束帧号语义排布帧表；大体型 Boss 先把单帧像素图实际缩采样到 `1/k` 再重新打包图集；瞬移收招与现身之间垫入全透明帧，保齐 9 个标准时间轴标签。
- **怎么验证**：运行 `python -m wf.studio.draft pixel-analyze --character <角色ID>` 并在工作台 L1 像素预览逐动作回放。预期无坑位告警、体型与常规角色相当、动作切换无错帧。

## 7. 战斗特效（`PartsAnimation`）精灵表文件名与目录不同名（`C8100`）或三段路径隐形

- **现象**：引用特效后进图无限卡在「数据不足」弹窗（`C8100`），或者进图不报错但技能放出来一片空气、完全看不见特效。
- **原因**：客户端预载战斗特效时，固定按特效所在目录名去拼 `<目录>/<目录名>.png` 和 `<目录>/<目录名>.atlas`（跨角色目录引用完全合法，只要目录名与精灵表文件名一致即可）；名字对不上就会下载死循环。同时 `.parts` 内部引用的图集切片名固定为 `.gen/<parts文件名无后缀>/<帧号>` 两段路径，多套一层子目录写成三段路径会导致查不到贴图而全程隐形。
- **怎么做**：把特效目录下的 `.png` 和 `.atlas` 严格改名为与父目录同名；把 `.atlas` 与 `.parts` 里的切片键统一改成 `.gen/<stem>/<帧号>` 两段式。
- **怎么验证**：核对目录与文件名一致、`.atlas` 切片键为两段式后进练习场释放技能。预期加载不卡「数据不足」且特效画面完整渲染。

## 8. `.parts` 4096 定点矩阵未居中、黑底色带直出或误删同目录共用帧

- **现象**：自制特效偏到角色右下角、套着一层纯黑方块底、圆环中间实心发白，或者改完 A 技能特效后同目录的 B 技能特效突然缺块闪烁。
- **原因**：`.parts` 矩阵缩放采用 `4096 = 1.0` 定点数，贴图原点在左上角；宽高 `W × H` 的切片要居中对齐锚点，平移必须设为 `x = -(W / 2) * (a / 4096)`、`y = -(H / 2) * (d / 4096)`，且最终大小等于此处缩放乘以 DSL `ShowEffect` 缩放。导出的特效条带若只有 RGB 忘了把黑底转 Alpha 会画出黑砖；矩阵包围盒比例算错会把圆环压成空心错位块；同一目录下的多个 `.parts` 共用一张 `.atlas`，删掉自己没用但别的 `.parts` 在用的帧就会连累其他特效（替换弹板皮肤同理，必须严格对齐 `.gen` 切片矩形尺寸）。
- **怎么做**：按 `4096` 定点公式写入居中偏移，导出前检查透明通道与矩阵包围盒；编辑共用图集时只增改所需帧，绝不删除同目录其他 `.parts` 仍引用的帧。
- **怎么验证**：在工作台 L2 时间轴预览及练习场同时测试本特效与同目录关联特效。预期中心点紧贴角色或命中点、无黑底方框、关联特效不缺帧。

## 9. `.parts` 片段越界崩 `F1125`、缺 `end` 收尾硬切消失或全屏单帧掉帧

- **现象**：特效播到快结束时闪退报 `F1125`，持续光环结束瞬间像断电一样突兀消失，或者特效炸开瞬间游戏明显卡顿掉帧。
- **原因**：图层片段的 `起始帧 + 持续帧` 超出总帧数，或头部 `a` 字段（`imageMaxNumbers` 并发贴图池上限）小于同屏实际切片峰值时，运行时数组越界必崩 `F1125`。拉长特效时长时若只改了一处，没同步拉长图层 `t` 保持帧与 `.timeline` 的 `end` 标记也会提前截断；持续特效被销毁时客户端会跳转播放 `end` 淡出标签，没做 `end` 就会硬切消失；单帧塞入多张铺满全屏的巨型半透明贴图则会打爆移动端填充率。
- **怎么做**：修改时长时同步对齐图层帧长、`.timeline` 标签与 `imageMaxNumbers` 上限；给持续型特效补上几帧缩小的 `end` 淡出序列；避免多张全屏大图同帧叠加。
- **怎么验证**：运行 `python wf_flatomo_capacity.py` 核对容量与帧界。预期零越界报错；进图观察特效自然播完和被打断收尾均平滑淡出，全程不弹 `F1125`。
