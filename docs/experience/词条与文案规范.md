# 词条与文案规范

本文适合需要编辑被动能力（`ability`）、队长技（`leader_ability`）、固有状态（`unique_condition`）以及技能和面板文案的改包新手阅读。改表后如果遇到进图报错、面板冒出「null角色」、主位图标消失或被动死活不触发，可以按本文逐条核对列位与文案规范。

## 1. 单键多记录 CSV 只读首行或插队改错行

- **现象**：角色一个能力槽写了多段效果，改表后后半段效果丢失，或者副位禁用标记突然失效。
- **原因**：`orderedmap` 里一个键的值可以是由换行拼起来的多条 CSV 记录。客户端遍历该键下的全部记录生效，没有行数上限；但只有第 0 条记录（`values[0]`）的 `c1`（能否进副位）和 `c2`（玛纳板雕像组）会被读取。若工具按普通单行切分只写回第 0 行，或在首行前插队却没对齐 `c1 / c2`，就会丢效果或改坏副位开关。
- **怎么做**：读写表值时必须用标准 `csv` 解析整个键下的全部记录列表；新增子效果统一追加在记录列表末尾，保持第 0 行的 `c1` 和 `c2` 语义不变。
- **怎么验证**：运行 `python -m wf.studio.draft --view <视图名> ability <角色ID>` 查看该角色各能力槽的 `rows` 记录列表（若需导出面板文案快照，运行 `python -m wf text read <角色ID> --tip <版本号> --output <快照.json>`）。预期在输出的 JSON 中看到该槽位完整的记录条数；若只剩 1 条或首行字段错位，从备份恢复后按多记录列表重新追加。

## 2. `ability`（126 列）与 `leader_ability`（124 列）列号混用

- **现象**：把被动表里验证通过的一行直接复制到队长技表，进游戏立刻崩 `C7050`、`C7101` 或点详情页崩 `F1009`。
- **原因**：`leader_ability` 比 `ability` 少了 `c1`（副位开关）和 `c2`（雕像组）两列，从模式列开始所有列号整体左移 2 位（例如模式列从 `c5` 变成 `c3`）。此外部分扩展词条（如 `kind 724`）只在 `ability` 表实现了构造器，部分触发器在 `leader_ability` 里没有自动描述模板，放过去必崩。
- **怎么做**：跨表迁移词条时必须按列名映射平移 `-2` 偏移，绝不能按列下标硬拷；没有官方队长技先例的触发器或扩展 `kind` 只放在 `ability` 表。
- **怎么验证**：导出快照后运行 `python -m wf check text <快照.json>`。预期看到列合法性与表范围检查通过；若报 `parseAt` 列错位或表不支持该 `kind`，修正 `-2` 列偏移或移回 `ability` 表。

## 3. 空字符串与 `(None)` 哨兵混填（`C7050` / `C7101` / `C8601` / `null角色`）

- **现象**：启动或进编队报 `C7050`、`C7101`、`C8601`，或者角色能力面板上出现刺眼的「null角色」字样。
- **原因**：客户端解析器对空值极其严格：枚举列留空串报 `C7050`（`parseAtN` 即第 `N` 列）；`during` 常驻行的冷却帧列（`ability` 的 `c85`）未填 `(None)` 报 `C7050`；带主体参数的前置条件（`8 / 9 / 87 / 144 / 187 / 188 / 200 / 205`）后一列主体留空报 `C7050`；布尔列（`ability c72` / `leader_ability c70`）留空报 `C7101`；`character_groups` 填了空串 `""` 而不是 `(None)` 会在自动文案里拼出「null角色」；`ability c2` 填了 25 个官方雕像组键以外的词，或 `character c26` 填了 6 个官方定位（`Attacker / Tank / Healer / Supporter / Jammer / Balance`）以外的词，进界面即报 `C8601`。
- **怎么做**：无值枚举列与 `character_groups` 一律填 `(None)`；核对前置条件后一列主体非空、布尔列只填 `true` 或 `false`、雕像组和角色定位只取官方枚举集合。
- **怎么验证**：运行 `python -m wf check text <快照.json>`。预期输出 0 错误；若报错，按提示的列号补上 `(None)` 或合法枚举值。

## 4. `kind 629` 漏配脚本映射、顺序写反或能力档数为 1（`C8601` / `C14510`）

- **现象**：带 `kind 629` 的角色进图弹窗「部分资源文件已损坏」（底层为 `C8601`）、崩 `C14510`，或消耗完层数后动作不触发。
- **原因**：`kind 629` 必须去 `master/ability/custom_ability_string.orderedmap` 查同名键获取 DSL 路径，缺键就抛 `C8601`；该能力槽对应 `character` 表 `c36`（`max_ability_powers`）若写成 `1`，客户端计算等级插值时除零抛 `C14510`；同一键内若先把固有状态用 `525` 消耗光再写 `629`，轮到 `629` 检查条件时层数已归零。
- **怎么做**：在 `custom_ability_string` 补齐同名键指向有效 DSL；把对应槽位的 `max_ability_powers` 设为 `6`（大于 1）；同键既要触发 `629` 又要 `525` 消耗状态时，把 `629` 记录排在 `525` 记录前面。
- **怎么验证**：检查 `custom_ability_string` 键存在且 `DSL` 树已入包，进练习场触发一次被动。预期动作正常释放且状态随后扣除；若仍报资源损坏，优先核对 `custom_ability_string` 键名拼写。

## 5. `unique_condition` 叠层上限填 `(None)` 或 `1`，叠层与消耗全失效

- **现象**：角色能正常挂上固有状态图标，但按层数加成的 `134 / 144 / 199`、消耗层数的 `525` 以及 DSL 条件 `72` 全部不生效。
- **原因**：`master/condition/unique_condition.orderedmap` 第 5 列（0 起第 4 列）是最大叠层数。填 `(None)` 或 `1` 时，客户端将 `accumulatable` 设为 `false`，所有读取层数的接口恒返回 0，消耗接口直接跳过。另外 `134 / 144` 统计的是单个固有状态的叠层数，而 `194 / 188` 统计的是身上不同状态图标的种类数，两者不能混用。
- **怎么做**：凡是需要计数、叠层或被消耗的固有状态，把 `unique_condition` 第 5 列设为 `>= 2` 的整数；按单个状态层数加成时选用 `134 / 144`。
- **怎么验证**：进战斗叠 2 层以上固有状态，观察角色状态栏图标右下角是否显示层数数字、伤害是否随层数递增；若无数字显示，回去把 `unique_condition` 第 5 列改到 `2` 以上。

## 6. 清除不可驱散固有状态时误用 `kind 528`

- **现象**：固有状态设了不可被敌方驱散（`unique_condition` 第 10 列 `c9 = false`），自己用 `kind 528` 想在特定时机删掉它，却怎么也删不掉。
- **原因**：`kind 528`（`DeleteUniqueCondition`）底层走的是常规驱散通道，硬性过滤掉所有 `c9 = false` 的不可驱散状态，就算调高叠层上限也无效。
- **怎么做**：要主动移除 `c9 = false` 的固有状态，改用 `kind 526`（`ConsumeAllUniqueCondition`，一次性消耗全部层数），并确保该固有状态第 5 列最大叠层数设为 `>= 2`。
- **怎么验证**：进战斗挂上该固有状态后触发清除条件。预期状态图标立刻清空；若仍残留，检查是否还留着 `528` 或 `unique_condition` 第 5 列仍为 `1`。

## 7. 合击副位（Unison）规则与主位图标 `Ⓜ` 双重绘制

- **现象**：能力在副位意外生效或意外灰显，自动生成的面板文案开头画出了两个重叠的主位图标，或副位触发的词条加到了主位身上。
- **原因**：第 0 行的 `c1 = false` 会把整个能力槽锁在主位；若整槽允许进副位（第 0 行 `c1 = true`），单条记录限主位靠前置 `202`，限副位靠前置 `203`。同一行既写 `c1 = false` 又写前置 `202` 会让自动文案画两次主位图标。副位角色触发能力时，词条里的「自身」指向主位组合体（唯独 `kind 720` 战斗切换属性在副位触发只改副位自己，且 `720` 必须用 `Instant` 模式，放进 `During` 会崩 `C10109`）。此外可玩角色属性禁填 `6`（无属性），否则崩 `C7050`。
- **怎么做**：整槽禁副位只设第 0 行 `c1 = false` 且不加 `202`；单行禁副位设第 0 行 `c1 = true` 且只在该行加 `202`。`kind 720` 一律配在 `Instant` 模式。
- **怎么验证**：把角色分别放进编队主位和副位打开详情面板。预期主位专属词条在副位灰显且只显示 1 个主位图标；若出现双图标，去掉多余的 `202`。

## 8. 角色换属性时漏改自身种族分组或词条属性列

- **现象**：角色改成新属性后，吃不到自己的队长技或本属性被动加成。
- **原因**：除了 `character` 第 3 列主属性外，`character_groups` 里往往还带有一项属性分组标签，且 `ability / leader_ability` 的目标属性列、触发属性列仍留着旧属性编号。
- **怎么做**：换属性时同步检查并更新 `character c3`、`character_groups` 中的属性项，以及全套被动与队长技里的属性筛选列（DSL 属性码记得按 `c3 + 1` 换算）。
- **怎么验证**：运行 `python -m wf.studio.draft --view <视图名> ability <角色ID>` 查看各能力槽的 `descriptions` 自动中文解释（或运行 `python -m wf text read <角色ID> --tip <版本号> --output <快照.json>` 查看 `abilities[*].auto_text`）。预期所有能力解释里的属性字样与新属性一致；不对则定位残留旧属性编号的列重改。

## 9. 覆写文案（`desc_override`）漏写主位图标标签或触犯版式禁令

- **现象**：接管文案后主位专属能力前的 `[M]` 图标消失了，或者面板直接把 `\n` 两个字符原样印了出来。
- **原因**：当某能力槽全部记录 `c1 = false` 且写了 `desc_override_<槽号>` 时，客户端不再自动补画主位图标，直接打 `Ⓜ` 字符在游戏字库里也无法正常渲染。同时面板规范严禁写「自身生命值100%以下时」凑条件、严禁写「自身为队长时」或「（觉醒后 X%）」、严禁用「／」把多条词条塞进同一行、严禁写入字面量反斜杠加 `n`。
- **怎么做**：在 `c1 = false` 槽位的 `desc_override` 中，每一个非空行开头都必须写上 ` <icon id='main'>  `（前面 1 个半角空格，后面 2 个半角空格）。用真实换行符分行，去掉凑数血线条件，改用无需血线前提的即时词条（如 `245`）。
- **怎么验证**：依次运行 `python -m wf check text <快照.json>`（或在线检查单角色 `python -m wf text check <角色ID> --tip <版本号>`）和全库规范审计 `python -m wf text audit-standard --tip <版本号> --output <审计报告.json>`。预期两项检查均无违规输出；若有告警，按规则编号逐行修正标签空格与换行。

## 10. 独立伤害乘区漏标编号或把「气绝」误写成「追击」

- **现象**：玩家看不出普通增伤和独立乘区的区别，或者以为对气绝增伤在常规击倒（Down）时也能触发。
- **原因**：`kind 410..417` 与 `707` 走独立乘法结算，覆写文案若不标注乘区编号会误导配队；其中 `416` 底层判定的是敌方陷入气绝（Stun），不是常规追击（Down），写错术语会造成机制误判。
- **怎么做**：使用独立乘区词条并撰写覆写文案时，在句尾按规范标明对应的 `（独立伤害乘区N）`；`kind 416` 统一写为对「气绝」中的敌人增伤，不写「追击」。
- **怎么验证**：运行 `python -m wf check text <快照.json>`（或 `python -m wf text check <角色ID> --tip <版本号>`）。预期独立乘区后缀与术语一致性校验通过；若提示术语与 `kind` 不符，按提示修正字眼。

## 11. 技能强化效果写进主动技能正文，或漏同步四处文本镜像

- **现象**：未点出被动时主动技能说明就提前写上了强化效果，或者图鉴、编队、结算界面看到的技能说明不一样。
- **原因**：按面板标准，`action_skill` 的技能说明只描述基础技能形态（不写倍率、段数、秒数，也不写被动附加的强化内容），技能强化效果统一用定性描述写在能力或队长技的 `change_skill_*` 词条里。此外角色与技能文本在客户端表、`character_text` 及服务端两处镜像 JSON 中同时存在，单改一处就会图文分裂。
- **怎么做**：基础说明只写基础动作，强化内容放进能力槽定性描述；修改文案时统一在工作台 `python -m wf.studio --view <视图名> --server-dir <服务端目录>` 保存草稿，或用命令行 `python -m wf text edit <编辑请求.json> --tip <当前版本号> --server-text <服务端目录>/assets/cdndata/character_text.json --rank-text <服务端目录>/assets/cdndata/character_text_rank_p5b.json --output <输出目录> --id <变更ID> --name <名称> --to-version <目标版本号> --slug <英文标识> --created-at <YYYY-MM-DD>` 一次同步客户端与服务端镜像。
- **怎么验证**：运行 `python -m wf text check <角色ID> --tip <版本号> --server-text <服务端目录>/assets/cdndata/character_text.json --rank-text <服务端目录>/assets/cdndata/character_text_rank_p5b.json`（或对携带服务端镜像导出的快照运行 `python -m wf check text <快照.json>`）。预期四处镜像一致性检查全部通过；若有差异报错，补齐 `--server-text` 与 `--rank-text` 重新执行 `wf text edit`。
