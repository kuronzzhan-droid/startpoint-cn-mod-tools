# DSL与技能脚本的坑

本文适合需要编写、克隆或排查主动技能、被动触发动作（`kind 629`）及敌方技能脚本（`ActionDsl`）的改包新手阅读。如果你遇到技能打不出伤害、特效飞到场地左上角、预览闪退或进图报错，可以按下面的现象逐条对照排查。

## 1. 命令名或事件名拼错，技能不报错但伤害神秘消失

- **现象**：脚本能正常打包进游戏，释放技能也不闪退，但后续判定框不生效或延时被直接跳过。
- **原因**：客户端反序列化枚举时，遇到未知构造名不会报错，而是静默退化为该枚举的 0 号构造。例如把延时 `["Wait", 30]` 误放进 `Command` 列表，`Command` 里没有 `Wait`，会退化成 0 号命令 `Trace` 提前打断流程；`Event` 名拼错则会退化成 0 号事件 `Wait`。
- **怎么做**：延时必须放在事件槽（如 `AddEventTo` 的事件列表），不能直接塞进 `Command` 数组。修改节点名时只使用官方词典里存在的构造名。
- **怎么验证**：在仓库根目录打开终端运行 `python -m wf check dsl <树文件.json>`。预期看到校验通过且无未知构造提示；若报未知构造或槽位不匹配，把拼错的节点名改回对应枚举的合法名字。

## 2. 根节点漏包 `ActionDsl` 外壳或误传包装字典（`F1009` / `F1034`）

- **现象**：点开角色技能预览立刻崩 `F1009`，或者进战斗释放技能瞬间崩 `F1034`。
- **原因**：技能与强化弹射 DSL 的根节点必须是 11 参数的 `ActionDsl`；直接把裸 `["Block", [...]]` 当成根节点会导致第 10 槽表达式为空引用（`F1009`）。另外 `wf_dsl.parse_dsl` 返回的是 `{"tree": ..., "numbers": ...}` 包装字典，若整份传给 `encode_amf3` 而不是只传 `parsed["tree"]`，客户端解包会触发类型转换失败（`F1034`）。
- **怎么做**：手写或生成脚本时，外层包齐 `["ActionDsl", 优先级, ["None"], false, false, false, false, false, false, false, 0, ["Block", [...]]]`；编码时只传 `tree` 列表。已有数据包可运行 `python wf_dsl_root_fix.py --store <数据包upload目录> --apply` 批量补齐裸 `Block` 外壳。
- **怎么验证**：运行 `python -m wf check dsl <树文件.json>`。预期看到根构造校验通过；若提示根节点不是 `ActionDsl` 或参数个数不对，补齐 11 参数外壳后重跑。

## 3. 条件分支（`Conditionals*`）空分支写成 `["DoNothing"]`（`F1009`）

- **现象**：包含 `If` / `Conditionals*` 的技能一加载就报 `F1009`。
- **原因**：条件节点的真假分支槽位要求的静态类型是 `Expression`（只接受 `Block`、`If`、`While` 等表达式）。`DoNothing` 属于 `Command`，填进分支槽位后反序列化直接返回 `null`。
- **怎么做**：所有不需要执行动作的空分支，一律写成空块 `["Block", []]`。
- **怎么验证**：运行 `python -m wf check dsl <树文件.json>`。预期无表达式槽位类型报错；若发现 `DoNothing` 出现在分支顶层，替换为 `["Block", []]`。

## 4. 形状与状态构造器参数形状不匹配（`F1034` / `F1009` / `U_f6da5a`）

- **现象**：进图加载或命中敌人瞬间弹 `F1034`、`F1009` 或 `U_f6da5a`。
- **原因**：多处参数要求固定长度数组或元组：`Sector` 第 2 参（扇形开角）和 3 参数 `AC*`（如 `ACAttackBuff` 第 3 参等级成长）要求技能等级数组，写成单个数字或 `false` 会崩 `F1034`；`Rectangle` 要求 `[宽数组, 高数组, 圆角]` 3 个参数，少写圆角会崩 `F1009`；同一条 `CreateCondition` 的状态列表里包含 `ACUnique` 且状态总数超过 2 个时，客户端内部断言直接抛 `U_f6da5a`。
- **怎么做**：写新节点前先查阅仓库内置模块 `wf_dsl_sig.py` 中的官方构造签名字典（写完用下方 `wf check dsl` 自动校验）。需要同时挂固有状态和多个普通状态时，把 `ACUnique` 单独拆成一条 `CreateCondition`，其余状态放进下一条 `CreateCondition`。
- **怎么验证**：运行 `python -m wf check dsl <树文件.json>`。预期全部签名检查通过；若报错则按提示把单值补成数组、补齐 `Rectangle` 第 3 参，或拆分 `CreateCondition`。

## 5. `ACUnique` 第二参数误填成持续帧数，一下叠满几百层

- **现象**：技能设计为赋予 12 秒（720 帧）固有状态，结果进图放一次技能瞬间叠满上限层数。
- **原因**：`["ACUnique", 状态ID, 数值]` 的第 2 个参数是本次增加的层数，不是持续帧数。固有状态的持续时间只由 `master/condition/unique_condition.orderedmap` 的持续秒数列（0 起第 3 列）控制。
- **怎么做**：把 `ACUnique` 的第 2 个参数改成单次叠加层数（通常填 `1`），再去 `unique_condition` 表填写持续秒数。
- **怎么验证**：进战斗释放一次技能并暂停查看角色状态栏。预期固有状态图标只增加设定的层数（如 1 层）；若一次叠满，回到 DSL 检查 `ACUnique` 第 2 参是否填成了帧数。

## 6. 负数内置主体与场地锚点混用，特效飞到左上角或钉死原地

- **现象**：角色释放跟随自身的护盾或近战斩击，特效和判定框却钉死在场地中央或左上角不动。
- **原因**：内置负数主体各有固定含义：`-1` 是场地中心，`-2` 是场地左上角原点，`-17` 是施放者自身，`-18` 是弹珠本体。另外 `CreateReferencePointAtSpecifiedPosition` 传 `[-1, -1]` 取的是场地固定坐标，不会绑定到角色身上。
- **怎么做**：需要跟随施放者的特效或判定框，主体直接填 `-17`（或基于 `-17` 调 `CreateReferencePoint` 派生局部锚点）。只有全屏固定位置演出才使用 `-1` 或 `-2`。
- **怎么验证**：启动工作台 `python -m wf.studio`，打开该角色技能的 L2 时间轴预览观察判定框轨迹。预期判定框随施放者位置移动；若固定在左上角或正中央，把主体从 `-1` / `-2` 改为 `-17`。

## 7. 局部拷脚本漏掉主体绑定，或 `MoveHitArea` 放错层级（`C16103`）

- **现象**：战斗中释放技能瞬间报错 `C16103`（主体查找失败）。
- **原因**：从官方技能只截取了下半段 `CreateHitArea` 或 `ShowEffect`，漏拷了前面创建正整数主体的 `FindAllSubjects` 或 `CreateReferencePoint`；或者把移动判定框的 `MoveHitArea` 写成了 `CreateHitArea` 的平级后续命令，而不是嵌在 `CreateHitArea` 的第 20 槽（`onCreate` 回调块）内部。
- **怎么做**：检查脚本内所有正整数主体编号，确保同一执行路径前序命令已绑定该编号；把操作判定框自身移动的命令移入 `CreateHitArea` 的第 20 槽 `["Block", [...]]` 中。
- **怎么验证**：运行 `python -m wf check dsl <树文件.json>`。预期不报悬空主体或作用域错误；若报错，补齐前序绑定节点或把 `MoveHitArea` 挪进 `CreateHitArea` 第 20 槽。

## 8. 在弹珠、敌人或队友主体上使用 `CD` 坐标系（`U_4f5401`）

- **现象**：强化弹射发射、技能命中敌人或敌方放技能时，游戏直接崩溃并报 `U_4f5401`。
- **原因**：客户端里弹珠（`BallImpl`）、敌人（`EnemyImpl`）、单位（`Unit`）和队友（`Mate`）的 `getDirCD()` 全是未实现的抛错桩函数。`CD` 坐标系只在判定框自身（`CreateHitArea` 的 `p21` 主体，不含 `p22` 被命中目标）和标记点上安全可用。（`-17` 自身配 `CD` 虽有个别不崩案例，但边界未实测，不要依赖。）
- **怎么做**：挂在弹珠（`-18`）上需要沿飞行方向发射的子弹或激光，坐标系一律改用 `["EF"]`；挂在被命中目标（`p22`）或敌人身上时改用 `["AB"]` 或 `["GH"]`。
- **怎么验证**：运行 `python -m wf check dsl <树文件.json>`。预期无 `CD` 坐标系告警；进图实测弹珠斜向弹射与命中敌人时不弹 `U_4f5401`，否则检查是否还有残留的 `["CD"]`。

## 9. `CreateCondition` 实体类型码与主体不匹配（`C16102`）

- **现象**：技能赋状态或 Boss 开场自挂抗性时立刻弹窗 `C16102`。
- **原因**：`CreateCondition` 第 10 槽是目标实体类型码：角色与敌人（`Member`）是 `3`，弹珠（`Ball`）是 `2`。主体填 `-17`（角色或 Boss）却把类型码写成 `2`，或主体填 `-18`（球）却写成 `3`，都会触发类型断言失败。
- **怎么做**：对 `-17` 或 `FindAllSubjects` 选出的角色/敌人赋状态时，第 10 槽填 `3`；对 `-18` 弹珠赋状态时填 `2`。
- **怎么验证**：检查树文件中所有 `CreateCondition` 第 10 槽数值，进图触发该状态。预期状态图标正常出现且不报 `C16102`；若报错则互换核对主体编号与 `2`/`3` 类型码。

## 10. `CreateNormalAttack` 属性码是 1 起算，与角色表差 1

- **现象**：给角色换属性后，主动技能打出的伤害飘字颜色比预期偏了一格，或变成无属性白字。
- **原因**：`character` 表第 3 列属性是 0 起算（`0..5` 对应火水雷风暗光），而 DSL `CreateNormalAttack` 第 2 槽属性码是 1 起算（`1..6`，即 `character.c3 + 1`），外加 `255`（继承施放者属性）和 `254`（全属性）。
- **怎么做**：普通本属性攻击在 `CreateNormalAttack` 第 2 槽直接填 `255` 自动跟随角色属性；必须写死单属性时填 `character.c3 + 1`。注意 `ACToleranceOfElement`（降抗）和 `FindAllSubjects`（按属性索敌）遵循各自玩法目标，不要在批量换色时误改成错误属性。
- **怎么验证**：进练习场释放技能观察伤害飘字颜色。预期飘字颜色与角色面板属性一致；若偏色则把 `CreateNormalAttack` 第 2 槽改为 `255` 或重算 `c3 + 1`。

## 11. `DeleteCondition` 里 `DCAll(N)` 误当成驱散个数

- **现象**：想驱散敌人 2 个强化，写了 `["DCAll", 2]`，结果把敌人身上所有强化一次性全扒光了；或者同帧给自己挂的新强化被自己秒删。
- **原因**：`["DCAll", N]` 里的 `N` 是正负向过滤（`1` = 强化与弱体全删，`2` = 只删强化，`3` = 只删弱体），真正的最大驱散个数是外层 `DeleteCondition` 的第 3 个参数（填 `0` 代表不限个数）。
- **怎么做**：例如「驱散 1 个强化」应写 `["DCAll", 2]` 并把 `DeleteCondition` 第 3 参设为 `1`。同一脚本块内既要驱散又要上状态时，必须先写 `DeleteCondition` 再写 `CreateCondition`。
- **怎么验证**：让测试怪挂上 2 个强化与 1 个弱体后命中技能。预期只减少 1 个强化、弱体保留；若强化全被清空，把外层 `DeleteCondition` 第 3 参从 `0` 改为目标个数。

## 12. 被动触发脚本（`kind 629`）照搬大招命令导致物理锁死

- **现象**：被动 `629` 在战斗中一触发，弹珠就悬停在半空无法操作，或者画面一直黑屏不恢复。
- **原因**：`kind 629` 走的是后台辅助动作通道，没有大招演出管理器的自动收尾逻辑。直接照搬主动大招里的锁物理、镜头特写命令，或写入无官方先例的 `CreateNormalHeal`、超出 `1..3` 范围的 `ShakeCamera` 强度，都会让战斗状态机卡死或报错。
- **怎么做**：`629` 脚本只保留判定框、特效、音效、状态赋予和比例治疗（`CreateRatioHeal`），删掉所有停顿物理、隐藏界面和特写镜头节点；`ShakeCamera` 强度只填 `1`、`2` 或 `3`。
- **怎么验证**：运行 `python -m wf check dsl <树文件.json> --kind 629`。预期看到 `629` 专项校验通过；若有违规命令提示，按输出把大招专用演出命令删干净后再进图实测。
