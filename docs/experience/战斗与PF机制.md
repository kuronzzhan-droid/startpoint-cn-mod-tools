# 战斗与PF机制

本文适合需要设计伤害乘区、强化弹射（PF）、Fever 充能、抗性易伤与护盾判定的改包新手阅读。当你发现词条配完打不出伤害、全队跨属性意外吃到加成、强化弹射特效被下一次弹板吞掉或高抗敌人打不动时，可以按本文核对底层结算机制。

## 1. 把能力伤害加成（`33 / 34 / 388`）误当成主动发出的能力伤害攻击

- **现象**：给角色配了 `kind 33`、`34` 或 `388`，进战斗满足触发条件后却没有任何额外攻击数字跳出来。
- **原因**：`33 / 34` 和 `388` 只是提高「能力伤害乘区百分比」的增益词条，本身不会生成任何攻击判定。真正向敌人发射能力伤害的是 `251 / 316 / 352` 等直伤族：其次数列留空代表攻击全场每个敌人 1 次，填整数 `N` 代表连打 `N` 次。若要做六属性彩虹追伤，必须拆成 6 条单属性直伤记录，不能填无属性。
- **怎么做**：需要自动发射追伤时改用 `251 / 316 / 352` 直伤族（或用 `629` 调 DSL）；`33 / 34 / 388` 只用来放大已有的能力伤害。
- **怎么验证**：运行 `python -m wf.studio.draft --view <视图名> ability <角色ID>` 查看各行 `descriptions` 中文解释。预期直伤行显示「造成属性伤害」而非「能力伤害提升」；进练习场触发一次，确认木桩跳出额外伤害飘字。

## 2. DSL 伤害乘区切换（`buffTargetAs`）与来源标记不同步

- **现象**：把技能 DSL 的 `buffTargetAs` 改成了能力伤或直击伤，虽然吃到了通用增伤，但飘字样式、敌方分类型抗性和 `410 / 413` 独立乘区仍按主动技能结算，或者进图直接报 `C8016`。
- **原因**：`ActionDsl` 根节点第 9 参（`tree[10]`）和 `CreateHitArea` 第 23 参填 `1=技能 / 2=能力 / 3=强化弹射 / 4=直接攻击 / 0=继承外层` 时，在原版客户端只切换通用增伤汇总池，不改底层的 `createdBy*` 来源标记。带伤害转换能力的补丁客户端支持在 `CreateHitArea` 第 23 参填 `101 / 102 / 104` 或 `131 / 132 / 133` 连来源标记一并改写，但填 `102`（转能力伤害）时若全队没有任何原生能力伤害词条，客户端不会预载 `total_ability_damage_effect` 时间轴，命中即崩 `C8016`。
- **怎么做**：原版环境只依赖通用增伤池切换；使用补丁转换码 `102` 时，给角色自身配一条原生能力伤害词条触发预载，并在包内声明客户端能力要求。
- **怎么验证**：用补丁转换码时先运行 `python -m wf check compat --requires <requires.json> --provides <provides.json>`，预期兼容性通过；再进练习场单挂对应类型独立乘区词条，确认飘字样式与倍率都随目标类型放大且不报 `C8016`。

## 3. 直接攻击连击次数在表词条里硬封顶为 3 次

- **现象**：在 `ability` 表里堆了多条附加直击次数词条（如 `521`），想做 5 连击直击，进图撞怪却最多只跳 3 段伤害。
- **原因**：客户端解析表词条的附加直击逻辑把单次撞击的总直击段数硬封顶在 3 次，继续叠表词条会被截断。
- **怎么做**：要做 4 连击及以上的直接攻击，改由主动技能或被动 `629` 的 DSL 脚本赋予 `ACAdditionalDirectAttack` 状态来实现。
- **怎么验证**：进练习场不带队友撞击单体木桩 1 次。预期连击计数一次增加设定的总段数（如 5 连击）；若仍停在 3 连击，检查是否还写在表词条而非 DSL `ACAdditionalDirectAttack` 里。

## 4. 强化弹射增伤（`55 / 696 / 23 / 413`）与贯通/定速延长（`190 / 690`）无条件全队跨属性生效

- **现象**：给火属性角色写了「自身强化弹射伤害提升」或限制了属性列，结果队里的水属性队长做强化弹射也全额吃到了加成。
- **原因**：`55 / 696`、`23 / 413` 在客户端落入整场战斗共享的 `Battle` 汇总器，`190`（贯通时间延长）与 `690`（最大速度固定时间延长）落入全队无属性过滤的 `Party(None)` 汇总器。这几类词条完全无视本行的目标范围列和属性分组列。
- **怎么做**：设计数值时按「只要该角色在队就全队生效」控制强度；撰写文案时如实写成全队强化弹射伤害或全队贯通延长，不要写假的「自身」或单属性限制欺骗读者。
- **怎么验证**：运行 `python -m wf check text <快照.json>`（或 `python -m wf text check <角色ID> --tip <版本号>`）检查文案描述是否与实际作用域一致；组不同属性队长进练习场打 LV1 强化弹射，核对伤害数值与预期全队总倍率吻合。

## 5. 强化弹射连击阈值固定三档与 LV3 跨档触发

- **现象**：想配置第 4 档强化弹射找不到入口，或者想改低 LV2 强化弹射的连击需求却找不到对应词条。
- **原因**：客户端强化弹射固定只有 LV1 / LV2 / LV3 三档，基础连击需求依次为 `9 / 15 / 39`。其中 LV2 的 `15` 连击在代码里写死不可修改；只有 LV3 连击需求可通过减连击词条下调。因为客户端优先判定高档位，当 LV3 所需连击被减到 `<= 15` 甚至负数时，达标会直接越过 LV2 触发 LV3。
- **怎么做**：只在三档框架内设计机制；需要高频出 LV3 时堆叠「LV3 强化弹射所需连击数减少」词条即可。
- **怎么验证**：进练习场观察达到目标连击数时弹板的光效颜色。预期达到折算后的连击数时弹板直接变红（LV3）；若仍出黄光（LV2），核算减费总和是否尚未压到目标值。

## 6. 强化弹射覆盖（`419 / 722`）残留剑气被下次弹板秒删或双倍爆音

- **现象**：定制强化弹射发出的持续领域或慢速剑气还没打完，角色一落回弹板发下一次强化弹射，上一发的剑气就凭空消失；或者弹射瞬间音效刺耳发炸。
- **原因**：`419` 和 `722` 都只在 1 号主位生效（进图会预载全部三档 DSL 与特效）。引擎在启动新一轮强化弹射动作时，会强制清理上一轮强化弹射动作挂出的未结束子对象。此外，在官方强化弹射特效母本上硬叠新特效层而不清理母本原有的 `sounds` 列表会导致同名音效双倍播放；强化弹射语音是 100% 必播，音频过长也会在高频弹板时叠音。
- **怎么做**：需要跨多次弹射存活的剑气或领域，不要直接写在强化弹射 DSL 里，改为用触发器 `183`（强化弹射时）触发 `kind 629` 独立脚本施放；改特效时替换图层并保持单份 `sounds`，`722` 行的 4 个生命周期参数保持官方母本组合不改，语音裁短。
- **怎么验证**：进练习场连续快速触发两次强化弹射。预期第一发生成的持续特效在第二次弹板后依旧留在场上打满伤害且音效不发炸；若提前消失，确认是否已迁移到 `183 + 629` 通道。

## 7. 判定框单目标命中上限（`p15`）设错与重击打击感做法

- **现象**：多段旋转激光擦过 Boss 只跳了 1 次伤害就停了，或者想做「卡肉停帧」翻遍命令表找不到停帧节点。
- **原因**：`CreateHitArea` 第 14 参（`p14`）是同目标再次命中的帧间隔，第 15 参（`p15`）是对单个目标的累计最大命中次数硬上限——`p15` 填 `1` 就只打 1 下，填 `0` 则在存活期内按 `p14` 间隔不限次命中。另外客户端没有帧冻结卡肉命令，官方技能的重击感全部由「同帧对齐 `ShakeCamera`（强度 `1..3`）+ 受击爆发特效 + 重击音效」三件套合成。
- **怎么做**：做 `K` 段稳定多段伤害时，把 `p15` 设为 `K`，并让判定框存活帧数略大于 `(K - 1) * p14`；做重击演出时在命中回调同帧配上震屏、受击特效和音效。
- **怎么验证**：在工作台 `python -m wf.studio` 打开 L2 预览核对判定框持续帧与 `p14 / p15` 参数，再进练习场打单体静止木桩。预期木桩精确跳出 `K` 段伤害并伴随震屏；段数不对则重算存活帧与 `p14 / p15`。

## 8. Fever 期间常规充能失效与大招约 60 帧硬冻结

- **现象**：进入 Fever 状态后，连击和普通加 Fever 词条完全推不动 Fever 槽；或者想关掉放主动技能时的全场定格却关不掉。
- **原因**：Fever 激活期间常规涨槽调用传的是 `isChangeable(false)`，会被直接拦截。全客户端只有三条通道传 `true` 可在 Fever 期间强行改槽（且均绕过 Fever 槽充能率乘区，单次 Fever 内累计延长上限为初始槽量的 `1.25` 倍）：被动 `kind 213`、补丁客户端仅限 `ability` 表的 `kind 724`（填负数可扣减剩余 Fever 时间）、以及 DSL 的 `AddFeverPoint / SubtractFeverPoint`。至于主动大招释放时的约 60 帧演出停顿在客户端代码写死，没有表列开关。
- **怎么做**：要做「续 Fever」或「烧 Fever 换爆发」机制时，只选用 `213`、`ability` 表 `724` 或 DSL `AddFeverPoint / SubtractFeverPoint`；不想触发 60 帧停顿的派生动作改走 `kind 629`。
- **怎么验证**：进练习场打进 Fever 后触发该被动或技能。预期 Fever 进度条刻度立刻上涨或回退；若纹丝不动，检查是否误用了普通 Fever 充能词条。

## 9. 正抗性除法公式、负抗性（易伤）硬下限与真伤/护盾边界

- **现象**：给 Boss 挂了 `1.0`（100%）正抗性以为能完全免疫，玩家还是能打出一半伤害；反过来叠了 `-300%` 降抗，伤害却卡在 2.5 倍不再涨。
- **原因**：正抗性走除法衰减 `伤害 / (1 + r)`，`r = 1.0` 只是 `÷ 2`（减伤 50%），要做到近似免疫必须填 `r >= 99`。负抗性（易伤）在底层有硬保底下限：属性易伤最低到 `-1.5`（最高 `×2.5` 倍伤害），技能/能力/强化弹射/直击四类分项易伤最低到 `-1.0`（最高 `×2.0` 倍伤害）。对开启了 `resist_element_resistance` 的 Boss 强行挂降抗，必须开启强制赋予（`CreateCondition` 第 11 参 `true` 或 `unique_condition` 第 10 列 `true`）且使用全属性 `254` 或弱点属性。比例扣血（`CreateRatioAttack`）、固定伤害（`CreateFixedAttack`）与毒伤无视抗性；角色护盾（Barrier）即使只剩 1 点耐久，也能完整吃掉单段超高额直伤。
- **怎么做**：做机制免伤阶段时正抗性填 `99` 或 `999`；设计降抗收益时不要按超过 `-150%` 属性易伤定数值；防逃课高难 Boss 注意拆多段伤害破除 1 点残盾。
- **怎么验证**：对挂满抗性或挂满降抗的测试怪放定额技能对比裸伤。预期 `r = 99` 时伤害压到 1% 以下、满属性降抗稳定封顶在 `2.5` 倍；不对则核对抗性数值正负号与类型。

## 10. 防御（Guard）纯看冲刺物理态，技能直充（`211`）无视充能率

- **现象**：想找一个「开启防御减伤」的表词条找不到；或者给敌人挂了「技能充能速度降低」弱体，角色触发 `kind 211` 自充时还是满额回槽。
- **原因**：角色在敌方红圈预警外的 `Guard` 减伤判定纯看碰撞瞬间弹珠是否带有冲刺光环（刚从弹板弹出且纵向速度满足上冲条件），没有任何表词条能开关它，且比例扣血无视 `Guard`。同样，即时充能词条 `kind 211` 直接对技能槽做加减，完全绕过技能槽充能率乘区（充能率增益/减益的结算范围是 `[-1, +1]`，只影响移动距离自然攒槽）。另外 `AbilityOriginKind` 只决定面板 UI 图标归类，不参与任何战斗乘区拆分。
- **怎么做**：不要围绕表词条设计开关 `Guard`，也不要指望减充能率能限制 `211` 固定回转；要卡大招回转应改技能槽总长（skill weight）或限制 `211` 触发次数。
- **怎么验证**：挂上 `-50%` 技能充能率状态后触发 `+50%` 的 `kind 211` 词条。预期技能条依然精确上涨 50%；自然弹射移动攒槽速度则减半。
