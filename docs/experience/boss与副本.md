# boss与副本

本文适合需要新增或移植领主战、活动副本、多波次协力双 Boss、击破试炼条、代币商店与肉鸽连战关卡的改包新手阅读。如果遇到点进副本报资源损坏、跨波次黑屏、换皮 Boss 改不动血量或商店图标闪退，可以按本文逐项核对关卡表与预载链路。

## 1. 新增领主战入口漏配商店分类、BGM 注册或服务端体力键（`C8601`）

- **现象**：在大地图点击新加的领主战星球节点，直接弹窗「部分资源文件已损坏」（底层为 `C8601`），或者选完助战点出发时报体力校验错误。
- **原因**：`boss_battle_stage_node` 第 6 列填的商店分类键必须在 `master/shop/boss_coin_shop_category.orderedmap` 中存在；自定义背景音乐键必须在 `bgm_asset` 表注册，缺任何一项都会抛 `C8601`。此外服务端入场体力表的键格式为 `<副本类别>_<副本ID>`，领主战类别固定是 `2`（即 `2_<副本ID>`），漏配或写错前缀会导致无法开房。
- **怎么做**：先在 `boss_coin_shop_category` 和 `bgm_asset` 补齐引用键，再在服务端体力配置中补齐 `2_<副本ID>` 条目。
- **怎么验证**：运行 `python -m wf check boss <副本ID>`。预期关联键检查全部通过；启动游戏从主城点进对应领主战列表并成功开房，若仍报资源损坏则核对第 6 列分类键拼写。

## 2. 代币商店自定义商品漏同步三张表，或道具小图标未进图集（`C8601` / `C8004` / `C4208`）

- **现象**：打开领主币商店报错 `C8601`、`C4208`，或滑到新道具时瞬间闪退报 `C8004`（纹理尚未加载）。
- **原因**：新增商店商品必须同时写入客户端 `boss_coin_shop`、服务端 `boss_coin_shop.json` 和 `boss_coin_shop_item_category_map.json` 三处。`item` 表第 4 列小图标路径写成 `(None)` 会崩 `C4208`；指向单张散装 PNG 会因为商店界面走同步取图集子纹理接口而直接崩 `C8004`。该列只能填已打包进 `item_icon/sprite_sheet` 图集的子纹理名（抽卡券大图走 `item/sprite_sheet`，而战斗内 `battle/common/layer1` 封在 APK 内置包里，不能单靠 CDN 覆盖）。
- **怎么做**：把新道具小图标并入 `item_icon/sprite_sheet`，发布时先确保新图集已就位再发引用它的 `item` 行，并三端同步商店条目。
- **怎么验证**：进游戏打开领主币商店滑到底并点开新商品详情框。预期图标清晰显示且可正常兑换；若报 `C8004`，检查子纹理名是否已写进 `item_icon/sprite_sheet.atlas`。

## 3. 多面相领主（`BothBoss`）放错活动表、保底行置顶或变体血量不等

- **现象**：按队伍体系切面相的 `BothBoss` 放进活动副本不生效，或者永远只进第一个面相，又或者第 0 轮共享血条扣血比例错乱。
- **原因**：`BothBoss` 分流逻辑只在常驻领主表 `BossBattleQuestValues` 中生效，`advent_event` 活动表不支持 `BothBoss`。`both_boss_map` 自上而下匹配玩家队长属性（唯独强化弹射条件汇总全队），若把无条件保底行放在第 1 行就会拦截后续全部条件。开启第 0 轮共享伤害（`DamageShare` 配合 `c40` 绑定目标 Boss）时，所有面相变体的总血量必须完全相等，否则跨面相折算血量会失真。另外 `event_list` 列顺序为 `[类别, 活动ID, 显示权重]` 且按权重降序展示。
- **怎么做**：`BothBoss` 一律建在 `boss_battle_quest` 下；把无条件保底行排在 `both_boss_map` 末尾；将所有面相的固定血量设为同一数值。
- **怎么验证**：运行 `python -m wf check boss <副本ID>` 校验表结构，再用两套不同流派队长分别进图，确认命中各自面相且共享扣血同步。

## 4. 多波次过场缺门动画、协力棺材位不足或移植 Boss 撞锚点（`C8251` / `C10000` / `C14102`）

- **现象**：多波次关卡进图崩 `C8251`、`C10000`，3 人协力有人死后不出棺材，或移植的 Boss 一放位移技能就崩 `C14102`。
- **原因**：波次数由地形文件里的 `'0'`、`'1'` 波次层决定；两波及以上的副本必须在 `field` 表第 7、8 列配齐传送门与过渡舱动画，否则崩 `C8251`。`zone` 表第 22 列填 `0` 可在协力实现同场双 Boss（填 `1` 为顺序登场），但 3 人协力每层地形必须摆够 9 个 `COFFIN` 棺材位，且 `BOUNDS / WALL` 唯一合法（重复或缺失崩 `C10000`）。移植 Boss 若调用了原场地专属的 `CUSTOM_POSITION` 跳点而新地形没有该锚点，位移即崩 `C14102`；同场双 Boss 共用同名跳点也会互相踩踏。
- **怎么做**：多波次关卡选用带门动画的 `field` 行；3 人协力补齐 9 个 `COFFIN`；只有不含场地跳点瞬移、且代码未按专属身份锁死机制的 Boss 才能直接改名克隆，带跳点的 Boss 必须把对应 `CUSTOM_POSITION` 一并拷入目标地形。
- **怎么验证**：运行 `python -m wf check boss <副本ID>`。预期地形锚点、波次与棺材位检查通过；组房打通全部波次确认过场门正常开启且位移不崩。

## 5. 混淆 `general_boss` 与 `StandardBoss`（`.esdl`），改不动血量或卡在下载（`C8100`）

- **现象**：改了 `boss_level` 的血量但进图 Boss 血条丝毫没变；或者 `general_boss` 进图无限卡在「数据不足」（`C8100`）；又或者打到后半程帧率暴跌。
- **原因**：Boss 分两套架构：无 `.esdl` 的 `general_boss` 读 `boss_level` 表（`c2` 为破棺撞击次数，`c3` 为倍率，`c5` 为固定血量），其空动作列（如 `c109`）必须留空串 `""`，填 `(None)` 会被当成真文件名去下载导致 `C8100`；它的招式槽由 `.timeline` 里的 `enemy_actionNN` 标记触发，弱点球完全由自身状态机开启，若借用了带 `Repeat(..., 9999)` 的循环脚本却漏写阶段切换时的 `RemoveEventFromOwner`，后台事件会无限堆积拖垮帧率。而 `StandardBoss` 的血量、阶段链和招式全封在 `battle/enemy/boss/*.esdl.amf3.deflate` 里，`boss_level` 对它完全无效。
- **怎么做**：改之前先查清目标属于 `general_boss` 还是 `StandardBoss`；`general_boss` 空动作槽一律写 `""`，循环事件配齐退出清理；`StandardBoss` 直接解包修改 `.esdl` 文件。
- **怎么验证**：运行 `python -m wf boss show <Boss或副本ID>` 查看架构与阶段摘要。进图实测血量数字与设定一致，连打 3 分钟帧率平稳无卡顿。

## 6. Boss 击破试炼条（`HitCountCheck`）改错位置不出条

- **现象**：照着普通 Boss 在 `general_boss_state` 填了 `c22..c26` 连击试炼参数，进图却根本不出击破倒计时条。
- **原因**：只有纯表驱动的 `general_boss` 从 `general_boss_state` 的 `c22..c26` 列（配合 `HitCountCheckTargetKind` 护盾）读取试炼条；`StandardBoss` 的试炼条定义在 `.esdl` 内部状态节点的 `SimpleState.trial` 结构里，不读外层状态表。
- **怎么做**：`general_boss` 改 `general_boss_state c22..c26`；`StandardBoss` 在 `.esdl` 对应阶段的 `SimpleState.trial` 中配置连击数与限时。
- **怎么验证**：进图推进到试炼阶段。预期顶部正常弹出连击计数条与倒计时，打满连击后 Boss 进入破防虚弱。

## 7. 用副本表 `c71..c80` 配常驻机制免伤，被玩家一发驱散秒破

- **现象**：在 `quest` 表 `c71..c80` 给高难 Boss 配了开场高额伤害抗性，结果玩家带个普通驱散角色一发技能就把抗性全清光了。
- **原因**：副本表 `c71..c80` 生成的开场抗性状态在客户端写死了 `cancelable = true`（允许驱散），无法通过表列锁死。
- **怎么做**：改用 `general_boss` 第 109 列 `pre_action` 开场脚本，调用 `CreateCondition` 把 `cancelable` 设为 `false`、主体填 `-17`、目标类型填 `3` 自挂不可驱散抗性；同时核对 `general_boss c36`（`resist_element_resistance`）布尔列非空，并至少留出一种未封死的属性或伤害类型通道防止死局。
- **怎么验证**：带驱散强化技能（`DCAll(2)`）进图命中 Boss。预期 Boss 血条下的抗性图标带锁定标记且驱散后依然保留。

## 8. 召唤浮游炮（`SpawnFunnel`）分组越界或漏前导预载（`U_ac0726` / `C8013`）

- **现象**：Boss 一放召唤技能就崩 `U_ac0726`，或者进图加载阶段直接报 `C8013`。
- **原因**：`SpawnFunnel` 的 `FunnelGroup` 分组号只允许填 `1..10`，超出该区间（或敌方脚本误调玩家专用的 `HideCharacter`）立刻抛 `U_ac0726`；同组场上槽位已满时新召唤会被静默丢弃；且被召唤的 `general_funnel` 键必须在进图前导预载表里存在，漏注册即崩 `C8013`。
- **怎么做**：`FunnelGroup` 严格取 `1..10`，删掉敌方脚本里的 `HideCharacter`，并在 `general_funnel` 表写齐召唤物定义与等级行。
- **怎么验证**：运行 `python -m wf check dsl <敌方树文件.json>` 并进图让 Boss 连续释放两次召唤。预期召唤物正常登场、满员再次召唤不报错。

## 9. 场地效果（`StartModifierField`）单条塞多项（`C14555`）或误以为能强化 Boss

- **现象**：Boss 开启场地效果瞬间崩 `C14555`；或者配了加攻场地想提升 Boss 伤害，结果反而给玩家全队加了攻。
- **原因**：`StartModifierField` 的效果数组硬限制最多只能包含 1 个效果项，写 2 项及以上必崩 `C14555`。同时场地效果在底层只对玩家方成员结算，永远不会给敌方 Boss 提供增益。
- **怎么做**：每条 `StartModifierField` 数组只放 1 项玩家侧环境效果；要强化 Boss 自身一律改对 `-17` 调 `CreateCondition`。
- **怎么验证**：进图触发场地开启。预期不弹 `C14555`，场地横幅正常提示且效果准确落在玩家侧。

## 10. 肉鸽与连战关卡的等级覆盖缺口（`U_50fc52` / `U_3be147`）及跨属性预载漏项（`C8016`）

- **现象**：随机抽怪或连战进图黑屏崩 `U_50fc52` / `U_3be147`（日志提示缺值 `N`），或者战斗中途小怪一出手就崩 `C8016`。
- **原因**：关卡在 `c95` 指定了怪物等级 `N` 时，主怪、分身变量表 `general_boss_variable`、`standard_boss`、普通小怪 `general_zako` 及关联召唤物在对应等级表里但凡缺了等级 `N` 的那一行，加载即抛 `U_50fc52` 或 `U_3be147`。此外客户端只按关卡 `c69`（`battle_recommended_element`）预载推荐属性通用特效，若 Boss 或召唤怪打出了其他固定属性的攻击，对应属性时间轴未加载就会崩 `C8016`。
- **怎么做**：补齐所有参战主怪、分身与召唤物在目标等级 `N` 的等级表行；有跨属性攻击或跨属性召唤物时，在关卡空余敌人槽塞入对应属性的占位哑元单位强制触发预载。
- **怎么验证**：肉鸽配置运行 `python wf_rogue_validate.py`，常规副本运行 `python -m wf check boss <副本ID>`。预期等级覆盖与属性预载检查零报错，实测打完跨属性招式不崩 `C8016`。
