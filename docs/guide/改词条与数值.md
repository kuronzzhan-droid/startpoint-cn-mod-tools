## 一、动手前先选对工具

不同数据由不同工具负责，改之前先按下面这张表选入口：

| 你要改什么 | 推荐工具 | 是否直接改动原数据包 |
|---|---|---|
| 被动词条、队长技、面板文案 | Studio 编辑台（`python -m wf.studio`） | 否，只写 `work/studio-drafts/` 草稿 |
| 主动技能伤害系数、连击数、技能能量消耗 | Studio 编辑台「技能模板」页 | 否，只写草稿 |
| 强化弹射（PF）三档系数与动作 | Studio 编辑台「强化弹射动作」页 | 否，只写草稿（需客户端支持 P13） |
| 角色 1/10/80/100 级基础 HP / ATK、觉醒属性加成 | 传统修改器（`python wf_gui.py` 或 `python wf_char_editor.py`） | 是，直接写 `paths.store` 并自动留 `.bak-wfmod-*` 备份 |
| 多名角色批量平衡调数（锁定旧值防改错） | 平衡配方命令行（`python -m wf balance`） | 否，输出变更集到 `work/` |

## 二、必知避坑：列号、单位与空值

### 1. 五张词条表的真实列数（切勿照搬旧 125 列手册）

仓库根目录的早期文档 [`CN-Mod字段手册.md`](../../CN-Mod字段手册.md) 第四章漏记了觉醒列，把 `ability` 写成了 125 列，导致第 3 列往后全部错位 1 列。**查看列号请一律以 [`词条条件代码全表.md`](../../词条条件代码全表.md) 为准**：

| 表名（逻辑路径） | 真实总列数 | 与 `ability` 的正文列号偏移 | 关键注意 |
|---|---|---|---|
| `master/ability/ability.orderedmap` | **126 列** | `0`（基准：`c5` 触发方式、`c6` 前置条件、`c47` 瞬发效果、`c109` 持续效果） | `c1=false` 表示仅主位生效；`c3/c4` 为觉醒类型与等级 |
| `master/ability/leader_ability.orderedmap` | **124 列** | **`-2`**（无主位限制列，`c3` 触发方式、`c45` 瞬发效果、`c107` 持续效果） | 队长技键查 `character` 表 `c17`（部分老角色队长键不等于角色 ID） |
| `master/ability/ability_soul.orderedmap` | **123 列** | **`-3`** | 魂珠与装备本体共用此表 |
| `master/equipment_enhancement/equipment_enhancement_ability.orderedmap` | **126 列** | `0` | 表头 6 列不同，正文块列号与 `ability` 相同 |
| 服务端 `assets/ex_ability.json` | **125 列** | **`-1`** | 位于服务端目录 |

### 2. 数值单位换算表

表里存的都是放大后的整数，填错倍数会出现「数值大十万倍」或「持续时间只有 0.0001 秒」：

| 字段类型 | 换算规则 | 填写示例 |
|---|---|---|
| 普通百分比强度、HP 比例门槛 | **`1000 = 1%`** | 攻击力 `+25%` 填 `25000`；HP `80%` 以上填 `80000` |
| 计数门槛（`threshold`）、发动次数（`number`）、队伍人数 | **`100000 = 1`** | 弹射 `15 次` 填 `1500000`；同属性 `6 人` 填 `600000` |
| 增益/减益持续时间（`frame` 列对） | **`帧数 × 100000`**（60 帧 = 1 秒） | 持续 `15 秒` = `900 帧` → 填 `90000000` |
| 触发冷却时间（`cooltime` 列对） | **直接填原始帧数**（不乘十万） | 冷却 `15 秒` = `900 帧` → 填 `900` |
| 瞬发延迟（`instant_delay`，`ability` 第 46 列） | **直接填原始秒数**（不乘 60 也不乘十万） | 延迟 `2 秒` → 填 `2` |

> 提示：每个强度或时间字段通常占相邻两列 `(等级1初值, 满级终值)`。游戏会按角色技能等级在两列之间自动插值；想固定数值就把两列填成一样的数。

### 3. 空值必须写 `(None)`，不能留空白

可选条件或上限列在「不启用」时，必须填入字面字符串 **`(None)`**，不能留成空字符串 `""`：
- 触发次数上限列留空会变成 `0 次`，整条词条永远不触发。
- 布尔列或枚举列留空会在进图或点开角色详情时直接闪退（报错 `C7050` 或 `C7101`）。
- 持续型词条（`trigger=1`）的 `during_accumulation_trigger`（`ability` 第 85 列）不启用时必须写 `(None)`，误写 `'0'` 会报错 `C2308`。

## 三、前置检查：确认本机路径配置已就绪

### 第 1 步：检查仓库根目录下的路径配置文件

- **做什么**：在工具仓根目录打开 PowerShell，执行以下命令查看 `profiles/local.json` 是否存在：
  ```powershell
  Test-Path profiles/local.json
  ```
- **预期看到什么**：终端输出 `True`。
- **不对怎么办**：如果输出 `False`，先把模板复制一份：
  ```powershell
  Copy-Item profiles/example.json profiles/local.json
  ```
  然后用记事本打开 `profiles/local.json`，按 [`profiles/README.md`](../../profiles/README.md) 填好你自备的数据包目录（`store` 或 `store131`）、补丁清单目录与服务端目录（`server`）。不要复制旧的根目录 `profiles.json`，旧格式会触发弃用警告。

## 四、任务一：用 Studio 编辑台改词条、文案、技能倍率与 PF（推荐）

Studio 编辑台只读取你的基准数据包和补丁链，把所有修改保存在 `work/studio-drafts/<角色ID>/` 草稿目录中，改错了随时可撤回。

### 第 1 步：首次构建编辑台前端网页

- **做什么**：如果 `studio/dist/index.html` 还没有生成，在工具仓根目录的 PowerShell 中依次运行：
  ```powershell
  cd studio
  npm install
  npm run build
  cd ..
  ```
- **预期看到什么**：`npm run build` 结束时没有红色 `error`，并且 `Test-Path studio/dist/index.html` 输出 `True`。
- **不对怎么办**：
  - 提示找不到 `npm`：说明本机未安装 Node.js（需安装 Node.js 并重新打开 PowerShell）。
  - 构建报 TypeScript 或依赖错误：确认是在 `studio` 子目录内执行了 `npm install`，不要在仓库根目录跑 `npm`。

### 第 2 步：启动 Studio 编辑台服务

- **做什么**：在工具仓根目录运行以下命令（把 `<视图名>` 换成你在 `profiles/local.json` 里配置的视图名，把 `<服务端目录>` 换成你自备的服务端目录；改文案必须带 `--server-dir`）：
  ```powershell
  python -m wf.studio --view <视图名> --server-dir <服务端目录>
  ```
- **预期看到什么**：终端提示服务已在 `http://127.0.0.1:8790` 监听，窗口保持运行不退出（浏览器交互流程为代码核实，本机真机联调标「未实测」）。
- **不对怎么办**：
  - 报错提示未配置路径或找不到视图：打开 `profiles/local.json` 检查视图名称拼写及 `manifest`、`store`、`server` 路径是否真实存在。
  - 报错端口 `8790` 被占用：加上 `--port 8791` 换一个本机空闲端口，再访问对应地址。
  - 报错拒绝绑定非本机地址：编辑台出于安全限制只允许绑定 `127.0.0.1`、`localhost` 或 `::1`，不要传局域网 IP。

### 第 3 步：在网页中修改被动词条或队长技

- **做什么**：用浏览器打开 `http://127.0.0.1:8790`，进入顶栏「角色工坊」，搜索并点开目标角色，在「能力」标签页选择「一板 / 二板 / 三板」或队长技槽位，按卡片修改触发条件、效果类型与数值，点击预览无误后保存到草稿。
- **预期看到什么**：右侧或下方实时显示修改前后的中文词条自动描述和五态规则检查结果；保存后右上角「本次修改」抽屉出现 `ability_edit` 记录，且 `work/studio-drafts/<角色ID>/changeset.json` 被更新（浏览器实操标「未实测」）。
- **不对怎么办**：
  - 保存按钮无响应或报 `403`：必须直接访问 `http://127.0.0.1:8790` 打开页面（后端会注入同源安全令牌），不要打开本地静态 HTML 文件。
  - 提示该角色是新克隆角色、暂不支持叠加 `ability_edit`：含 `character_clone` 的新角色首包草稿不能同时叠加 `ability_edit`；请先把新角色首包交付入链，再按已有角色打开编辑，详见 [`studio/character-clone.md`](../studio/character-clone.md)。
  - 想用命令行检查词条请求 JSON：可运行 `python -m wf.studio.draft --view <视图名> --server-dir <服务端目录> ability <角色ID> --request <请求JSON路径> --preview`。

### 第 4 步：修改并核查角色面板文案

- **做什么**：切到角色详情页的「文案」标签页，修改技能名、技能说明或能力覆盖文案（`desc_override_<c0>`），确认检查通过后保存草稿。你也可以在 PowerShell 用命令行单独核查该角色的文案规范：
  ```powershell
  python -m wf text check <角色ID> --tip <当前版本号> --server-text <服务端目录>/assets/cdndata/character_text.json --rank-text <服务端目录>/assets/cdndata/character_text_rank_p5b.json
  ```
- **预期看到什么**：命令返回退出码 `0`，无阻断性违规问题。若想查看全部 60 条文案规范细则，可运行 `python -m wf text rules`。
- **不对怎么办**：如果报文案规范阻断，请对照以下最常踩的 4 条红线修改（详见 [`m2/text-standard.md`](../m2/text-standard.md)）：
  1. 覆盖文案里**禁止写** `自身为队长时` 和 `X%（觉醒后 Y%）` 双值写法。
  2. **禁止**用全角斜杠 `／` 把两条不同效果压在同一行。
  3. 当某个能力槽所有行的 `c1`（`unisonable`）都是 `false`（仅主位生效）时，覆盖文案的**每一个非空行开头**都必须精确带上 ` <icon id='main'>  `（前面 1 个半角空格，后面 2 个半角空格），**严禁手打圆圈字母 `Ⓜ`**。
  4. 服务端同时存在 `character_text.json` 与 `character_text_rank_p5b.json` 两份镜像，不要用记事本只改其中一份，务必通过编辑台或 `python -m wf text edit` 同步写回。

### 第 5 步：（按需）修改主动技能倍率、能量或强化弹射（PF）动作

- **做什么**：
  - **改主动技能**：在角色页点击「技能 → 技能模板」，从官方技能母本中挑一个模板，修改伤害倍率、连击数、判定范围或技能能量（`skill_cost`），先点「预览编译」，再点「写入角色草稿」（详见 [`studio/skill-templates.md`](../studio/skill-templates.md)）。
  - **改强化弹射（PF）**：点击「技能 → 强化弹射动作」，选择复用已有 PF 键，或克隆官方三档 PF 并调整 Lv1/Lv2/Lv3 系数后写入草稿（详见 [`studio/pf-actions.md`](../studio/pf-actions.md)）。
- **预期看到什么**：预览编译显示将生成的 `action_skill.orderedmap` 与 `action_dsl/*.json` 摘要且无红字报错；写入后「本次修改」抽屉出现对应记录（浏览器实操标「未实测」）。
- **不对怎么办**：
  - 改完自定义 PF 后在交付检查报 `P13` 扩展阻断：自定义角色 PF 依赖 `custom_ability_string` 中的 `wfx_*` 私有扩展键，目标客户端必须支持 P13 扩展；若面向普通客户端（如 `official` 或 `test-v34`），请改用词条表内的 `722` 覆盖方案，详见 [`客户端补丁与APK.md`](客户端补丁与APK.md) 与 [`studio/p13-keys.md`](../studio/p13-keys.md)。

### 第 6 步：校验草稿并打出本地交付包

- **做什么**：在 PowerShell 先校验草稿完整性，再编译为本地交付包（`<输出目录>` 必须是工具仓内一个尚未创建或为空的目录，如 `work/studio-deliveries/<本次名称>`）：
  ```powershell
  python -m wf.studio.draft --view <视图名> save <角色ID>
  python -m wf.studio.draft --view <视图名> build <角色ID> --from <当前版本号> --to <目标新版本号> --out <输出目录> --server-dir <服务端目录> --client-profile <客户端档案名>
  ```
- **预期看到什么**：两条命令都退出码为 `0`，输出一行包含状态摘要的 JSON，并在 `<输出目录>` 下生成热更 ZIP、`manifest-entry.json`、`server/` 同步镜像以及 `check.json`、`compat.json` 检查报告。
- **不对怎么办**：
  - 报目标版本已被占用：运行 `python -m wf.studio.draft --view <视图名> versions next` 查询下一个空闲版本号。
  - 报 `compat` 客户端能力不兼容：说明你用到了目标 `--client-profile` 不支持的效果码或扩展，需更换匹配的客户端档案或删掉超纲词条。
  - 交付包生成后如何预演、上线和回滚，请继续阅读 [`发布与回滚.md`](发布与回滚.md)。

## 五、任务二：改角色基础生命值（HP）与攻击力（ATK）

Studio 编辑台目前不提供角色基础 HP/ATK 成长曲线面板。修改基础面板请使用传统修改器 `wf_gui.py` 或命令行 `wf_char_editor.py`。

> **重要警告（两张表列序相反！）**：
> - `character_status.orderedmap`（1/10/80/100 级基础面板）：内层两列顺序是 **`HP, ATK`**，且**严禁增删或重排 `1`、`10`、`80`、`100` 四个等级断点**，否则进游戏必报 `C2268`。
> - `character_awake_status.orderedmap`（觉醒大节点属性加成）：单行两列顺序反过来，是 **`ATK, HP`**！只对原本有觉醒板的角色生效。

### 方式 A：用传统网页修改器 `wf_gui.py` 可视化修改

#### 第 1 步：启动 `wf_gui.py`

- **做什么**：确认 `profiles/local.json` 中已填好 `paths.store`（指向数据包 `production/upload` 目录），在工具仓根目录运行：
  ```powershell
  python wf_gui.py
  ```
- **预期看到什么**：终端打印本地监听地址（默认为 `http://127.0.0.1:8765`）并自动打开浏览器页面（本机真机联调标「未实测」）。
- **不对怎么办**：
  - 报错 `未配置 store`：检查 `profiles/local.json` 的 `paths.store` 是否填写了有效路径，或在当前 PowerShell 会话设置 `$env:WF_STORE = "<数据包upload目录>"`。
  - 默认 `8765` 端口被系统保留（`WinError 10013`）：脚本会自动顺延尝试 `8766` 等备用端口，请以终端实际打印的 `http://127.0.0.1:<端口>` 为准。

#### 第 2 步：修改角色 HP / ATK 并保存

- **做什么**：在网页左侧搜索并点击目标角色，修改各等级断点的 HP、ATK 或觉醒加成数值，点击保存。
- **预期看到什么**：页面提示保存成功，同时在你的 `<数据包upload目录>` 对应哈希文件旁自动生成 `.bak-wfmod-<时间戳>` 备份文件（浏览器实操标「未实测」）。
- **不对怎么办**：
  - 改完后还不会自动发到服务端热更链；需要按 [`发布与回滚.md`](发布与回滚.md) 中的 `python wf_publish.py --list` / `--tables` 打包发布，客户端拉取热更后才会生效。

### 方式 B：用命令行 `wf_char_editor.py` 导出 JSON 修改

#### 第 1 步：导出目标角色的完整可读 JSON

- **做什么**：在工具仓根目录运行：
  ```powershell
  python wf_char_editor.py export <角色中文名或ID> --out work/char_edit
  ```
- **预期看到什么**：在 `work/char_edit` 下生成该角色的 `.json` 文件，终端打印导出的文件路径。
- **不对怎么办**：若提示找不到角色，改用准确的数字角色 ID 再试。

#### 第 2 步：编辑 JSON 并先做干跑检查（`--dry-run`）

- **做什么**：用文本编辑器打开导出的 JSON，修改里面的 `status`（`hp` / `atk`）数值并保存，然后先加 `--dry-run` 预演：
  ```powershell
  python wf_char_editor.py apply work/char_edit/<导出的文件名>.json --dry-run
  ```
- **预期看到什么**：终端清晰列出将要变更的表、键和旧值→新值对比，且提示未实际写盘。
- **不对怎么办**：如果对比出的列或数值不是你预期的，回到 JSON 修正；确认完全正确后，去掉 `--dry-run` 再运行一次即可写入 `paths.store`（同样会自动生成 `.bak-wfmod-*` 备份）。底层全表 CSV 导入导出用法另见 [`WF_mod_tool_usage.md`](../../WF_mod_tool_usage.md)。

## 六、任务三：用 YAML 平衡配方批量改数值

如果你要把一批词条数值改动保存成可重复检查的配方文件（参考 [`recipes/README.md`](../../recipes/README.md)）：

### 第 1 步：只读干跑校验配方旧值

- **做什么**：编写好 YAML 配方后，先不带 `--write` 执行校验：
  ```powershell
  python -m wf balance <配方路径.yml>
  ```
- **预期看到什么**：所有单元格旧值核对与 629 动作门禁通过，命令退出码为 `0`。
- **不对怎么办**：
  - 报旧值不匹配：说明当前视图里该格子的现有数值与配方里的预期旧值不一致，先核对基线版本是否选错。
  - 报不支持改文本列：`wf balance` 只允许改数值/配置列，主动技能名、技能描述（`action_skill` 的 `c0/c1`）与 `custom_ability_string` 请改用 `python -m wf text` 或 Studio 编辑台。

### 第 2 步：写出标准变更集

- **做什么**：确认干跑无误后，加上 `--write` 产出变更集：
  ```powershell
  python -m wf balance <配方路径.yml> --write --output work/m1/balance/<任务名>
  ```
- **预期看到什么**：在 `work/m1/balance/<任务名>` 下生成标准变更集与产物，可继续交给 `python -m wf deliver` 出包。
- **不对怎么办**：提示输出目录非空时，换一个新的 `<任务名>` 目录，不要覆盖旧产物。

## 七、词条移植 6 条铁律与常见闪退速查

从别的角色身上借词条时，必须遵守以下 6 条铁律（详见 [`角色改动规律方案.md`](../角色改动规律方案.md) 与 [`新角色制作心得.md`](../新角色制作心得.md)）：

1. **只借同表有玩家角色先例的词条**：战斗里能算不代表角色详情页能画出来。把没有队长先例的效果（如 `720`/`722`、`689`、触发 `198`）塞进 `leader_ability`，一点开详情页就会报 `F1009` 闪退；把队长专属 `trigger=2（开幕）` 行塞进角色 `ability` 表则会报 `U0000`。
2. **只借同属性角色的词条（或完整替换全部属性字段）**：跨属性硬搬词条会拼出非法描述串触发 `U0000`；带队伍属性共鸣（`kind=2`）的行不要粗暴把 `2` 改成 `0`，应保留结构并把属性英文名（`Red/Blue/Yellow/Green/White/Black`）和元素编号整套换成目标属性。
3. **跨表搬运必须做列号平移，换效果必须清空旧伴随列**：`ability`（126 列）与 `leader_ability`（124 列）差 2 列，绝不能原列号直接粘贴；更换效果 `kind` 时，必须把旧效果残留的伴随列改回 `(None)` 或 `0`。
4. **固有状态与贯通组件必须成组搬运**：固有状态（`461`）的「赋予行 + 判定行 + 消耗行」必须整组搬运并使用同一个不冲突的 `unique_condition_id`；判断固有状态**叠层数**必须用前置代码 **`144`**（`188` 数的是状态实例个数，恒为 1，填大于 1 永远不触发）。
5. **`629`（发动技能动作）词条必须配齐文案键并过 DSL 门禁**：`629` 行填写的 `string_id` 必须在 `custom_ability_string` 表里存在，漏注册会报 `C8601`（游戏弹窗误报“资源文件已损坏”）；同时被引用的动作树不得包含 `RemoveEvent`、`SetPowerFilpSuppress`、`NotifyPowerflipEnd`、`Wait` 四类锁死强化弹射生命周期的指令（`wf deliver` 与 `wf balance` 会自动拦截）。
6. **先拆共享键再改**：如果多个角色共用同一个 `ability` 或 `action_skill` 键，直接改会把别的角色一起改掉；务必先为目标角色分配独立新键。

### 常见报错与闪退速查表

| 现象或崩溃码 | 最常见原因 | 解决办法 |
|---|---|---|
| `C7050` | 枚举列留了空字符串 `""`、填了越界数字（如角色属性填了 `6` 无属性），或客户端 APK 未装对应补丁却读到了扩展码（如 `724`、`422–424`） | 把空串改为 `(None)` 或合法枚举；可玩角色属性只能是 `0..5`；核对 `--client-profile` |
| `C7101` | 效果块的布尔列（`true/false`）或乘算伴随列留了空串 | 对照同 `kind` 的官方先例行补齐 `false` 或 `(None)` |
| `C2308` | 持续词条（`trigger=1`）的第 85 列误填了 `'0'` | 改成 `(None)` |
| `C2268` | 修改 `character_status` 时增删或打乱了 `1/10/80/100` 等级断点 | 恢复该角色原本的 4 个等级键顺序 |
| `C8601`（提示“资源文件已损坏”） | 实际是 `string_id` 未在 `custom_ability_string` 注册，或热更缺了关联表 | 在「文案」页或 `custom_ability_string` 补齐对应键并一起打包 |
| `F1009` | `leader_ability` 使用了无玩家队长先例的 `kind` 或触发器 | 把该词条移到角色被动 `ability` 槽，换有先例的队长词条 |
| `U0000` | 跨属性搬词条导致自动描述器崩溃、`Opening` 行进了 `ability` 表，或带换行的 CSV 被按行切碎 | 换同属性先例行，或在 `custom_ability_string` 为该槽写合规的 `desc_override_<c0>` |
