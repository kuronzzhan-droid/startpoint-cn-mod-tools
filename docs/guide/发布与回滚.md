本手册面向 Windows 新手。按场景说明如何把改好的角色、词条或数据包安全地上线到本机服务端，以及上线后出现问题时如何无损回滚。

## 一、动手前必知：3 条发布与回滚铁律

1. **热更版本号永远只进不退（绝不能删包复用旧版本号）**：
   一旦某个版本（例如 `1.4.250 → 1.4.251`）已经被任何一台手机或模拟器下载过，绝对不能把服务端退回 `1.4.250` 再重发一个同名 `1.4.251`。已经升到 `1.4.251` 的客户端不会重下同名版本。正确的回滚永远是**把旧数据重新打成更高一版（例如 `1.4.251 → 1.4.252`）发出去**，让客户端正常往前更新覆盖回来。
2. **单包体积上限 5 MiB，且三层目录不能混放**：
   每个热更 ZIP 压缩后不超过 5 MiB（超限由工具按 `-1-`、`-2-` 自动拆包）。客户端资源分 `common`（`archive-common-diff`）、`medium`（`archive-medium-diff`）、`android`（`archive-android-diff`）三层，部署时必须保持三层子目录对应，不能把所有 ZIP 混丢进同一个文件夹。
3. **回滚只回退资源包与服务端静态配置，不会降级玩家数据库存档**：
   如果新版本上线了新角色或新武器，且已有账号抽到并编入了队伍，回滚删掉该角色的定义表会导致该账号读档报错。因此**正式上线前务必先跑隔离预演**。

## 二、四条发布路线怎么选

| 你的场景 | 推荐路线 | 是否需要停服 | 回滚方式 |
|---|---|---|---|
| 用 Studio 编辑台或 `wf balance` 改了草稿/变更集，想先安全验包 | **路线 1：本地交付 + 本地服隔离预演** | 预演不动原服 | 直接丢弃隔离预演沙盒目录 |
| 已有封口工作区或 `.wf-release.zip` 发行包，要装到本机受管服务端 | **路线 2：`wf_release_v1` 受管安装** | 工具自动停启或要求停服 | `wf_release_v1 rollback` / `rollback-legacy` |
| 用 `wf_gui.py` 或 `wf_mod_tool.py` 直接改了 `paths.store` 单表，想快速打热更边 | **路线 3：`wf_publish.py` 裸表增量发布** | 建议停服（dev 服需重跑同步） | 还原 `.bak-wfmod-*` 备份后再发更高版本号新边 |
| 用 `wf_character_flow.py` 做好了完整四层角色包，要直发生产账本 | **路线 4：`wf_character_flow.py` 原子上线** | **必须先停服** | `wf_character_flow.py rollback` 发前滚快照边 |

> 说明：仓库根目录的 `wf_scoped_release.py`、`wf_local_scoped_release.py`、`wf_character_pack.py`、`wf_character_rollback.py` 是内部调用的 Python 库模块，不直接作为命令行入口运行。

## 三、路线 1：变更集本地交付与本地服隔离预演（日常首选）

Studio 编辑台和 `wf deliver` 只在工具仓 `work/` 内生成候选交付包，绝不直接改写你的线上服务端或 CDN。

### 第 1 步：生成本地候选交付包

- **做什么**：
  - 如果你的改动在 **Studio 编辑台草稿**里，在工具仓根目录运行：
    ```powershell
    python -m wf.studio.draft --view <视图名> build <角色ID> --from <当前版本号> --to <目标新版本号> --out work/studio-deliveries/<交付名> --server-dir <服务端目录> --client-profile <客户端档案名>
    ```
  - 如果你的改动是 **`wf balance` 或 `wf text` 产出的 `changeset.json`**，运行：
    ```powershell
    python -m wf deliver <changeset.json路径> --baseline-manifest <manifest.json路径> --base-store <基准store目录> --out work/m1/deliver/<交付名> --server-dir <服务端目录> --client-profile <客户端档案名>
    ```
- **预期看到什么**：命令退出码为 `0`；输出目录必须事先为空，完成后里面会生成热更分包 ZIP、`manifest-entry.json`、`patches/<目标新版本号>/patch-manifest.json`、`server/` 服务端暂存镜像以及预检报告。
- **不对怎么办**：
  - 报输出目录已存在或非空：换一个新的 `<交付名>`，工具为防误覆盖不会清空旧目录。
  - 报 `compat` 或 `dsl-629` 阻断：按终端提示打开输出目录下的 `check.json` / `compat.json`，修掉客户端不支持的效果码或违规 DSL 指令后重跑。

### 第 2 步：核查共享表键级差异（防串改别的角色）

- **做什么**：对刚刚生成的 `common` 层热更 ZIP 跑一次键级归属审计：
  ```powershell
  python -m wf.studio.draft --view <视图名> key-diff --zip <交付目录中的common层.zip> --subject <角色ID>
  ```
- **预期看到什么**：输出 JSON 中改动键全部归类为 `owned`（当前角色自用），`foreign`（他人键）为空。
- **不对怎么办**：只要 `foreign` 不为空，说明这次打包把其他角色或武器的表行也改掉了，**立即停止上线**，回到草稿排查是否误改了共享键（详见 [`studio/key-diff.md`](../studio/key-diff.md)）。

### 第 3 步：在本地服隔离副本中预演并验证

- **做什么**：确认 `profiles/local.json` 中已配置 `servers.local.root`（指向本地测试服务端）及隔离沙盒路径，执行只读预演：
  ```powershell
  python -m wf.studio.draft rehearse --delivery-dir work/studio-deliveries/<交付名> --server local
  ```
  *(你也可以在 Studio 网页交付结果面板直接点击「在本地服预演」，或用 `python -m wf.deliver.assert_box --phase pre --manifest <交付目录>/delivery-manifest.json --store <store目录> --server-dir <服务端目录>` 核验前置摘要。)*
- **预期看到什么**：工具把服务端变更与热更 ZIP 复制到一个带时间戳的**独立沙盒目录**，并生成 `rehearsal.json` 手工核验步骤单；原本地服目录一字未动。按步骤单启动隔离服并用客户端连接验证即可（真机联调标「未实测」）。
- **不对怎么办**：
  - 如果预演进游戏发现崩溃或数值不对：**回滚零成本**——直接关掉隔离服进程并删掉该时间戳预演沙盒目录，原服务端完好无损；回编辑台改好草稿重新 `build` 即可。

## 四、路线 2：用 `wf_release_v1` 构建、安装与回滚受管服务端

当你要把封口好的工作区打包成标准 `.wf-release.zip` 发行包，并带事务保护地安装到本机服务端时，使用 `wf_release_v1`（详见 [`wf-release-v1-local-install.md`](../wf-release-v1-local-install.md)）。

### 第 1 步：（可选）打开本机只读工作台做可视化准备

- **做什么**：在工具仓根目录运行：
  ```powershell
  python -X utf8 wf_release_ui.py --open
  ```
- **预期看到什么**：终端启动本机回环网页服务并自动在浏览器打开十阶段发行准备台（只读检查、生成覆盖层、捕获依赖与预演安装计划，不含直写线上按钮；浏览器实操标「未实测」）。
- **不对怎么办**：若浏览器未自动弹出，复制终端打印的 `http://127.0.0.1:<端口>` 手动打开。

### 第 2 步：生成覆盖层、捕获依赖并打包 `.wf-release.zip`

- **做什么**：依次对已封口的工作区（`<工作区目录>`）和目标服务端描述文件（`<target.json>`，写法参考 [`examples/wf-release-target.windows.json`](../examples/wf-release-target.windows.json)）执行以下 4 条命令：
  ```powershell
  python -X utf8 -m wf_release_v1 build-overlay --workspace <工作区目录> --from-version <起始版本> --target-version <目标版本> --output work/release_v1/overlay --json
  python -X utf8 -m wf_release_v1 capture-requirements --target <target.json> --workspace <工作区目录> --output work/release_v1/requirements.json --json
  python -X utf8 -m wf_release_v1 build --workspace <工作区目录> --overlay work/release_v1/overlay --requirements work/release_v1/requirements.json --name <发行包英文名> --version <语义版本号如1.0.0> --output work/release_v1/<包名>.wf-release.zip
  python -X utf8 -m wf_release_v1 verify --release work/release_v1/<包名>.wf-release.zip --json
  ```
- **预期看到什么**：`verify` 输出的 JSON 显示归档门禁、清单门禁与语义门禁全部通过，退出码为 `0`。
- **不对怎么办**：根据 `verify` JSON 中的错误字段修正工作区所有权声明或版本范围，未通过 `verify` 的包切勿安装。

### 第 3 步：探测目标服务端并预演安装计划

- **做什么**：
  - 若目标服务端是首次纳入受管模式，先停服执行一次初始化纳管：`python -X utf8 -m wf_release_v1 bootstrap --target <target.json> --confirm BOOTSTRAP_WF_TARGET`（本机服务端交互标「未实测」）。
  - 每次安装前，先跑只读探测与安装计划预演：
    ```powershell
    python -X utf8 -m wf_release_v1 probe --target <target.json> --json
    python -X utf8 -m wf_release_v1 plan-install --target <target.json> --release work/release_v1/<包名>.wf-release.zip --json
    ```
- **预期看到什么**：`probe` 正常识别服务端能力契约，`plan-install` 返回无所有权冲突、无基线版本断裂的可执行计划。
- **不对怎么办**：若报基线版本不匹配，检查 `build-overlay` 填的 `--from-version` 是否等于目标服务端当前的资源链尾版本。

### 第 4 步：执行原子安装

- **做什么**：
  - **标准受管目标**：
    ```powershell
    python -X utf8 -m wf_release_v1 install --target <target.json> --release work/release_v1/<包名>.wf-release.zip --confirm INSTALL_WF_RELEASE
    ```
  - **旧服过渡目标（Legacy Transition）**：
    ```powershell
    python -X utf8 -m wf_release_v1 install-legacy --target <target.json> --release work/release_v1/<包名>.wf-release.zip --confirm INSTALL_LEGACY_RELEASE
    ```
- **预期看到什么**：命令完成事务提交并输出安装回执（含操作 ID 与当前发行包标识；本机服务端实装标「未实测」）。
- **不对怎么办**：如果安装中途失败中断，记下输出里的 `operation` 操作 ID，立即按第 5 步执行失败事务恢复。

### 第 5 步：故障恢复与版本回滚

- **做什么**：按你遇到的情况三选一执行（本机服务端实装标「未实测」）：
  1. **安装中途报错中断，需清理恢复现场**：
     ```powershell
     python -X utf8 -m wf_release_v1 rollback --target <target.json> --operation <失败的操作ID> --confirm RECOVER_FAILED_INSTALL
     ```
  2. **安装已完成，但想退回上一个已安装的受管发行包**：
     ```powershell
     python -X utf8 -m wf_release_v1 rollback --target <target.json> --to-release <上一个发行包标识> --confirm I_UNDERSTAND_DATA_DOWNGRADE_RISK
     ```
  3. **旧服过渡目标退回前一条版本边**：
     ```powershell
     python -X utf8 -m wf_release_v1 rollback-legacy --target <target.json> --to-release <目标版本> --confirm ROLLBACK_LEGACY_RELEASE
     ```
  *(若服务端因维护处于受管暂停态，恢复完成后用 `python -X utf8 -m wf_release_v1 resume --target <target.json> --confirm RESUME_WF_TARGET` 重新拉起。)*
- **预期看到什么**：命令退出码为 `0`，目标状态切回上一稳定版本。
- **不对怎么办**：确认口令必须全大写原样输入；回滚前请确认没有玩家存档强依赖刚刚下线的新角色 ID。

## 五、路线 3：用 `wf_publish.py` 快速发布单表改动与前滚回退

当你用 `wf_gui.py`、`wf_char_editor.py` 或 `wf_mod_tool.py` 直接修改了 `paths.store` 里的表文件，需要打一条增量热更边到本地 CDN 时使用此路线。

### 第 1 步：（仅限角色包共存时）按键级推送，防止整表覆盖回退

- **做什么**：如果你要微调的角色原本存放在 `work/character_packs/<包标识>` 里，**不要**把角色包里的整张表直接拷进 `store`（那会把别家角色新改的行退回旧快照）。先不带 `--apply` 预演键级推送，核对无误后加 `--apply`：
  ```powershell
  python wf_pack_push_keys.py --workspace work/character_packs/<包标识> --key <逻辑表路径>:<键1>,<键2>
  python wf_pack_push_keys.py --workspace work/character_packs/<包标识> --key <逻辑表路径>:<键1>,<键2> --apply
  ```
- **预期看到什么**：终端只替换你点名的那几个键，其余所有键保留 `store` 现有原始字节并打印前后对照。
- **不对怎么办**：若提示找不到键或逻辑路径错误，核对表路径拼写（例如 `master/ability/ability.orderedmap:1299911`）。

### 第 2 步：预览待发布清单并过客户端能力门禁

- **做什么**：在打包前，先查看待发布内容并校验目标客户端兼容性：
  ```powershell
  python wf_publish.py --list
  python wfx_gate.py check --client-profile <客户端档案名> --tables <逗号分隔的表别名或逻辑路径>
  ```
- **预期看到什么**：`--list` 列出本次将打包的表与起始版本号；`wfx_gate.py check` 通过且无报错。
- **不对怎么办**：
  - 报“线上已有的键会消失”：说明你本地 `store` 的这张表比 CDN 现网最新版本少了键（极大概率是基准过期），**严禁盲目加 `--allow-key-deletion`**，先同步最新基准表后再改。
  - 报 `wfx_gate` 不兼容：说明表里写了目标 `--client-profile` 不认识的 `wfx:` 效果码或扩展枚举，详见 [`客户端补丁与APK.md`](客户端补丁与APK.md)。

### 第 3 步：打包发布到本地 CDN

- **做什么**：运行发布命令铸造新的版本边（默认会自动补齐无变更层的 `.empty` 占位包并更新 `dev` 目录清单）：
  ```powershell
  python wf_publish.py --tables <逗号分隔的表别名或逻辑路径> --client-profile <客户端档案名>
  ```
- **预期看到什么**：终端打印新生成的 `pinball-<旧版>-<新版>-...zip` 文件路径与版本号（本机 CDN 实写标「未实测」）。
- **不对怎么办**：如果你的服务端是上游 `dev` 分支（启动前编译路径），发包后还需在服务端目录执行其 `content:sync` 同步流程并重启服务端，客户端才能拉到新版本。

### 第 4 步：改错了怎么回滚（前滚新版本）

- **做什么**：
  - **网页方式**：打开 `python wf_gui.py`，进入「备份/改动日志」页面，找到刚才修改前的 `.bak-wfmod-*` 记录执行回溯，并再次发布一条**更高版本号**的热更边（浏览器实操标「未实测」）。
  - **手工方式**：在 `<数据包upload目录>` 中把对应表文件的 `.bak-wfmod-<改前时间戳>` 备份覆盖回原哈希文件名，然后再次运行第 3 步的 `python wf_publish.py --tables <表名> --client-profile <客户端档案名>`。
- **预期看到什么**：CDN 新增一条版本号 `+0.0.1` 的热更包，客户端重登下载后数值恢复为改前状态。
- **不对怎么办**：**切勿手工去 `.cdn/cn/archive-*-diff/` 里直接删掉刚发的 ZIP**——已经下载过该版本的客户端会因为本地版本号高于服务端而卡死或无法同步。

## 六、路线 4：用 `wf_character_flow.py` 停服发布成品角色包与快照回滚

### 第 1 步：对齐账本基线并停止服务端

- **做什么**：
  1. 如果上次用 `wf_character_flow.py` 发包之后，你曾用路线 3 的 `wf_publish.py` 单发过裸表边，角色账本 `active.json` 的基线会落后于 CDN 链尾。此时先对齐账本：
     ```powershell
     python wf_character_flow.py reanchor --confirm REANCHOR_CHARACTER_LEDGER
     ```
  2. **彻底停止正在运行的服务端进程**（运行中会被发布锁拒绝）。
- **预期看到什么**：`reanchor`（若需执行）返回成功 JSON，服务端端口已停止监听。
- **不对怎么办**：若提示未配置服务端或 CDN 路径，先检查 `profiles/local.json`。

### 第 2 步：执行原子发布并保存快照路径

- **做什么**：运行正式发布命令（必须带大写确认口令 `PUBLISH_CHARACTER_PACKAGE`）：
  ```powershell
  python wf_character_flow.py publish --workspace work/character_packs/<包标识> --client-profile <客户端档案名> --confirm PUBLISH_CHARACTER_PACKAGE
  ```
- **预期看到什么**：终端输出发布成功的 JSON，其中包含 **`snapshot_dir`**（自动保存在 `work/character_releases/snapshots/` 下的前像快照目录）和已安装包目录。**请立刻复制记下这个 `snapshot_dir` 路径**（本机停服实发标「未实测」）。
- **不对怎么办**：提交点 `active.json` 替换之前若任何门禁失败，工具会自动回退现场，无需手工删文件；按报错修好角色包重跑 `preflight` 即可。

### 第 3 步：故障时用前像快照执行前滚回滚

- **做什么**：先**停止服务端进程**，然后用第 2 步记下的 `<快照目录>` 执行回滚：
  ```powershell
  python wf_character_flow.py rollback --snapshot-dir <快照目录> --installed-package-dir <当前已安装包目录> --confirm ROLLBACK_CHARACTER_PACKAGE
  ```
- **预期看到什么**：工具校验现场未漂移后，将快照前像作为一条**更新版本号的 `*-rollback` 增量边**发布到 CDN 并更新 `active.json`，随后可重启服务端（本机停服实测标「未实测」）。
