## 一、动手前必知：自备材料与 4 条铁律

> 注意：仓库早期文档（如 `角色生成器使用说明.md`）中提到的 `wf_char_gen.py` AI 生成器**并未合入本仓库**，请不要寻找或运行该脚本。现行制作新角色统一走下文的 **Studio 编辑台克隆流**（推荐）或 **`wf_character_flow.py` 角色包流**。

### 1. 你需要自备什么

本仓库不包含官方游戏资源，也不提供任何下载渠道。开始前请确认本机已自备以下内容：

1. **已配置好的 [`profiles/local.json`](../../profiles/README.md)**：指向你自备的只读基准数据包（`store` 或 `store131`）与补丁链清单。
2. **完整的服务端数据目录（`<服务端目录>`）**：新角色必须同步生成服务端数据，该目录下的 `assets/` 内必须同时存在以下 5 张 JSON 表：
   - `character.json`
   - `cdndata/character.json`
   - `cdndata/character_text.json`
   - `mana_node.json`
   - `mana_board.json`
3. **你自制的美术与语音源文件**：
   - 普通态与觉醒态透明背景立绘 PNG 各 1 张（建议正方形大画布透明底，方便裁切脸部锚点）。
   - 像素小人帧图（PNG 序列、网格精灵图，或现成的 `pixelart` / `special` 四件套）。
   - 语音音频（`.wav` 或 `.mp3`），并在本机装好 `ffmpeg`（加入系统 `PATH`，或设置环境变量 `WF_FFMPEG` 指向 `ffmpeg.exe`）。

### 2. 做新角色 4 条硬性铁律

1. **母本必须同星级、同属性**：克隆器强制新角色继承母本的星级和属性（`0` 火、`1` 水、`2` 雷、`3` 风、`4` 光、`5` 暗），不支持跨星级或跨属性克隆；可玩角色属性也绝不能写 `6`（无属性，进图必闪退）。
2. **玛纳板节点号必须按 `新角色ID × 2` 重映射**：客户端会从玛纳节点 ID 反推角色 ID。漏改或填错节点前缀，在游戏里一点开玛纳板就会报 `H400` 踢回标题界面（使用克隆命令会自动完成重映射）。
3. **37 项必需资产缺一不可（★4/★5 必带 `special` 动作，安卓切入图必编 ATF）**：
   - ★4 与 ★5 角色在抽卡/邮件领取演出中硬性调用 `special_land` 和 `special_pose` 两个像素动作，缺失会导致领取时直接报错崩溃（★1–★3 自动豁免 4 项 `special` 文件）。
   - 技能特写（`skill_cutin`）在 Android 客户端上只读取 `android` 层的 `.atf.deflate`（ETC1 纹理），只换 PNG 在真机上不会生效。
4. **主页语音必须覆盖觉醒前/后两态，音频必须是 96k CBR MP3**：`character_speech` 表中主页台词（`kind=0`）必须同时有觉醒前可见行和觉醒后可见行，缺一态会报 `C2265`；音频必须为 **44.1kHz、单声道、96kbps CBR（固定码率，无 Xing 头）**。

## 二、路线 A：用 Studio 编辑台克隆并制作新角色（推荐新手）

这条路线全程在 `work/studio-drafts/<新角色ID>/` 草稿目录内工作，不改动你的原始数据包和服务端目录。

### 第 1 步：检查服务端五张必需表是否就位

- **做什么**：在工具仓根目录打开 PowerShell，把 `<服务端目录>` 换成你自己的服务端根目录路径，运行以下命令：
  ```powershell
  @(
    "<服务端目录>/assets/character.json",
    "<服务端目录>/assets/cdndata/character.json",
    "<服务端目录>/assets/cdndata/character_text.json",
    "<服务端目录>/assets/mana_node.json",
    "<服务端目录>/assets/mana_board.json"
  ) | ForEach-Object { "$_ : $(Test-Path $_)" }
  ```
- **预期看到什么**：5 行输出末尾全部都是 `True`。
- **不对怎么办**：只要有一行是 `False`，先检查 `<服务端目录>` 是否指到了包含 `assets` 子目录的那一层；缺表时虽然能建草稿，但最后构建交付包一定会被阻断。

### 第 2 步：查询空闲的新角色 ID、玛纳节点段与版本号

- **做什么**：运行只读 ID 查询命令，让工具同时扫描客户端视图、服务端镜像与本机所有草稿，挑出一个完全没被占用的角色 ID（例如在 `119901` 附近找）和下一个资源版本号：
  ```powershell
  python -m wf.studio.draft --view <视图名> --server-dir <服务端目录> ids next character --near 119901
  python -m wf.studio.draft --view <视图名> --server-dir <服务端目录> ids check mana_node <选定的新角色ID>
  python -m wf.studio.draft --view <视图名> versions next
  ```
- **预期看到什么**：
  - `ids next character` 输出一行 JSON，给出空闲的数字 ID；
  - `ids check mana_node` 返回该角色对应的 `新角色ID × 2` 玛纳节点段未被占用；
  - `versions next` 返回下一个可用的 `1.4.<数字>` 版本号。
- **不对怎么办**：如果某个 ID 提示已被占用或玛纳节点段冲突，换一个数字重新跑 `ids check`，切勿强行复用已有角色 ID。

### 第 3 步：从同属性、同星级官方母本创建克隆草稿

- **做什么**：选好与新角色**同属性、同星级**的官方母本角色 ID（例如 `<母本ID>`），先加 `--preview` 预演，确认无报错后去掉 `--preview` 正式建草稿（`--code` 填纯小写字母和下划线组成的内部英文代号，`--skill copy` 表示为新角色创建独立技能键）：
  ```powershell
  python -m wf.studio.draft --view <视图名> --server-dir <服务端目录> character clone --from <母本ID> --to <新角色ID> --code <英文代码名> --skill copy --name "<角色中文名>" --preview
  python -m wf.studio.draft --view <视图名> --server-dir <服务端目录> character clone --from <母本ID> --to <新角色ID> --code <英文代码名> --skill copy --name "<角色中文名>"
  ```
  *(可选：如果美术想在还没定正式 ID 时先画像素，可用 `scratch-new --name "<名字>" --element <火|水|雷|风|光|暗> --base <母本ID>` 建无编号草稿，定稿后再用 `scratch-promote <scratch目录名> --to <新角色ID> --code <英文代码名>` 转正。)*
- **预期看到什么**：终端输出一行成功 JSON，并在 `work/studio-drafts/<新角色ID>/changeset.json` 生成新角色草稿（自动派生独立队长技键、被动能力槽键与重编号后的玛纳板）。你也可以在 Studio 网页（`python -m wf.studio --view <视图名> --server-dir <服务端目录>`，浏览器打开 `http://127.0.0.1:8790`）的「角色工坊 → 新建角色」界面完成这一步。
- **不对怎么办**：
  - 报 `element 必须等于母本` 或拒绝跨星级：换一个属性和星级都与你规划一致的官方角色做母本。
  - 报目标 ID 已存在：回到第 2 步换一个新的空闲 ID。

### 第 4 步：导入普通/觉醒立绘并自动派生 30 项 UI 图与 ATF

- **做什么**：
  - **网页方式（推荐，方便拖脸部中心点）**：在编辑台打开该新角色，进入「立绘」页，分别上传普通立绘（形态 `0`）和觉醒立绘（形态 `1`），拖动取景框对准脸部，点击保存派生（浏览器实操标「未实测」）。
  - **命令行方式**：依次上传并按默认裁剪模板派生形态 `0` 和形态 `1`（**不要**加 `--no-atf`，让工具一并生成安卓 `skill_cutin` 的 ETC1 ATF 纹理）：
    ```powershell
    python -m wf.studio.draft --view <视图名> portrait-info <新角色ID> --form 0 --upload <普通立绘.png>
    python -m wf.studio.draft --view <视图名> portrait <新角色ID> --form 0 --template-from upload
    python -m wf.studio.draft --view <视图名> portrait-info <新角色ID> --form 1 --upload <觉醒立绘.png>
    python -m wf.studio.draft --view <视图名> portrait <新角色ID> --form 1 --template-from upload
    ```
- **预期看到什么**：命令返回成功 JSON，草稿内生成双形态共 26 张立绘/头像/切入图及 ATF、共享图集和 3 张坐标定位表（`trimmed_image`、`character_image`、`full_shot_image_attribute`）。在网页右上角「资源」抽屉中，立绘相关条目从「复用母本」变为「已派生」。
- **不对怎么办**：
  - 输入图片不是透明底 PNG：游戏内角色立绘背景会带白底色块，请换成 RGBA 透明背景 PNG 重新上传。
  - 头像或队伍长条图切到了胸口而非脸：打开 Studio 网页「立绘」页，手动拖动脸部锚点后重新点保存。

### 第 5 步：替换像素小人并做工艺预检

- **做什么**：
  - 如果你准备的是**现成四件套文件夹或压缩包**（含 `sheet / atlas / frame / timeline`），分别导入普通动作族 `pixelart` 和（★4/★5 必填的）必杀动作族 `special`：
    ```powershell
    python -m wf.studio.draft --view <视图名> pixel-import <新角色ID> --dir <pixelart四件目录> --family pixelart
    python -m wf.studio.draft --view <视图名> pixel-import <新角色ID> --dir <special四件目录> --family special
    ```
  - 如果你准备的是**单动作序列帧 PNG 或精灵网格图**，用 `pixel` 子命令逐动作导入（或直接在网页「像素」页可视化导入、拆解或调色映射）：
    ```powershell
    python -m wf.studio.draft --view <视图名> pixel <新角色ID> --family pixelart --action walk --frames <帧1.png> <帧2.png> --duration 6
    ```
  - 导入后，可在网页「像素」分组打开「批量预检」「场地比例」「图集重排」核查身高比例与图集面积；或用独立只读预览器检查散帧动画：
    ```powershell
    python -X utf8 wf_preview_2d.py <本地序列帧目录> --describe
    ```
- **预期看到什么**：命令返回成功 JSON；★4/★5 角色的 `special` 族包含 `special_land` 与 `special_pose` 两个动作，且单张像素图集宽高不超过 `4094`、加边距面积不超过预算上限。
- **不对怎么办**：
  - 报图集面积超限（> `1000000 px` 阻断）：缩小画布空白边缘或在编辑台「图集重排」页重新紧凑排布（三人联机房共享纹理预算，过大会导致联机黑块或闪退）。
  - ★4/★5 角色漏做 `special_land` / `special_pose`：务必补齐这两个动作，否则玩家在邮箱或抽卡界面获得该角色时必崩。

### 第 6 步：导入语音并核查主页两态台词

- **做什么**：
  1. 先在 PowerShell 确认 `ffmpeg` 可用，再查看该角色可替换的语音槽位：
     ```powershell
     ffmpeg -version
     python -m wf.studio.draft --view <视图名> voice-lines <新角色ID>
     ```
  2. 在网页「语音」页编辑 `character_speech` 五列台词（确保主页 `kind=0` 同时保留觉醒前和觉醒后可见台词）并上传音频；或用命令行逐条替换语音（工具会自动调用 `ffmpeg` 做响度归一化并转成 44.1kHz 单声道 96kbps CBR MP3）：
     ```powershell
     python -m wf.studio.draft --view <视图名> voice <新角色ID> --line home/home_0 --audio <语音文件.wav>
     ```
- **预期看到什么**：`ffmpeg -version` 正常打印版本信息；`voice` 命令返回成功 JSON，草稿内写入合规的无 Xing 头 CBR MP3。
- **不对怎么办**：
  - 报找不到 `ffmpeg`：安装 `ffmpeg` 后重启 PowerShell，或设置 `$env:WF_FFMPEG = "<ffmpeg.exe完整路径>"`。
  - 报 `character_speech` 缺觉醒前/后可见行：在网页「语音」页为主页台词补齐觉醒前与觉醒后两态条目，避免客户端报 `C2265`。

### 第 7 步：（按需）调整技能模板、召唤物与文案

- **做什么**：在同一份新角色草稿中，你可以进入网页「文案」「技能 → 技能模板」「技能 → 强化弹射动作」或「技能 → 召唤角色」（命令行 `python -m wf.studio.draft summon templates` / `summon <新角色ID> --request <请求JSON>`）配置技能倍率、召唤物和角色文案；最后在「交接单」标签页总览 37 项资产状态。
- **预期看到什么**：「资源」抽屉与「交接单」页全部必需项状态正常，无阻断红灯（浏览器实操标「未实测」）。
- **不对怎么办**：
  - **特别注意**：新克隆角色首包草稿**不支持同时叠加 `ability_edit`（一/二/三板与队长技词条改写）**。如果你要精改新角色的被动词条或队长技，请先完成第 8 步把新角色首包交付入链，随后按「修改已有角色」打开 [`改词条与数值.md`](改词条与数值.md) 编辑词条。

### 第 8 步：复核草稿并生成本地交付包

- **做什么**：先运行 `save` 做整包哈希与结构复核，再运行 `build` 生成本地交付包（克隆角色**必须传 `--server-dir`**；若有目标客户端 APK，建议一并传 `--apk` 做内置表撞名检查）：
  ```powershell
  python -m wf.studio.draft --view <视图名> save <新角色ID>
  python -m wf.studio.draft --view <视图名> build <新角色ID> --from <当前版本号> --to <目标新版本号> --out work/studio-deliveries/<新角色英文名> --server-dir <服务端目录> --client-profile <客户端档案名>
  ```
- **预期看到什么**：命令退出码为 `0`，在 `work/studio-deliveries/<新角色英文名>` 下生成客户端分包 ZIP、`manifest-entry.json`、`server/` 五表同步镜像，以及 `check.json`、`compat.json`、`key-diff.json`、`icon-alpha.json`、`client-extensions.json` 等守卫报告。
- **不对怎么办**：
  - 报 `key-diff` 出现 `foreign`（改动了别家角色的键）：说明误改了共享键，回到草稿检查是否把 `--skill` 设成了 `reuse` 又去改了共享条目。
  - 报 `C7051` / `bundle-check` 撞名：说明新增资产或键名与 APK 内置 Bundle 冲突，需更换 `--code` 或私有键名（详见 [`studio/bundle-keys.md`](../studio/bundle-keys.md)）。
  - 交付包生成后如何做本地服隔离预演、正式上线与回滚，请转到 [`发布与回滚.md`](发布与回滚.md)。

## 三、路线 B：用 `wf_character_flow.py` 管理成品角色包

如果你已经用外部脚本准备好了一整套四层成品目录（`common`、`medium`、`android`、`server`），需要走带锁的生产账本（`active.json`）直发流程，可使用 `wf_character_flow.py`（详见 [`角色包工作流.md`](../角色包工作流.md)）。

### 第 1 步：初始化角色包工作区

- **做什么**：在工具仓根目录运行：
  ```powershell
  python wf_character_flow.py init --template-id <母本ID> --character-id <新角色ID> --code-name <英文代码名> --package-id <包标识>
  ```
- **预期看到什么**：在 `work/character_packs/<包标识>/` 下创建标准工作区骨架，终端打印工作区路径。
- **不对怎么办**：报工作区已存在或参数格式错误时，确认 `--package-id` 使用不重名的纯英文数字下划线短名，且 `--character-id` 为纯数字。

### 第 2 步：放入四层资产并检查 37 项齐套状态

- **做什么**：将准备好的客户端三层与服务端文件放入 `work/character_packs/<包标识>/package/` 对应子目录后，执行状态检查：
  ```powershell
  python wf_character_flow.py status --workspace work/character_packs/<包标识>
  ```
- **预期看到什么**：输出报告显示必需资产齐套（★4/★5 为 `37/37`），且不存在被禁止混入的 `story`、`words`、`login`、`episode_banner` 目录。
- **不对怎么办**：按终端列出的 `missing` 缺失项逐一补齐真实资产，切勿拿其他角色的无关文件重命名充数。

### 第 3 步：执行上线前预检与基线对齐

- **做什么**：如果线上共享表在你制作期间有更新，先跑 `rebase` 对齐最新共享表，再跑 `preflight` 全量门禁预检：
  ```powershell
  python wf_character_flow.py rebase --workspace work/character_packs/<包标识>
  python wf_character_flow.py preflight --workspace work/character_packs/<包标识>
  ```
- **预期看到什么**：`preflight` 全部引用检查、解析器合法性检查与客户端能力门禁通过，退出码为 `0`。
- **不对怎么办**：
  - 报角色账本基线落后于线上 `wf_publish` 链尾：需先执行 `reanchor` 对齐账本，再到停服窗口执行 `publish` 与快照回滚，完整步骤见 [`发布与回滚.md`](发布与回滚.md)。

## 四、新角色进游戏必测清单与崩溃速查

> 说明：以下真机/模拟器进游戏验证环节需配合你本机运行的服务端与客户端完成（本机真机实操标「未实测」）。每做一个新角色，请按顺序逐项打钩：

1. **登录与热更下载**：客户端能正常拉取新版本热更，不卡进度条、不报“数据不足”。
2. **获得角色演出**：通过发卡或邮箱领取新角色（★4/★5 重点看落地与摆姿势演出是否正常，不闪退）。
3. **角色一览与详情页**：打开角色列表、点进新角色详情页、切换普通/觉醒立绘、查看三板能力描述（验证无 `C7050` / `F1009` / `U0000`）。
4. **设为主页看板娘**：在主页点击角色播放语音，切换觉醒前/后形态各点一次（验证无 `C2265`）。
5. **点亮玛纳板**：进入玛纳板点亮节点并保存（验证无 `H400` 踢回标题）。
6. **编队与进战释放技能**：作为队长和作为合击（sub）各进一次战斗，释放主动技能（验证 Android 真机 `skill_cutin` 特写图像正常显示、技能不报 `C8601`）。

### 新角色专属高频崩溃码速查

| 现象或崩溃码 | 原因定位 | 修复方法 |
|---|---|---|
| 点玛纳板报 `H400` 踢回登录 | 玛纳板节点未按 `新角色ID × 2` 重编号，或服务端 `mana_node.json` / `mana_board.json` 未同步上线 | 重新用 `character clone` 派生并确认服务端五表已同步部署 |
| 领角色瞬间崩溃（日志含 `special_land` / `special_pose`） | ★4/★5 角色的 `special` 像素四件缺失，或时间轴里漏了 `special_land` / `special_pose` 标签 | 补齐 `special` 四件及这两个动作标签 |
| 设为主页角色或点开语音报 `C2265` | `character_speech` 表里 `kind=0`（主页台词）没有同时覆盖觉醒前与觉醒后可见态 | 补齐觉醒前和觉醒后均可见的主页台词行 |
| 热更后启动或进界面报 `C7051` | 新增表或资源路径与 APK 内置 AssetBundle 重名冲突 | 运行 `python -m wf.studio.draft bundle-check --apk <客户端APK> --delivery-dir <交付目录>` 定位撞名项并改名 |
| 放技能弹窗“资源文件已损坏”（`C8601`） | 技能或 `629` 引用的文案键未写进 `custom_ability_string`，或热更漏发了 `medium` / `android` 层分包 | 补齐文案键，确认三层热更包全部随 `manifest` 上线 |
| 放技能瞬间报 `U_f6da5a` | 技能 ActionDsl 单条 `CreateCondition` 里包含固有状态 `ACUnique` 且总条件数 ≥ 3 | 把该条指令拆成两条独立的 `CreateCondition`（每条条件数 ≤ 2） |
