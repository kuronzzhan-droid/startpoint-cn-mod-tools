# 游戏剧本导出器使用说明

`wf_story_export.py` 从 CN CDN store **只读**解码剧情 `scenario.orderedmap`，输出可读 Markdown 与逐指令 JSONL。它不会修改 store、`sync_pending.json`、CDN diff 或发布状态。

## 快速使用

在仓库根目录 `${WF_ROOT}\startpoint-cn` 运行：

```powershell
# 列出全部剧情或单一类别
python mod-tools/wf_story_export.py --list
python mod-tools/wf_story_export.py --list character_story_quest

# 单话；basename 有歧义时会列出候选并拒绝猜测
python mod-tools/wf_story_export.py --quest white_tiger_001
python mod-tools/wf_story_export.py --quest story_quest/main_chapter_01/main_chapter_01_01

# 角色可用 code、id 或 CN 名；按 identity_character_id 自动包含版本变体
python mod-tools/wf_story_export.py --character 白
python mod-tools/wf_story_export.py --character white_tiger
python mod-tools/wf_story_export.py --character 10

# 类别或全量导出
python mod-tools/wf_story_export.py --category story_event_quest
python mod-tools/wf_story_export.py --all

# 只做全量门禁，不创建输出目录
python mod-tools/wf_story_export.py --validate
```

通用参数：

- `--format md|jsonl|both`：默认 `both`。
- `--out <目录>`：默认 `mod-tools/work/story_export/`。
- `--store <upload目录>`：覆盖默认 `弹国服/WorldFlipper/dummy/download/production/upload`；目录不存在时立即失败，不扫描其他 profile 兜底。

导出前会先完成所选剧情的全部解码、渲染、临时写入与旧文件备份，再用同目录原子替换提交；提交中途失败会还原已替换文件，若回滚本身也失败则保留唯一 `.backup` 恢复件并在错误中给出精确路径。`--out` 等于或位于 store 内、剧情目录含 `.`/`..`、或目标叶子是 symlink/junction 时会拒绝执行，避免任何路径把输出重定向回只读 store。

正确的离线单测命令：

```powershell
python -m unittest discover -s mod-tools/tests -p "test_story_export.py" -v
# 或仓库 Python 全量回归
npm run test:python
```

## 输出布局与格式

每话写到：

```text
<out>/<category>/<scenario-relative-dir>/
├── scenario.md
└── scenario.jsonl
```

角色剧情 Markdown 标题为：

```markdown
# 白 个人剧情 第1话 「疑惑」
```

有声与无声对白示例：

```markdown
**阿尔克**🔊：久等了。\
　今天吃西红柿炖鸡肉哦。

**旁白**：夜深了。
```

- `🔊` 只在 `text_voice_path` 不是 `(None)` 时出现。
- 引号 CSV 内的真实换行、CRLF/CR 和字面 `\n` 都归一为 LF；Markdown 续行使用两个尾随空格和一个全角缩进。
- 空说话人明确显示为“旁白”。未知说话人保留原代号；`--validate` 同时计数。
- `_known` 是 `story_character` 中的独立权威别名，不会折叠回本体。例如 `white_tiger_known` 显示“兽人”。
- Markdown 展开对白、BGM、movie section、角色入退场、表情与静态背景。其余已知指令仍完整存在 JSONL 中。
- 未知 opcode 在 Markdown 中保留为 `<!-- kind=N cols={...} -->`，JSONL 同时保留全部 raw 列。

JSONL 每个物理行都是一个完整 JSON 对象：

```json
{"line": 5, "kind": 0, "op": "Text", "args": {"text_character_id": "alk", "text_body": "这里就是外面的世界？", "text_voice_path": "character/alk/voice/words/uwaa_1", "text_voice_immediately": false, "text_balloon_position": 3}, "raw": ["0"], "speaker_code": "alk", "speaker_name": "阿尔克", "text": "这里就是外面的世界？", "voice": "character/alk/voice/words/uwaa_1"}
```

实际 `raw` 始终是完整 43 列；少于或多于 43 列会作为损坏行拒绝，上例为排版简写。`(None)` 在 typed `args`/`voice` 中为 JSON `null`，在 `raw` 中仍是原始字符串。

- `pinball/common/data/story/ScenarioCommandKind.as`：0..24 枚举。
- `pinball/master/generated/ScenarioCommandValues.as`：字段名、列号、类型及 `(None)` 解析。
- `pinball/scene/storyQuest/scenario/ScenarioLayer.as`：运行时分派。

### 与任务书经验表的修正

| kind | 经验判断 | 反编译结论 |
|---:|---|---|
| 4 | 等待 | `BgmFadeOut`；协议没有独立 Wait opcode |
| 5 | 场景切换 | `MovieSequence`，控制当前背景 movie 的 section；静态背景是 kind 21 |
| 7 | 聚焦？ | `CharacterOut` |
| 8 | 全场操作？ | `CharacterOutAll` |
| 9 | 未知 | `CharacterActive` |
| 10 | 说话高亮/聚光 | `CharacterActiveOnly`，会暗化其他角色 |
| 11 | 角色退场 | `CharacterInactive`，只暗化；真正退场是 kind 7 |
| 20 | 未知 | `ScreenColorEffectDisable` |
| 22 | 文件头/初始化 | `MessageWindowShow`；因为常在开头出现而容易误判 |

任务书未观察到但客户端定义的 kind 为 2、14、15、16、17、19、21、23、24。
