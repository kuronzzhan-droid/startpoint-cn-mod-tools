## 二、⚠ 未解决 / 我搞错过的

### 1. 队伍卡片「脸太小、感觉好远」——**无解，别再用 faceY 折腾**

**我在这上面翻过车，回滚了（1.4.321 → 1.4.322 撤回）。**

公式（`FullShotImageAttributeTools.as:getOffsetToCenterizeFace`，已确证）：

```
offset = scale × (pivotY − faceY)
```

**方向是：faceY 调小 → offset 变大 → 立绘往下推。** 我一开始反过来理解了，把杰拉德 551→250，结果角色详情页的立绘下移 301px（作者截图实锤）。已全部还原并发布 1.4.322，与改动前语义逐键一致。

**真正根因**：官方美术是**大头身**，我们的 AI 立绘是**七八头身**。同样锚在胸口，我们的头就是小。faceY 只能改「露出哪一段身体」，改不了「头有多大」。而且**一个值两个界面共用**（队伍卡片 + 角色详情页），诉求矛盾。

要解决只能**重裁 `full_shot` 本身**做成更近的构图——改动面大且会改变角色详情页观感，**建议单开一轮做，别顺手动**。

## 四、踩过的坑（省时间用）

### 1. `wf_publish` 会跳过本地链尾，造成死路

`current_max_version()` **故意把 asset-patch 的版本纳入 max**。我发了公开链 1.4.318 之后，本地链尾其实是 1.4.317，于是重摇发出来的边是 `1.4.318→1.4.319`，**整条 1.4.313~1.4.317 被孤立**——包括作者自己那台（当时在 1.4.317）。已补桥 `1.4.317→1.4.318`。

**铁律：每次发布后跑一次全版本可达性检查**：

```bash
node -e "const g=require('./out/lib/cn-asset-graph.js');const s=g.getCnReleaseGraphSnapshot();
for(const v of ['1.4.0','1.4.312','1.4.319','1.4.322']){const r=g.findReleasePath(s,v);
console.log(v+' -> '+r.targetVersion+' ('+r.edges.length+'边)');}"
```

### 2. 发出去的服务端资产 ≠ 作者本机配置

`assets/rogue_event.json` 是**跟着仓库发给别人的**。`reset_rerolls_tower` 一旦非空，别人自建的服上有人按「战斗记录&重置」，就会在**他们的机器**上 spawn `wf_rogue_reroll.py --apply`：重建塔、写他们的 `.cdn` 推版本号、清那台服所有存档的进度。已改成环境变量开关。
**判据：凡是会在服务端机器上产生副作用的开关，默认值必须对陌生部署安全。**

### 3. 服务端 json 的 CRLF 会让发布回执静默变红

`npm run verify:local-release` 报 `server terminal evidence mismatch` 而 `git diff` 一行差异都没有 —— Windows 上 Python 文本模式默认写 CRLF，git 的 `text=auto` 把差异归一化掉（status 干净），但回执 `_server_evidence` 哈希的是**原始字节**。实测 7 个服务端 json 全中招。已给三个写入点补 `newline="\n"`（`wf_rogue_build.py` 两处 + `wf_gui.py` 一处）。**新增写服务端 json 的代码务必带上。**

### 4. 排查工具的三个陷阱

- **`git status` 会因 stat 缓存虚报改动**，`git diff --stat` 才是准的；真要定死就 `git show HEAD:<path>` 取 blob 和磁盘比字节。
- **本 CDN 的 PNG 魔数是小写 `\x89png`**，PIL 认不出，读前要补成大写、写回要还原成小写。
- **medium/android 根的资源 `--tables` 发不了**（它只按 common 解析）。要走 `sync_pending.json` 写 `medium:<2位>/<38位>` 前缀，然后 `wf_publish` 不带 `--tables`。发完 pending 会被自动清空。

### 5. 本仓的序列化器复现不出原始压缩流

改 `full_shot_image_attribute` 时，**语义只变 3 个键、字节却变了 505 个**（41405→43692 B）。试遍 zlib 全部 10 个级别都还原不了原字节。这与当初回执校验器从「重新 deflate 比字节」改成结构性检查是同一个根因。**改嵌套表前先跑 `q.build_node(tree)==原字节`，False 就要预期到内容告警会响。**

### 6. 其它

- `wf_quest_lib.save_table` 自带 build→parse 自校验 + 自动备份，改表优先用它。嵌套表内层值是 **str 不是 bytes**。
- 导出仓同步走**三分法**，`diff` 必带 `--strip-trailing-cr`，**同步前必先 fetch**（本轮本地克隆又落后 4 提交）。
- Bash 工具 cwd 在调用间保留，一律用绝对路径。
