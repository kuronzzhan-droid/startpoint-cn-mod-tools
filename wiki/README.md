# 官方与 MOD 角色 Wiki

独立、只读、可离线使用的角色资料站。前端无依赖，生成数据和媒体不进版本控制。

公网入口：[星见图鉴](https://wf-mod-wiki.pages.dev/)。源码分为本目录的静态界面、
[`../wiki-community/`](../wiki-community/README.md) 的 Pages Functions/D1 社区服务、
`../wf_wiki*.py` 的只读导出工具，以及 `../tests/test_wiki*` 与社区目录中的测试。
二维码、站点 Logo 和分享海报随前端源码保存；游戏媒体与数据包需使用获授权的本地资料导出。

## 当前在线功能

- 角色、编队、配队参考、武器、副本、排行六个入口；支持手机布局、主题切换与页底居中回到顶部。
- 图鉴默认按评分倒序，沿用票数修正；排序条件与正反方向分开，支持查看次数排序。
  卡片展示真实均分和累计查看次数，查看次数在右下与标签对齐；角色详情底部可查关联配队。
- 编队支持角色、武器/魂珠选择、清空、撤销、本机保存与删除，以及 Wiki 队伍码预览。
  管理员通过可视槽位编辑已保存队伍；公开配队支持关键词/代码搜索、模式筛选和点赞排序。
- 评分与手动排行独立计票、每日北京时间换日汇总；满三票按真实均分分档，少于三票暂定，档内按票数修正。
- 浏览量批量汇总缓存三十分钟；同访客同角色三十分钟内重复访问只计一次。
  活跃访客心跳三十分钟，页面切后台暂停。界面切换不主动轮询，限流仍逐请求检查。
- 管理员可维护配队公告、逐层副本推荐和赞助位；赞助位默认关闭，游客投稿未开放。
- Reborn 加群二维码、站点地址复制和三角色二维码宣传图；管理员入口收起在 Logo 右侧，登录身份可查看邮箱。

正式部署须使用经过核验的静态包与生产 Worker；D1 仅按当前结构增量迁移。
数据库、密钥、账户备份和本机审计记录放在站点目录与 Git 仓库之外，不能上传为静态资源。

## 导出与打开

公开源码不包含游戏资源、生产数据库、账号或本机配置。干净克隆可运行下文的测试夹具，
但不能直接重新生成完整站点媒体。完整导出需将 Wiki 工具用于匹配版本的完整游戏工作区，
其中包括有效的本地 profile/store、官方比较归档、装备登记与客户端规则，以及五重决战源码和配置。
`wf_wiki.py` 从工具目录的上一级读取游戏工作区，目前没有 `--repo` 参数。
仅部署网页与社区服务时，可使用已获授权并核验过的导出包，无需复制游戏服务端实现到静态站点。

在完整游戏工作区的仓库根目录执行（Python 环境需有 Pillow，复用现有 MOD 工具依赖）：

```powershell
python -X utf8 mod-tools/wf_wiki.py --output ${WF_ROOT}/out/MOD角色Wiki/site
```

可选 `--legacy-data <localApi.json>` 读取作者提供的旧 Wiki 别名与有标记的历史参考；
`--external-character <独立角色包/package>` 只读取单角色包，醒目标记本机快照未含，不安装或发布该包。

双击输出目录的 `index.html` 或 `打开角色Wiki.bat`。复制或压缩整个输出目录后仍可离线浏览。
更改游戏数据后再次执行导出命令，再刷新页面。不要只复制 HTML；图片、语音、数据和脚本必须一起保留。

可选本机 HTTP 预览（只绑定本机，不改游戏服务端）：

```powershell
python -m http.server 8877 --bind 127.0.0.1 --directory ${WF_ROOT}/out/MOD角色Wiki/site
```

然后打开 `http://127.0.0.1:8877/`。这是本地预览，不会获得互联网访问地址。

## 资料口径

- 收录当前 profile 的所有可玩官方角色与 MOD，以 CN 官方最终归档 1.4.54 比较同一角色的修改；不把剧情和助战占位记录当作可玩角色。
- 分为毛茸异世界、原创与变体、Boss角色、小动物、原版角色改动、官方原版六栏；支持全部/六种属性与角色星级筛选，默认评分倒序，可切换属性内评分、图鉴顺序等排序。毛茸异世界收录赛瑞斯、杰拉德、基诺维、凯尔；赛瑞斯另标“早期方案，后续将重做”。小动物沿用项目十五角色名单，Boss按可玩化来源登记。
- 按作者要求，Wiki 固定排除海豹球 `129990`、金丝雀二号 `119998`、雨果 `119999`；在角色和媒体导出之前按精确 ID 过滤，统计只计可见角色，其他变体保留。隐藏清单也在 `wf_wiki_categories.py`，不修改游戏数据。
- 页面显示导出版本与时间，属于静态快照。存在 pending 或导出时来源发生变化会拒绝完成，避免混入在途版本。
- 技能的 1/2 表层级表示普通/进化，不是技能等级；技能能量显示满级值，保留初级值。
- 能力优先显示自定义面板说明，补充分项效果；技能列出单次命中倍率、状态百分比、持续秒数、成长公式与条件分支。不能将条目数当作命中数或直接相加为总伤害。
- 公开数据不包含内部角色代码、原始表行或技能程序，网址使用独立图鉴编号。哈希媒体清单仅用于本地审计，不应上传到公开目录。
- 立绘解码后缩放为 WebP 保留透明度；语音只解码当前存储资源，不生成新音频。相同内容去重保存。
- 中文字幕优先取当前游戏台词表，标记为游戏内字幕；台词稿需与当前音频哈希匹配才引用。原版音频仅有 ID3 标签差异时可核对完整音频帧哈希。未找到可靠原文/翻译时明确标注，不能按槽名硬套旧稿。
- 官方角色只收录主页、战斗、加入觉醒与登录语音，排除全部剧情语音；新增 MOD 保留已找到的完整语音。
- 角色图鉴与编成角色候选共用可折叠查找组件，图鉴查找默认收起，搜索、属性、星级、战斗类型与收录来源组合筛选；查找区只在对应角色列表显示。角色列表提供立绘／标准／致密切换；致密只显示头像与身份角标。排列、明亮／黑夜主题、目录展开状态在当前浏览器记忆。
- 头像使用属性色边框，稀有度通过描边、角饰区分，星级继续显示在姓名旁。明确的旧 Wiki 国服限定记录显示“限定”，新增 MOD 与改版官方分别显示“MOD”“MOD改”；节庆主题不用于推断限定，限定标记不代表 MOD 服当前卡池。
- 立绘使用纯色背景，点击可在弹窗中缩放、拖动查看，关闭后回到原位置。详情展示已确认关联的游戏铭牌与获得条件，未收录时明确说明；不根据名称猜配铭牌。
- 能力效果按条显示原生主位、合击、自身属性与属性共鸣图标；限制只从对应条目的结构化条件提取。自身属性限制不等于六人属性共鸣，无法明确拆分的复合条件保留完整文案。
- 武器图鉴按系列分组，分类标题可展开或收起并保留筛选前状态，提供全部展开／全部收起；深渊与诅咒优先展示，支持星级筛选与只看可强化武器；所有可强化条目均可切换强化前与最高强化后的名称、图标、数值和效果，魂珠与强化材料单列。悖论另外提供原始／Lv120终式／Lv200三档，分别显示实际阶段的追加能力、面板与原生图标，200级使用专用蓝金底图。五重决战介绍按当前敌方数据、路线和机制逐项核对。
- 幻想、女帝、普莉莉艾、机兵、领主掉落与兑换、临境域、深层域、装备扭蛋、主线、活动等武器依据已核对来源分别归类；两条破星剑归悖论，但不继承 PARADOX 专属的编成衰减规则。无法确认来源的武器留在其他。
- 配队为三个主位、三个合击位、三件武器与三颗魂珠，支持拖拽和点击操作、撤销、清空、本机保存与删除，以及 Wiki 队伍码预览。保存只在当前浏览器；不模拟实际战斗。特殊装备规则按本方已占主位的槽位计件，不计其他玩家。
- 界面与编成交互参考作者提供的《弹射世界中文 WIKI》离线版 v3.0.0；感谢 memimu 与「弹射世界wiki重生群」（QQ群 610753092）的资料收集。原生图标与面板从当前游戏资源提取，编队保留游戏面板与队长标记，卡组采用作者指定的紧凑双排：主位与装备在上，魂珠与合击在下。制作与维护署名 PARADOX，页脚保留上游与本项目仓库链接。旧稿与当前快照明确区分。

## 副本与模式资料

顶部「副本与模式」合并活动、领主战、降临讨伐、深渊／幻想等模式。五重决战保留波次、Boss 机制和旧 `#five-boss` 链接。
目录按需加载 `dungeons-data.js`，横幅为去重 WebP；展开预览时才创建预览图片。只浏览角色页不会加载副本资料。

普通 Wiki 导出默认读取本地当前资料。明确刷新灰服资料时单独运行：

```powershell
python -X utf8 mod-tools/wf_wiki_dungeons.py --site ${WF_ROOT}/out/MOD角色Wiki/site --gray-url https://game-server.example/patch/cn/dummy/download/production/upload --gray-snapshot ${WF_ROOT}/out/Wiki副本模式/灰服快照 --community-catalog mod-tools/wiki-community/dungeon-catalog.mjs
```

仅读取正常公开资源，不绕过客户端准入验证。灰服未提供的文件可用本地快照补齐；每条入口记录来源状态，
`dungeons-manifest.json` 保存详细审计信息，不能作为公开静态文件上传。目录收录不代表活动当前开放。
导出参数及来源细节以 `wf_wiki_dungeons.py --help` 为准；`--community-catalog` 显式同步服务端可信副本 ID。

攻略与推荐盘通过独立 Wiki 社区 API 保存。管理员可编辑攻略、关联公开队伍、上传图片；移除推荐只取消关联。
图片上传先压缩、保存攻略后公开；未使用图片可由上传者或站长／副站长删除。游客只读，静态离线版保留资料目录，
在线攻略不可用时明确提示。生产数据库迁移和接口见 [Wiki 社区后台](../wiki-community/README.md)。

## 维护模块

`wf_wiki.py` 负责导出入口；`wf_wiki_catalog*` 负责角色资料；`wf_wiki_voice*` 负责语音字幕；
`wf_wiki_media.py` 负责媒体解码；本目录保存前端源码。此工具不修改 store、pending、角色候选或旧后台，不发布游戏数据。

聚焦检查：

```powershell
python -X utf8 -m unittest discover -s mod-tools/tests -p 'test_wiki*.py' -v
node --test mod-tools/tests/test_wiki_team.cjs
node --test mod-tools/wiki-community/tests/*.test.mjs
```

完整前端聚焦测试：PowerShell 可使用 `node --test (Get-ChildItem mod-tools/tests/test_wiki_*.cjs).FullName`。
社区本地测试需要 Node.js 24 的 `node:sqlite`；依赖 workerd 的检查需显式指定已安装的 Miniflare 路径。
装备规则和五重奖励的解析测试使用 `../tests/fixtures/wiki/` 中的最小资料，不执行客户端补丁或服务端代码。
若工作区带有对应游戏源码，还会校验当前规则与说明一致；缺少时只跳过这两项集成校验，解析测试仍会执行。
这些检查不读取或修改正式数据库，也不替代真实手机和正式部署后的验收。
