# 任务：按规范重写 MOD 角色面板文案与技能描述（只产出提案文件）

输入同 TASK.md（chars/、dsl/、zones.json），另加：
- `STYLE.md`：写法规范，必须遵守。
- `findings_reviewed.json`：上一轮核对出的问题（带 `skip` 的不要改，只在 notes 里提一句）。其余的修正要并进重写结果。
- `official_templates.tsv`：客户端官方文案模板，术语和句式以它为准。

## 要做什么
对本 shard 每个角色：
1. **面板覆盖文案**（chars 里标了「面板覆盖文案 desc_override_xxx」的槽位）：按 STYLE.md 重写整段。每行一条，行间用换行；「整键仅主位(c1=false)」的槽位每行开头必须是 ` <icon id='main'>  `（前1空格、后2空格）。
2. **技能描述**（action_skill 两档 c1）：按 STYLE.md §9 重写。**本轮先保留现有的伤害倍率数字**（作者还没决定删不删），倍率写错的按 DSL 改对；两档描述各写各的满级数据。
3. **没有覆盖文案的槽位**：默认不动（客户端自动生成）。只有当自动生成的效果会被拆成很多行难以阅读时（例如六属性能力伤害 6 行），才新建覆盖文案，键名 `desc_override_<该槽 string_id>`，而且必须把该槽**所有行**都写进去（包括独立伤害乘区标签）。新建前先确认该 string_id 没有被别的槽共用（chars 里同 string_id 出现在两个槽就不要建）。

## 硬约束
- 数值、条件、对象、上限、CT、持续时间一律以数据为准（满级列），不能编；拿不准就保持原句并在 notes 里说明。
- 不新增数据里没有的效果，也不删掉数据里有的效果。
- 技能名、状态名、角色名照抄现有译名（『』括技能名，「」括状态名）。
- 不改数据，只出文案。

## 输出
写到 `rewrites/<shard>.json`（shard 名见启动参数），格式：
```
{
 "cas": {"desc_override_xxx": "新全文（行间用\n）", ...},
 "skill": {"<action_skill 键>": {"1": "档1新描述", "2": "档2新描述"}, ...},
 "notes": [{"id":"角色ID","key":"键","note":"拿不准/没改/需要作者决定的事"}]
}
```
- 只放**有变化**的键；和原文一字不差的不要放。
- 每个角色都看完。最后核对：每个新文本里的每个数字都能在数据或 DSL 里找到出处。
