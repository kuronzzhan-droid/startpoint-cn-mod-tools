# 任务：核对 MOD 角色面板文案与数据（只读审查）

你是审查员。目录里是世界弹射物语私服 108 个 MOD 角色（自制角色 + 改过的官方角色）的导出，视图版本 1.4.226。
找出**玩家看到的文字和实际数据不一致**的地方。不要改任何文件，只写结果文件。

## 输入
- `chars/<角色ID>.md`：每个角色一份。含技能名/技能描述（action_skill，两档）、队长技与能力1-6。
  每个槽位给出：
  - 「面板覆盖文案」：玩家在角色详情页看到的就是这段，每 `│` 一行一条。没有覆盖时客户端按数据自动生成（自动生成的不用查）。
  - 「行N」：数据行的机器翻译（describe 工具），「原始」是该行非空列 `c列号=值`。
  - 官方角色另附「官方原版」行，便于看出我们改了什么。
- `dsl/<角色ID>.txt`：该角色技能和「发动技能动作」(kind 629) 引用的 DSL 树（JSON）。用来核对技能描述和 629 类效果的说明。
- `zones.json`：内容种类 → 独立伤害乘区编号（instant = 瞬发块内容 kind，during = 持续块内容 kind；"6d" 表示仅当伤害值≠0 时属于乘区6）。

## 读数规则
- 强度/百分比列：值 ÷ 1000 = %（100000 = 100%）。连击类内容（如 226 加连击）单位 ×100000（+9 连击 = 900000）。
- 每行两列数值（低级/满级），面板只写一个值，以**满级列**为准。
- 前置条件 `编成≥6`、阈值 600000 + 元素 = 「X属性共鸣时」。
- describe 已知误报（以此为准）：kind 70 渲染「冻结无效」实为「免疫疲惫」；kind 245「2号位技能槽」实为「技能槽最大值」；during_trigger 1 阈值 100000 渲染「HP≤1」实为永真（常驻）。
- 一个槽位可有多行；同一效果分属攻击力/技能伤害等多行时，面板合成一句是正常的。

## 要找的问题
1. **漏写**：数据里有实际效果，面板一句没提（例：某能力有直击3次+伤害25%的行，面板只写了贯通延长）。
2. **写错/对不上**：数值、条件（共鸣/Fever/队长/主位/层数上限/CT/持续秒数/次数上限）、对象（自身/全队/某属性/协力球）、效果种类和数据不符；面板写了数据里没有的效果。
3. **独立伤害乘区标签**：属于 zones.json 里乘区的效果，面板必须带「（独立伤害乘区N）」且 N 正确；不属于的不能带。乘区9 的写法是全角「（独立伤害乘区９）」。
4. **技能描述**：action_skill 描述与 DSL 明显不符（倍率、属性、持续时间、召唤数量等）。只报你在 DSL 里能指出证据的。
5. **文案规范**（作者定的）：
   - 面板覆盖文案不写「自身为队长时」；队长槽本身就是这个意思。
   - 不写两档数字（如「X%（觉醒后Y%）」）。
   - 「整键仅主位(c1=false)」的能力，覆盖文案每一行都要以 ` <icon id='main'>  ` 开头。
   - 技能强化（队长/能力里的「强化『技能名』…」）只写在队长/能力条目，技能描述里不重复写强化后的效果。
   - 不写「生命值100%以下」这类恒真条件文字。

## 不要报
- 纯措辞偏好、标点全半角混用（除乘区9 的「９」）、无覆盖的自动生成槽位。
- 你无法从给定数据确认的猜测；拿不准就 confidence 写 low 并说明。

## 输出
写到 `findings/<shard>.jsonl`（shard 名见启动参数），每行一个 JSON：
```
{"id":"169985","name":"莫弥亚","slot":"能力4","type":"漏写|写错|对不上|乘区标签|技能描述|规范","current":"面板现在的原句（没有就写空串）","evidence":"数据证据：行号+关键列+换算后的值","suggest":"建议改成的完整句子（只改文字能修好时）","number_change":false,"confidence":"high|medium|low"}
```
- `number_change`：如果要修好必须改数据数值（而不是改文字），写 true，并在 evidence 里说清哪一边更像设计意图。
- 每个角色都看完；没问题的角色不用写行。最后在 jsonl 末尾追加一行 `{"done":true,"chars_checked":N}`。
